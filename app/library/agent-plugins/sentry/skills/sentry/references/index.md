# sentry operations

Choose the operation below, then read only its linked contract.

- [access_project_information](access_project_information.json): Retrieves detailed information for a Sentry project, given its existing organization and project ID or slug.
- [add_organization_member_via_email](add_organization_member_via_email.json): Invites a new member (or re-invites an existing non-accepted member) to a Sentry organization via email, allowing specification of organization and team roles.
- [add_team_member_in_organization](add_team_member_in_organization.json): Adds an existing organization member to one of its teams, or may generate an access request when permission to join is needed. An already-existing membership is reported as an error.
- [add_team_to_project](add_team_to_project.json): Grants a Sentry team access to a Sentry project within the specified Sentry organization.
- [bulk_mutate_an_organizations_issues](bulk_mutate_an_organizations_issues.json): Bulk mutate various attributes on issues within an organization. Use when you need to update status, priority, assignment, or other attributes for multiple issues at once. Maximum of 1000 issues can be mutated, with a 100 issue limit per request.
- [bulk_remove_an_organizations_issues](bulk_remove_an_organizations_issues.json): Permanently removes issues from an organization. If IDs are provided, queries and filtering are ignored. Maximum of 1000 issues can be removed at once.
- [create_an_alert_for_an_organization](create_an_alert_for_an_organization.json): Creates a workflow alert for a Sentry organization using the New Monitors and Alerts system. Use when you need to set up automated alerting for issues based on trigger conditions and filters. Note: This endpoint is currently in beta and may change.
- [create_external_user_for_organization](create_external_user_for_organization.json): Links a Sentry user to an external identity provider's user within a Sentry organization; the Sentry user must be an organization member, an active integration for the provider must be configured, and `external_id` is typically required for the external user.
- [create_organization_alert_rule](create_organization_alert_rule.json): Creates a Sentry metric alert rule for an organization, mandating a 'critical' trigger, typically for a single project, where actions may require Sentry integrations.
- [create_organization_monitor](create_organization_monitor.json): Creates a new monitor (type 'cron_job') within a Sentry organization to track scheduled tasks, allowing configuration of its name, slug (which must be unique if provided), status, owner, and muting preferences for incidents.
- [create_organization_team](create_organization_team.json): Creates a new team in a Sentry organization, requiring either a 'slug' or 'name' to define the team.
- [create_release_deploy_for_org](create_release_deploy_for_org.json): Creates a new deploy record in Sentry to track the introduction of a release version into a specific environment.
- [create_release_for_organization](create_release_for_organization.json): Creates a new Sentry release for an existing organization, associating it with specified projects that must belong to that organization.
- [create_sentry_external_issue_link](create_sentry_external_issue_link.json): Links an existing Sentry issue to an issue in an external service, or updates an existing link, requiring a configured Sentry App installation `uuid`.
- [create_team_project_for_organization](create_team_project_for_organization.json): Creates a new Sentry project for an existing organization and team, allowing configuration of its name, slug, platform, and default alert rules.
- [delete_an_alert](delete_an_alert.json): ⚠️ This endpoint is currently in beta and may be subject to change. Deletes an alert. Use when you need to permanently remove an alert from an organization.
- [delete_bulk_alerts](delete_bulk_alerts.json): Bulk delete alerts for a given organization. Use when you need to delete multiple alerts at once. ⚠️ This endpoint is currently in beta and may be subject to change.
- [delete_external_issue_by_uuid](delete_external_issue_by_uuid.json): Unlinks an external issue (e.g., from Jira/GitHub), identified by `external_issue_id`, from the Sentry app installation specified by `uuid`.
- [delete_external_team_by_id](delete_external_team_by_id.json): Unlinks a previously established external team from a Sentry team; this action does not delete either the Sentry team or the external team.
- [delete_external_user_from_organization](delete_external_user_from_organization.json): Deletes the link between an external user (from an integration provider like GitHub, Slack, GitLab, or MS Teams) and a Sentry user within the specified organization. This removes the association but does not delete the Sentry user itself. Requires org:admin or org:write permissions.
- [delete_member_from_team](delete_member_from_team.json): Removes an organization member from a Sentry team, revoking their team-specific permissions, provided the member is currently part of that team.
- [delete_organization_alert_rule](delete_organization_alert_rule.json): Deletes a specified Sentry organization metric alert rule. An HTTP 202 response yields an empty result, indicating that the deletion request was accepted for processing.
- [delete_organization_dashboard](delete_organization_dashboard.json): Deletes a custom dashboard or tombstones (marks as deleted) a pre-built dashboard within a Sentry organization.
- [delete_organization_discover_query](delete_organization_discover_query.json): Permanently removes a specific saved Discover query (a configuration for exploring event data) from a Sentry organization. This action requires one of the following scopes: org:admin, org:read, or org:write. The Discover saved queries feature is only available on Business and Enterprise plans.
- [delete_organization_issue](delete_organization_issue.json): Permanently deletes a specific Sentry issue, identified by its ID, from an organization; this operation is irreversible and idempotent.
- [delete_organization_member](delete_organization_member.json): Permanently removes a member from a Sentry organization, revoking their access to that organization and all its associated projects.
- [delete_organization_monitor](delete_organization_monitor.json): Deletes a Sentry cron monitor or, if `environment` is specified, only specific environments within that monitor.
- [delete_organization_release](delete_organization_release.json): Permanently and irreversibly removes a Sentry release, including all its associated files, identified by its version from the specified organization.
- [delete_project_by_id](delete_project_by_id.json): Schedules a Sentry project for asynchronous deletion within a specified organization, hiding it from most public views once the process begins.
- [delete_project_hook](delete_project_hook.json): Deletes a specific service hook from a Sentry project using its organization, project, and hook identifiers.
- [delete_project_issues](delete_project_issues.json): Permanently removes specified issues from a Sentry project; if no issue IDs are provided, it removes the oldest 1000 issues.
- [delete_project_monitor](delete_project_monitor.json): Deletes a Sentry monitor, or optionally only its specified environments, for a given project.
- [delete_project_team_association](delete_project_team_association.json): Revokes a team's access to a Sentry project; this operation is idempotent.
- [delete_team_by_organization_or_team_slug](delete_team_by_organization_or_team_slug.json): Schedules a Sentry team for asynchronous deletion, which releases the team's slug for reuse upon successful scheduling.
- [fetch_alerts](fetch_alerts.json): Retrieves a list of alerts (workflows) for a Sentry organization. Use to get alert configurations, statuses, and trigger details. ⚠️ Note: This endpoint is currently in beta and may be subject to change. It is supported by New Monitors and Alerts and may not be viewable in the UI today.
- [fetch_an_alert](fetch_an_alert.json): Retrieves detailed information for a specific alert workflow. Use when you need to get alert configuration, triggers, action filters, or monitoring status. This endpoint is currently in beta and supported by New Monitors and Alerts.
- [fetch_an_organizations_monitors](fetch_an_organizations_monitors.json): Retrieves monitors (detectors) for a Sentry organization. This endpoint is currently in beta and may be subject to change. Use when you need to list or query monitors for an organization.
- [fetch_issue_event_by_id](fetch_issue_event_by_id.json): Retrieves the 'latest', 'oldest', or 'recommended' event for a Sentry issue within an organization, optionally filtered by environment(s).
- [fetch_organization_alert_rules](fetch_organization_alert_rules.json): Retrieves metric alert rules for a Sentry organization by ID or slug. A 404 with the detail “The requested resource does not exist” is returned as an empty list, which does not by itself establish that the organization has no rules.
- [fetch_organization_release_threshold_statuses](fetch_organization_release_threshold_statuses.json): Retrieves derived health statuses for release thresholds in a Sentry organization for a given time range, optionally filtered by environment, project, or release; `start` and `end` times must be provided together. **`[WARNING]`**: This API is experimental (Alpha) and subject to change!
- [fetch_project_environment_details](fetch_project_environment_details.json): Retrieves detailed information for a specific environment within a Sentry project.
- [fetch_tag_values_for_issue](fetch_tag_values_for_issue.json): Retrieves a list of distinct values for a specified tag key associated with an existing Sentry issue, useful for understanding tag manifestations like browser versions or affected users.
- [get_alerts](get_alerts.json): Tool to retrieve all combined alert rules and monitors for a Sentry organization. Use when you need to get a unified view of both alert rules and cron monitors. This endpoint combines results from multiple sources into a single response.
- [get_oldest_event](get_oldest_event.json): Retrieves the oldest (first) event associated with a Sentry issue within an organization. Use this action when you need to investigate the original occurrence of an issue to understand its root cause or initial context. This is particularly useful for debugging issues from their first appearance, analyzing initial error conditions, or determining when a problem first started occurring.
- [get_organization_by_id_or_slug](get_organization_by_id_or_slug.json): Retrieves a Sentry organization by its ID or slug; use the `detailed` parameter to optionally exclude project and team details for a more concise response.
- [get_organization_details](get_organization_details.json): Retrieves Sentry organizations accessible via the current authentication, with scope varying between user (all in region) and API key (linked org only) credentials.
- [get_organization_environments](get_organization_environments.json): Lists deployment environments for a Sentry organization, optionally filtered by visibility status. Environments represent deployment contexts like 'production', 'staging', or 'development' where events are tracked. By default, only visible environments are returned. Use the visibility parameter to include hidden environments or view only hidden ones.
- [get_organization_issue_details](get_organization_issue_details.json): Retrieves detailed information for a specific issue within a Sentry organization. Accepts both numeric issue IDs (e.g., '7159174717') and short IDs displayed in the Sentry UI (e.g., 'PROJECT-123', 'SENTRY-4V'). Short IDs are automatically resolved to numeric IDs before fetching issue details.
- [get_organization_release_version](get_organization_release_version.json): Retrieves detailed information, including optional health data and statistics, for a specific release version within a Sentry organization.
- [get_organization_sessions](get_organization_sessions.json): Retrieves time series data for an organization's Sentry project release health sessions; note session duration data (e.g., using `avg(session.duration)`) may be incomplete after Jan 12, 2023, results are capped at 10,000 data points, `statsPeriod` overrides `start`/`end` timestamps, and the `interval` parameter (default/min '1h', max '1d', format like `statsPeriod`) dictates time series resolution and must cleanly divide one day.
- [get_organization_stats_summary](get_organization_stats_summary.json): Retrieves summarized event statistics for a Sentry organization, aggregated by project, allowing queries for event counts or unique occurrences over a specified time period and resolution, with filtering by project, category, and outcome.
- [get_project_event_stats](get_project_event_stats.json): Retrieves time-series event statistics for a Sentry project. Returns an array of [timestamp, count] data points showing event volumes over time. Use this to analyze event trends, monitor error rates, or generate custom dashboards. The endpoint supports different event types (received, rejected, blacklisted, generated) and time resolutions (10s, 1h, 1d). **Important**: This endpoint may change in the future without notice. Monitor Sentry's API changelog for updates. **Common use cases**: - Monitor error rates over time - Analyze event rejection patterns - Generate custom analytics dashboards - Track event volume trends
- [get_project_events](get_project_events.json): Retrieves a list of error events for a specified project within a Sentry organization, with options for pagination and detail level.
- [get_project_hook](get_project_hook.json): Retrieves detailed information for an existing service hook within a Sentry project. Service hooks (webhooks) are HTTP callbacks that notify external systems when specific events occur in Sentry, such as when alerts are triggered ('event.alert') or new events are processed ('event.created'). This action requires: - Authentication with 'project:read' scope - The hook_id (GUID) of an existing service hook, typically obtained from creating a hook or listing project hooks Common use cases: - Verifying hook configuration and status - Retrieving the webhook URL and secret for external system setup - Checking which events the hook is subscribed to - Auditing hook creation timestamps Note: The 'servicehooks' feature must be enabled on your Sentry plan to create or manage hooks, though reading existing hook details may be possible depending on your API permissions.
- [get_project_list](get_project_list.json): Lists all Sentry projects the authenticated token has membership access to across all organizations. IMPORTANT: This endpoint returns projects where the token's user is a member. An empty result does NOT mean no projects exist - it means the token lacks project membership. This commonly happens when: - The auth token has organization-level access but not explicit project membership - Projects exist in organizations you can access, but you're not a project member If you receive an empty list but know projects exist, use sentry.retrieve_organization_projects instead, which lists all projects within a specific organization (requires organization_id_or_slug parameter).
- [get_project_monitor_by_id](get_project_monitor_by_id.json): Retrieves detailed information for a specific Sentry cron monitor, provided the organization, project, and monitor exist.
- [get_sentry_app_installations_for_organization](get_sentry_app_installations_for_organization.json): Retrieves a list of Sentry App installations for a given organization, which must exist.
- [get_team_members_by_id_or_slug](get_team_members_by_id_or_slug.json): Retrieves a page of Sentry team members with user information, organization and team roles, authentication status, and membership flags. Supports pagination with a cursor.
- [ingest_event_via_dsn](ingest_event_via_dsn.json): Ingests a single custom event into a Sentry project using its DSN via the Envelope ingestion endpoint. This may create or update an issue group depending on Sentry's grouping algorithm. Note: Sentry does not provide a direct API to 'create an issue group'; issues are created from ingested events. This tool allows controlled generation of events for testing or workflows requiring synthetic events.
- [list_a_projects_user_feedback](list_a_projects_user_feedback.json): Retrieves a list of legacy user feedback items within a Sentry project. Use when you need to see user-reported feedback on errors. Note: This returns legacy User Reports, not submissions from the User Feedback Widget.
- [list_a_tags_values_for_an_issue](list_a_tags_values_for_an_issue.json): Retrieves values and statistics for a specified tag key on a Sentry issue, optionally filtered by environment. Use it to analyze tag value frequency and when values were seen.
- [list_an_organizations_issues](list_an_organizations_issues.json): Returns a list of issues (error groups) for an organization. Use when you need to retrieve and analyze error patterns, track unresolved issues, or monitor issue trends. Default query applies 'is:unresolved issue.priority:[high,medium]'.
- [list_organization_dashboards](list_organization_dashboards.json): Retrieves a list of custom dashboards for a Sentry organization, with pagination support.
- [list_organization_members](list_organization_members.json): Lists all members, including those with pending invitations, for a Sentry organization.
- [list_organization_releases](list_organization_releases.json): Retrieves a list of releases for an existing Sentry organization, optionally filtering by a query string that matches the start of the release version.
- [list_organization_repositories](list_organization_repositories.json): Retrieves a list of version control repositories for a specific Sentry organization, which must exist and is identified by its ID or slug.
- [list_organization_user_teams](list_organization_user_teams.json): Retrieves a list of all teams that the authenticated user has access to within the specified Sentry organization.
- [list_organizations](list_organizations.json): Retrieves a list of organizations available to the authenticated session. Use this action when you need to discover which organizations the user has access to before performing operations on a specific organization. This is essential for organization-bound operations that require an organization_id_or_slug parameter. Note that API key requests only return the associated organization.
- [list_project_tags](list_project_tags.json): Retrieves all tags that have been recorded for events within a Sentry project, along with statistical information for each tag. Use when you need to understand what tags are available in a project and their usage patterns. This provides an overview of tag distribution and helps identify commonly used tags for filtering and analysis.
- [list_project_users](list_project_users.json): Retrieves users who have interacted with or are recognized within a specific Sentry project, optionally filtered by a query.
- [list_teams_in_organization](list_teams_in_organization.json): Lists teams for an existing Sentry organization, optionally including project details and supporting pagination via a cursor.
- [modify_organization_settings](modify_organization_settings.json): Updates settings for a Sentry organization, such as name, slug, member roles, privacy, and integrations; if `avatarType` is 'upload', `avatar` (base64 image) is required.
- [mutate_an_organization_s_alerts](mutate_an_organization_s_alerts.json): Bulk enable or disable alerts for an organization. Use when you need to activate or deactivate multiple alerts at once. This endpoint is in beta and may change in the future.
- [mutate_an_organizations_monitors](mutate_an_organizations_monitors.json): Bulk enable or disable monitors for an organization. This endpoint is in beta and may change. Use when you need to enable or disable multiple monitors at once based on filters.
- [patch_user_active_status_in_organization](patch_user_active_status_in_organization.json): Deactivates and permanently deletes a Sentry organization member by using a SCIM PATCH operation to set their 'active' attribute to 'false'.
- [query_explore_events_in_timeseries_format](query_explore_events_in_timeseries_format.json): Retrieves explore data for an organization as a timeseries for a selected dataset and aggregate axis, optionally grouped by top events.
- [retrieve_alert_rule_details](retrieve_alert_rule_details.json): Retrieves detailed information for a specific metric alert rule within a Sentry organization. Note: This endpoint is specifically for metric alert rules (organization-level alerts based on metrics like error count, latency, failure rate, etc.). For issue alert rules (project-level alerts triggered by events), use the project rules endpoint instead. The API may return 404 if: - The alert rule ID does not exist - The organization does not have metric alerts enabled - The organization does not exist or you don't have access
- [retrieve_commits_for_organization_repo](retrieve_commits_for_organization_repo.json): Retrieves a list of commits for a given repository within a Sentry organization.
- [retrieve_custom_integ_issue_links_given_sentry_issue](retrieve_custom_integ_issue_links_given_sentry_issue.json): Retrieves all external issue links for a Sentry issue. Returns connections between the Sentry issue and external tracking systems (e.g., Jira, GitHub Issues, Linear, GitLab, Asana) created through custom integrations or Sentry Apps. Use this to see what external tickets or issues are linked to a Sentry error.
- [retrieve_event_id_for_organization](retrieve_event_id_for_organization.json): Resolves a Sentry event ID to its project and issue details within an accessible Sentry organization.
- [retrieve_issue_events_by_id](retrieve_issue_events_by_id.json): Retrieves events for a specified Sentry `issue_id`, which must be an existing issue.
- [retrieve_issue_hashes_for_organization](retrieve_issue_hashes_for_organization.json): Retrieves a list of grouping checksums (hashes) generated by Sentry for a specific issue within an organization, used for understanding event aggregation.
- [retrieve_issue_tag_details](retrieve_issue_tag_details.json): Retrieves detailed information (e.g., top values, counts) for a specific tag key on an existing Sentry issue; results are paginated (max 1000 values per page).
- [retrieve_organization_dashboard](retrieve_organization_dashboard.json): Fetches detailed information about a specific custom dashboard within a Sentry organization.
- [retrieve_organization_events](retrieve_organization_events.json): Retrieves Discover event data for a Sentry organization. When a nonempty field list and sort are supplied, the tool adds the sort field to the list if missing; equation fields cannot be used for sorting, and the field list has a 20-item limit.
- [retrieve_organization_member](retrieve_organization_member.json): Retrieves details for a Sentry organization member or pending invitee, including role, teams, and status, using their member ID and the organization's ID or slug.
- [retrieve_organization_monitors](retrieve_organization_monitors.json): Retrieves cron monitors for a Sentry organization, including details of nested monitor environments.
- [retrieve_organization_projects](retrieve_organization_projects.json): Retrieves a list of Sentry projects for a specified organization (which must be accessible), supporting pagination via cursor.
- [retrieve_organization_release_commits](retrieve_organization_release_commits.json): Retrieves a list of commits for a given release version in an existing Sentry organization, if the release exists.
- [retrieve_organization_stats_v2](retrieve_organization_stats_v2.json): Retrieves Sentry organization event statistics; specify time range with `statsPeriod` OR both `start`/`end`; note that grouping by `project` returns a sum not a time-series, and `interval` (if used) must be 1h-1d and cleanly divide 24 hours.
- [retrieve_project_environments](retrieve_project_environments.json): Retrieves a list of environments for an existing project within a Sentry organization.
- [retrieve_project_event_by_id](retrieve_project_event_by_id.json): Retrieves detailed information for a specific Sentry event using its ID, organization identifier, and project identifier.
- [retrieve_project_filter_data](retrieve_project_filter_data.json): Retrieves a Sentry project's current data filtering settings, used to ignore events from sources like localhost, web crawlers, or legacy browsers.
- [retrieve_project_hooks](retrieve_project_hooks.json): Return a list of service hooks (webhooks) bound to a Sentry project, used to send notifications to external services upon event occurrences.
- [retrieve_project_issues_list](retrieve_project_issues_list.json): Retrieves a list of issues for a Sentry project, defaulting to unresolved issues unless an empty `query` string is provided or specific `hashes` are used.
- [retrieve_project_members_list](retrieve_project_members_list.json): Retrieves active organization members belonging to any team assigned to the specified Sentry project.
- [retrieve_project_tag_values](retrieve_project_tag_values.json): Retrieves values for a specified tag key recorded in a Sentry project. An empty list can also result from a 404 response or a non-list response.
- [retrieve_project_teams](retrieve_project_teams.json): Retrieves a list of teams with explicit access to a specific project within a Sentry organization.
- [retrieve_release_commits](retrieve_release_commits.json): Retrieves a list of commits associated with a specific release version within a Sentry project.
- [retrieve_saved_discover_query_for_organization](retrieve_saved_discover_query_for_organization.json): Retrieves a specific saved Discover query (a predefined set of filters and conditions for exploring event data) for a Sentry organization.
- [retrieve_short_id_for_organization](retrieve_short_id_for_organization.json): Resolves a Sentry short ID (e.g., 'PROJECT-1A') to its complete issue details including organization slug, project slug, group ID, and full issue metadata. Use this to look up issue information when you have a short ID reference.
- [retrieve_team_info_via_organization_id_or_slug](retrieve_team_info_via_organization_id_or_slug.json): Retrieves detailed information for an existing Sentry team within its organization, optionally expanding related data (e.g., projects) or collapsing sections (e.g., organization details).
- [retrieve_team_projects](retrieve_team_projects.json): Retrieves a list of Sentry projects for a specific team within an organization, supporting pagination via a cursor.
- [save_organization_discover_query](save_organization_discover_query.json): Saves a new Discover query with a unique name for a Sentry organization, allowing reuse of search criteria for analyzing event data (errors, transactions) across specified projects and environments.
- [switch_team_role_for_member](switch_team_role_for_member.json): Changes a member's role within a Sentry team, ensuring the member is already part of the team and that any organization-level role restrictions are respected.
- [toggle_project_filter_status](toggle_project_filter_status.json): Updates the status or configuration of a specific inbound data filter for a Sentry project; use `active` for most filters, or `subfilters` if `filter_id` is `legacy-browsers`.
- [update_an_alert_by_id](update_an_alert_by_id.json): Updates a Sentry alert workflow by ID, including its name, filters, triggers, or configuration; the enabled setting defaults to true unless set otherwise or explicitly set to null. This endpoint is in beta and supported by New Monitors and Alerts.
- [update_external_user_for_organization](update_external_user_for_organization.json): Updates attributes of an existing external user linkage (identified by `external_user_id`) within a Sentry organization (specified by `organization_id_or_slug`).
- [update_issue_attributes_in_organization](update_issue_attributes_in_organization.json): Updates specified attributes of an existing Sentry issue within a Sentry organization, leaving other attributes unchanged.
- [update_monitor_for_project](update_monitor_for_project.json): Updates a monitor for a project. Use when you need to modify monitor name, schedule, check-in margin, max runtime, timezone, status, owner, or alert thresholds for a project-level monitor.
- [update_organization_alert_rules](update_organization_alert_rules.json): Replaces an existing Sentry metric alert rule's configuration; fields not provided in the request are removed or reset. This action updates an existing metric alert rule. Note that this is a full replacement - any fields not provided will be removed or reset to defaults. Prerequisites: - The organization must have metric alerts feature enabled - The alert_rule_id must be a valid existing metric alert rule - Use sentry.fetch_organization_alert_rules to get existing alert rule IDs
- [update_organization_dashboard](update_organization_dashboard.json): Updates an existing custom dashboard, allowing modifications to its title, widgets, and data filters; providing `widgets`, `projects`, `environment`, `period`, `start`, `end`, or `filters` will overwrite existing settings for those fields.
- [update_organization_member_role](update_organization_member_role.json): Updates a Sentry organization member's organization-level role and team roles. The request sends an empty team roles list by default when team roles are omitted.
- [update_project_details](update_project_details.json): Updates a Sentry project's settings (e.g., name, slug, platform, bookmark status); `isBookmarked` can be updated with `project:read` permission, other fields typically require `project:write` or `project:admin` permissions.
- [update_project_issue_status_and_details](update_project_issue_status_and_details.json): Bulk updates attributes of issues in a Sentry project, selecting issues by ID or status. If IDs are omitted when a status filter is used, the update targets all issues matching that status.
- [update_release_details_for_organization](update_release_details_for_organization.json): Updates an existing Sentry release's details for an organization, including its reference, URL, release date, associated commits, or repository references.
- [update_saved_query_for_organization](update_saved_query_for_organization.json): Updates an existing Discover saved query for a Sentry organization. If omitted, projects is sent as an empty list and the query dataset as error-events.
- [update_team_information_by_organization_id](update_team_information_by_organization_id.json): Updates the slug for an existing team within a Sentry organization.
