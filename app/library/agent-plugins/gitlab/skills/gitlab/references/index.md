# gitlab operations

Choose the operation below, then read only its linked contract.

- [approve_merge_request](approve_merge_request.json): Approves a merge request in a GitLab project. Use this action when you need to record an approval from the authenticated user on a specific merge request. The authenticated user must be an eligible approver with appropriate permissions. Note that this action is idempotent — calling it multiple times on the same merge request will not create duplicate approvals.
- [archive_project](archive_project.json): Tool to archive a project. Use when you need to mark a project read-only after finishing active development. Call after confirming no further changes are required.
- [cancel_pipeline](cancel_pipeline.json): Tool to cancel a running pipeline in a GitLab project. Use this action when you need to stop a CI/CD pipeline that is currently executing or queued. Note that the API returns success (200) regardless of the pipeline's state, so this action can be safely called even if the pipeline has already finished or been canceled.
- [cherry_pick_commit](cherry_pick_commit.json): Cherry-pick a commit onto a project branch, creating a new commit. Set dry_run to true to check whether it applies cleanly without committing. Conflicts and empty changesets fail rather than creating a commit.
- [clone_issue](clone_issue.json): Clone an issue into a project, optionally including its notes. Copies as much data as possible when the destination has equivalent labels or milestones. Insufficient permissions can produce HTTP 400.
- [create_commit](create_commit.json): Creates a commit in a GitLab project with multiple file operations, including creating, updating, deleting, moving, and changing permissions. An optional force setting can overwrite the target branch with a new commit history.
- [create_commit_comment](create_commit_comment.json): Posts a comment to a specific commit in a GitLab project repository. Use this action when you need to provide feedback, review notes, or discussion on a particular commit. Line-specific comments require both path and line parameters; if invalid, the comment is placed at the commit level.
- [create_file](create_file.json): Creates a new file in a GitLab repository at the specified path with the given content. Use this action when you need to add a new file to a repository branch with a commit message.
- [create_issue_discussion](create_issue_discussion.json): Create an issue discussion thread that can receive replies. Backdating with created_at requires administrator or project/group owner rights.
- [create_issue_link](create_issue_link.json): Create a two-way relationship between two issues. The caller must be allowed to update both issues. Supports related issues, blocking, and blocked-by relationships.
- [create_issue_note](create_issue_note.json): Creates a new note (comment) on a project issue in GitLab. Use this action when you need to add a comment, provide feedback, or document information on an existing issue.
- [create_label](create_label.json): Creates a new label for a GitLab project with specified name, color, and optional attributes. Use this action when you need to create a new label for organizing issues and merge requests within a project. Labels help categorize and filter project items, making project management more efficient.
- [create_merge_request](create_merge_request.json): Creates a new merge request in a GitLab project to propose changes from a source branch into a target branch. Use this action when you need to create a merge request for code review, feature integration, or bug fixes. This action requires both the source and target branches to exist in the project.
- [create_merge_request_discussion](create_merge_request_discussion.json): Create a replyable merge request discussion on the overview or a diff position. For added lines supply new_line only; for removed lines supply old_line only; for unchanged lines supply both. Use line_range for multiline comments.
- [create_merge_request_note](create_merge_request_note.json): Create a merge request comment, not a line-specific diff discussion. Emoji-only content can create and return an emoji reaction instead of a note. Quick actions in the body can also change the merge request.
- [create_merge_request_pipeline](create_merge_request_pipeline.json): Create a detached or, when enabled, merged results merge request pipeline. This does not run a regular branch/tag pipeline. Configure .gitlab-ci.yml for merge request jobs (for example, only: [merge_requests]).
- [create_milestone](create_milestone.json): Creates a new milestone in a GitLab project. Milestones track progress towards a goal with a start date, due date, and associated issues. Use this action when you need to establish a new project milestone for organizing work, tracking release schedules, or planning sprints.
- [create_pipeline](create_pipeline.json): Tool to create a new pipeline for a specific branch or tag in a GitLab project. Use when you need to manually trigger a CI/CD pipeline run, optionally passing variables or inputs. For merge request pipelines, use the dedicated merge requests endpoint instead.
- [create_project](create_project.json): Tool to create a new project in GitLab. Implements POST /projects endpoint.
- [create_project_issue](create_project_issue.json): Tool to create a new issue in a GitLab project. Use when you need to report a bug, request a feature, or track a task within a specific project.
- [create_release](create_release.json): Create a project release, optionally creating its tag and adding asset links. Requires at least Developer access. Supply ref when the tag does not exist. See https://docs.gitlab.com/api/releases/#create-a-release.
- [create_release_asset_link](create_release_asset_link.json): Create an asset link for an existing project release. Link names and URLs must each be unique within the release. Supported URL protocols are HTTP, HTTPS, and FTP. Optionally set a direct download path. See https://docs.gitlab.com/api/releases/links/#create-a-release-link.
- [create_repository_branch](create_repository_branch.json): Tool to create a new branch in a project. Use when you need to create a new branch from an existing branch or a specific commit in a GitLab project.
- [create_repository_tag](create_repository_tag.json): Create a repository tag pointing to a commit, branch, or existing tag. Supply a message for an annotated tag. Creation is subject to the project's shared tag-creation rate limit and can return HTTP 429.
- [delete_issue](delete_issue.json): Delete an issue from a project permanently. Planner or Owner roles can delete any issue; other project members can delete issues they authored (GitLab 18.10+).
- [delete_issue_discussion_note](delete_issue_discussion_note.json): Permanently delete an existing note from an issue discussion. See https://docs.gitlab.com/api/discussions/#delete-an-issue-thread-note.
- [delete_issue_link](delete_issue_link.json): Delete an issue link, removing the two-way relationship without deleting either issue. Returns the deleted relationship's source issue, target issue, and link type. See https://docs.gitlab.com/api/issue_links/#delete-an-issue-link.
- [delete_issue_note](delete_issue_note.json): Deletes a note (comment) from an issue in a GitLab project. Use this action when you need to remove a specific comment from an issue. This action is irreversible — the note cannot be recovered once deleted.
- [delete_label](delete_label.json): Deletes a label from a GitLab project by its ID or title. Use this action when you need to remove a label from a project permanently. This action is irreversible — the label cannot be recovered once deleted.
- [delete_merge_request](delete_merge_request.json): Tool to permanently delete a merge request from a GitLab project. Use when you need to remove a merge request entirely, though closing is typically preferred to preserve the discussion history and audit trail. This action is irreversible — the merge request and its associated data cannot be recovered once deleted.
- [delete_merge_request_discussion_note](delete_merge_request_discussion_note.json): Permanently delete an existing note from a merge request discussion. See https://docs.gitlab.com/api/discussions/#delete-a-merge-request-thread-note.
- [delete_merge_request_note](delete_merge_request_note.json): Delete an existing note (comment) from a merge request. This permanently removes the specified note. See https://docs.gitlab.com/api/notes/#delete-a-merge-request-note.
- [delete_milestone](delete_milestone.json): Deletes a project milestone by its ID. Use when you need to permanently remove a milestone from a project. This action is irreversible — the milestone cannot be recovered once deleted. Requires at minimum the Planner role for the project.
- [delete_pipeline](delete_pipeline.json): Tool to delete a CI/CD pipeline by its ID within a specified project. This action expires all pipeline caches and deletes all immediately related objects such as builds, logs, artifacts, and triggers. This action is irreversible — the pipeline cannot be recovered once deleted. Use when you need to permanently remove a pipeline and all its associated data.
- [delete_project](delete_project.json): Tool to delete a GitLab project by its ID. Use when you need to remove a project, either by marking it for later deletion or deleting it immediately.
- [delete_release](delete_release.json): Delete a project release and return its release body, without deleting its tag. Requires at least the Developer role for the project. See https://docs.gitlab.com/api/releases/#delete-a-release.
- [delete_release_asset_link](delete_release_asset_link.json): Delete a specified asset link from a release and return the deleted link. See https://docs.gitlab.com/api/releases/links/#delete-a-release-link.
- [delete_repository_branch](delete_repository_branch.json): Tool to delete a branch from a GitLab project repository. Use when you need to remove a branch that is no longer needed. This action is irreversible — the branch cannot be recovered once deleted. Cannot delete default or protected branches.
- [delete_repository_file](delete_repository_file.json): Delete a file from a GitLab project's repository by creating a commit on the specified branch. You can supply author details and a last known commit ID to detect concurrent modifications, or specify a starting branch when creating the target branch.
- [delete_repository_tag](delete_repository_tag.json): Delete the specified repository tag from a project.
- [fork_project](fork_project.json): Forks a GitLab project to a specified namespace or the current user's namespace. Creates an independent copy of the project that maintains a relationship with the source. Use this action when you need to create a personal or team copy of a project for development, experimentation, or contribution workflows.
- [generate_release_evidence](generate_release_evidence.json): Collect evidence for an existing release. Returns success, not a release object. See https://docs.gitlab.com/api/releases/#collect-release-evidence.
- [get_commit_diff](get_commit_diff.json): Retrieve a page of file diffs for a commit, branch, or tag in a project. Configured diff limits can stop pagination before all changed files are returned.
- [get_commit_refs](get_commit_refs.json): Tool to get all references (branches or tags) a commit is pushed to. Use when you need to find out which branches or tags a specific commit belongs to in a GitLab project.
- [get_commit_sequence](get_commit_sequence.json): Tool to get the sequence number of a commit in a project by following parent links from the given commit. Use when you need to determine the order of a commit in the project's history.
- [get_commit_signature](get_commit_signature.json): Retrieve a commit's GPG, SSH, or X.509 signature. Unsigned commits return HTTP 404.
- [get_current_user](get_current_user.json): Retrieves information about the currently authenticated user. Use this action when you need to get details about the user who owns the authentication token, such as their profile information, permissions, and settings.
- [get_file](get_file.json): Retrieves a single file from a GitLab repository at a specific ref (branch, tag, or commit). Returns the file content as base64-encoded data along with metadata like size, encoding, and commit information. Use this action when you need to fetch the contents or details of a specific file from a GitLab project repository.
- [get_file_blame](get_file_blame.json): Return commit attribution and lines for a GitLab repository file.
- [get_issue](get_issue.json): Retrieves a single issue from a GitLab project by its internal ID (iid). Returns comprehensive issue details including description, state, labels, assignees, time tracking, and task status. Use this action when you need to inspect a specific issue's current state, check its metadata, or retrieve detailed information before performing updates or analysis. Requires knowing both the project ID/path and the issue's internal ID.
- [get_issue_by_id](get_issue_by_id.json): Retrieve an issue by its global ID. Administrator access is required. This does not accept a project-local IID. For a project ID/path and issue IID, use Get Issue instead. Returns issue details and preserves tier-specific fields.
- [get_issue_discussion](get_issue_discussion.json): Retrieve one issue discussion and its notes without modifying it. See https://docs.gitlab.com/api/discussions/#retrieve-an-issue-discussion-item.
- [get_issue_link](get_issue_link.json): Retrieve one issue relationship by project, issue IID, and issue link ID. Returns the source issue, target issue, and relationship type. See https://docs.gitlab.com/api/issue_links/#retrieve-an-issue-link.
- [get_issue_note](get_issue_note.json): Retrieves a single comment (note) from a GitLab issue by its ID. Use this action when you need to fetch the details of a specific note on an issue, including its content, author information, and metadata.
- [get_label](get_label.json): Retrieves a single project label by its ID or title. Use this action when you need to fetch details about a specific label within a GitLab project, such as its color, description, or associated issue/MR counts.
- [get_merge_request_approval_state](get_merge_request_approval_state.json): Retrieves rule-level approval satisfaction for a GitLab merge request. This endpoint requires GitLab Premium or Ultimate and shows which users count toward each rule, not every user who approved. Use Get Merge Request Approvals for all-tier aggregate status and the complete approving-user list.
- [get_merge_request_approvals](get_merge_request_approvals.json): Retrieves aggregate approval status for a GitLab merge request on any GitLab tier. Returns every approving user, even when an approval does not satisfy a specific approval rule. Use Get Merge Request Approval State instead when Premium or Ultimate rule-level satisfaction is needed.
- [get_merge_request_discussion](get_merge_request_discussion.json): Retrieve one merge request discussion and its notes without modifying it. See https://docs.gitlab.com/api/discussions/#retrieve-a-merge-request-discussion-item.
- [get_merge_request_note](get_merge_request_note.json): Retrieve one existing merge request note by its ID without modifying it. See https://docs.gitlab.com/api/notes/#retrieve-a-merge-request-note.
- [get_merge_request_notes](get_merge_request_notes.json): Fetches one page of comments on a specific merge request.
- [get_merge_request_raw_diffs](get_merge_request_raw_diffs.json): Get raw diffs of files changed in a merge request. GitLab diff limits may truncate results.
- [get_milestone](get_milestone.json): Retrieves a single milestone by its ID for a specific project. Returns detailed information including title, description, dates, and state. Use when you need to fetch complete details about a specific milestone.
- [get_project](get_project.json): Tool to get a single project by ID or URL-encoded path.
- [get_project_merge_request](get_project_merge_request.json): Tool to fetch full details for a single merge request when the MR IID is known. Use when you need to retrieve canonical metadata, description, state, branches, authors, and approval-related fields for a specific merge request.
- [get_project_merge_request_commits](get_project_merge_request_commits.json): Tool to get commits of a merge request. Use when you need to retrieve all commits associated with a specific merge request.
- [get_project_merge_requests](get_project_merge_requests.json): Lists merge requests for a GitLab project, with filters including state, labels and milestones. Returns one page per request.
- [get_project_release](get_project_release.json): Retrieve the complete release resource associated with a project tag.
- [get_projects](get_projects.json): Lists projects accessible to the authenticated user, with filtering and pagination. Private or group projects may be omitted if access is insufficient; each request returns one page.
- [get_projects_id_merge_requests_iid_diffs](get_projects_id_merge_requests_iid_diffs.json): Lists diff version metadata for a GitLab merge request, including commit SHAs, state and creation time.
- [get_raw_file](get_raw_file.json): Retrieves a file from a GitLab repository's raw file endpoint as text, without Base64 encoding. The response includes the content type when available.
- [get_release_asset_link](get_release_asset_link.json): Retrieve a specified asset link from a project's release by tag and link ID.
- [get_repository_branch](get_repository_branch.json): Tool to retrieve information about a specific branch in a project. Use when you need to get details for a single branch.
- [get_repository_branches](get_repository_branches.json): Retrieves a list of repository branches for a project. Use this when you need to get all branches or search for specific branches within a GitLab project.
- [get_repository_file_metadata](get_repository_file_metadata.json): Return GitLab repository file metadata without downloading file content.
- [get_repository_tag](get_repository_tag.json): Retrieve one repository tag by name, including its commit and associated release.
- [get_single_commit](get_single_commit.json): Tool to get a specific commit identified by the commit hash or name of a branch or tag. Use this when you need to retrieve detailed information about a single commit in a GitLab project repository.
- [get_single_pipeline](get_single_pipeline.json): Tool to retrieve details of a single pipeline by its ID within a specified project. Use when you need to get information about a specific CI/CD pipeline.
- [list_blocked_merge_requests](list_blocked_merge_requests.json): List one page of merge requests blocked by the specified merge request. Returns dependency relationships with blocking and blocked merge request details. Follow next_page to retrieve additional results.
- [list_commit_comments](list_commit_comments.json): Retrieves all comments associated with a specific commit in a GitLab project. Use this action when you need to view discussions or feedback left on a particular commit, including both general comments and inline code review comments.
- [list_commit_merge_requests](list_commit_merge_requests.json): List one page of merge requests associated with a commit. Returns the merge request that originally introduced the commit. Optionally filter by state and follow next_page for more results.
- [list_commit_statuses](list_commit_statuses.json): List one page of commit statuses, optionally filtered and sorted. By default GitLab returns only the latest statuses. Set all to true to include all statuses and follow next_page to retrieve additional pages.
- [list_deployment_merge_requests](list_deployment_merge_requests.json): List one page of merge requests shipped with a deployment. Not all deployments can be associated with merge requests. Supports the Merge Requests API filters; follow next_page to retrieve subsequent pages. https://docs.gitlab.com/api/deployments/#list-all-merge-requests-associated-with-a-deployment
- [list_group_issues](list_group_issues.json): List one page of group issues with filters. Follow next_page to retrieve more results.
- [list_group_merge_requests](list_group_merge_requests.json): List merge requests across a GitLab group and its subgroups.
- [list_group_releases](list_group_releases.json): List one page of releases for projects in a group. Use simple for limited release fields and sort for ascending or descending order. Follow next_page for additional pages. The group endpoint has no order_by parameter. Current GitLab documentation lists Free, Premium, and Ultimate availability, with no Premium-only limitation stated.
- [list_issue_closing_merge_requests](list_issue_closing_merge_requests.json): List one page of merge requests that close an issue when merged. Private projects and confidential issues require authorized credentials.
- [list_issue_discussions](list_issue_discussions.json): List one page of an issue's discussions, including threaded and individual notes.
- [list_issue_links](list_issue_links.json): List linked issues ordered by relationship creation time, oldest first. Results are filtered by the caller's authorization to view the linked issues.
- [list_issue_notes](list_issue_notes.json): Retrieves all notes (comments and activity) for a specific project issue in GitLab. Use this action when you need to view the discussion history, comments, or activity log on an issue to understand the context or follow up on conversations. Results are paginated and can be filtered by activity type or sorted by creation/update time.
- [list_issue_participants](list_issue_participants.json): List one page of users participating in an issue. Follow next_page for more results. Private projects and confidential issues require credentials with access to the issue.
- [list_issue_related_merge_requests](list_issue_related_merge_requests.json): List one page of merge requests related to an issue. Follow next_page for more results. Private projects and confidential issues require credentials with access to the issue.
- [list_issues](list_issues.json): List one page of issues accessible to the authenticated user across projects. Defaults to issues created by the current user, not every accessible issue. Use filters to narrow results and next_page to continue pagination. GitLab.com may reject scope=all; use a group or project issues action in that case.
- [list_labels](list_labels.json): Lists a page of labels for a GitLab project, with optional filtering by name, archived status, and ancestor inclusion.
- [list_merge_request_closed_issues](list_merge_request_closed_issues.json): List one page of issues that would close when a merge request is merged. These are not necessarily already closed. External trackers may return only an issue key and title. Follow next_page for additional results.
- [list_merge_request_diffs](list_merge_request_diffs.json): List the files changed by a GitLab merge request, including available patch content. Results are paginated, with up to 100 changed files per page; unified diff format can be requested. GitLab may omit diff content because of its diff limits.
- [list_merge_request_discussions](list_merge_request_discussions.json): Lists grouped discussion threads and their notes for a merge request.
- [list_merge_request_participants](list_merge_request_participants.json): List one page of participants for a merge request. Follow next_page to retrieve additional results.
- [list_merge_request_pipelines](list_merge_request_pipelines.json): List one page of pipelines for a merge request. Follow next_page to retrieve additional results.
- [list_merge_request_related_issues](list_merge_request_related_issues.json): List one page of issues referenced by a merge request's title, description, commit messages, comments, and discussions. Supports GitLab and external issue trackers. Follow next_page for additional results.
- [list_merge_request_reviewers](list_merge_request_reviewers.json): List a page of merge request reviewers with their review states. Follow next_page to retrieve additional results.
- [list_merge_requests](list_merge_requests.json): Retrieves a list of merge requests from across all accessible projects based on scope and filters. Use this action when you need to query merge requests at the instance or user level (not scoped to a specific project), such as finding all merge requests created by a user, assigned to a user, or awaiting review. By default returns merge requests created by the authenticated user; use scope=all to retrieve all accessible merge requests.
- [list_milestones](list_milestones.json): Lists a page of milestones for a specific project, with optional filtering by state, title, search terms, or IID.
- [list_package_files](list_package_files.json): List the files belonging to a package in a GitLab project.
- [list_pipeline_jobs](list_pipeline_jobs.json): Tool to retrieve a list of jobs for a specified pipeline within a project. Use this when you need to inspect the status or details of jobs associated with a particular CI/CD pipeline.
- [list_pipeline_variables](list_pipeline_variables.json): Retrieve variables associated with a project pipeline. GitLab returns 404 if the pipeline variables file is missing from storage.
- [list_project_issues](list_project_issues.json): Tool to list issues for a project with filtering options (state, labels, search, assignee, author, etc.). Use when you need to browse, filter, or triage project issues to confirm IIDs or decide what to update/close.
- [list_project_pipelines](list_project_pipelines.json): Tool to retrieve a list of pipelines for a specified project. Use when you need to get information about CI/CD pipelines, such as their status, source, or creation/update times.
- [list_project_releases](list_project_releases.json): List one page of project releases, sorted by released_at descending by default. Optionally sort by creation time or include rendered descriptions. Follow next_page to retrieve additional releases.
- [list_release_asset_links](list_release_asset_links.json): List asset links from a project release identified by its tag. Returns link IDs, names, URLs, and link types, not downloaded asset content.
- [list_repository_commits](list_repository_commits.json): Tool to get a list of repository commits in a project. Use when you need to retrieve commit history for a specific project, branch, or time range.
- [merge_merge_request](merge_merge_request.json): Merge a GitLab merge request immediately or enable auto-merge when checks pass. A successful merge is irreversible, and should_remove_source_branch can also delete the source branch.
- [move_issue](move_issue.json): Moves an issue from one project to another in GitLab. The issue receives a new IID and project_id in the destination project. Use this action when you need to relocate an issue to a different project, such as when reorganizing work or transferring issues between team projects. If equivalent labels or milestones exist in the destination project, they are automatically assigned to the moved issue.
- [rebase_merge_request](rebase_merge_request.json): Enqueue rebasing a merge request's source branch against its target branch. HTTP 202 means queued, not completed. Poll the retrieve merge request endpoint with include_rebase_in_progress=true to check rebase_in_progress and merge_error. Requires permission to push to the source branch, including force push when protected. See https://docs.gitlab.com/api/merge_requests/#rebase-a-merge-request.
- [reorder_issue](reorder_issue.json): Reorder a project issue for manually sorted issue lists. Position references use global issue IDs, not project-local IIDs. Supply at least one reference. Each name identifies the neighbor that should be before or after the reordered issue, not a move-command direction.
- [reply_issue_discussion](reply_issue_discussion.json): Add a note to an issue thread, or turn a single comment into a thread. System notes cannot receive replies (GitLab returns HTTP 400). See https://docs.gitlab.com/api/discussions/#add-a-note-to-an-issue-thread.
- [reply_merge_request_discussion](reply_merge_request_discussion.json): Add a note to a merge request thread, or turn a single comment into a thread. See https://docs.gitlab.com/api/discussions/#add-note-to-a-merge-request-thread.
- [reset_merge_request_approvals](reset_merge_request_approvals.json): Reset all approvals for a specified merge request. Available only to bot users with a valid project or group token. Human users receive 401 Unauthorized, even with an otherwise valid personal access token. See https://docs.gitlab.com/api/merge_request_approvals/#reset-approvals-for-a-merge-request.
- [retry_pipeline](retry_pipeline.json): Retries failed or canceled jobs in a pipeline. Use this action when you need to re-run a pipeline that has failed or was canceled. Note that if there are no failed or canceled jobs in the pipeline, calling this action has no effect.
- [revert_commit](revert_commit.json): Revert a commit on a target branch, creating a new commit. Set dry_run=true to check applicability without writing. Conflicting or already-reverted changes can fail.
- [search_project](search_project.json): Search resources and repository content within one GitLab project.
- [unapprove_merge_request](unapprove_merge_request.json): Removes the approval from the currently authenticated user for a specified merge request. Use this action when you need to revoke your previously given approval on a merge request. The action requires the merge request to have been previously approved by the authenticated user.
- [unarchive_project](unarchive_project.json): Unarchive a GitLab project to restore active use. Requires administrator access or the Owner role on the project. Idempotent: unarchiving an already unarchived project does not change it.
- [update_issue_discussion_note](update_issue_discussion_note.json): Update the content of an existing issue discussion note. See https://docs.gitlab.com/api/discussions/#update-an-issue-thread-note.
- [update_issue_note](update_issue_note.json): Updates an existing note (comment) on a GitLab issue. Use this action when you need to edit the content of a previously created comment on an issue. This is useful for correcting typos, adding additional information, or updating outdated information in issue discussions.
- [update_label](update_label.json): Updates an existing label in a GitLab project by modifying its name, color, description, priority, or archived status. At least one of new_name or color must be provided to perform the update. Use this action when you need to rename a label, change its appearance, update its description, adjust its priority, or archive/unarchive it.
- [update_merge_request](update_merge_request.json): Updates an existing merge request in a GitLab project (title, description, assignees, reviewers, labels, state, etc.). Use this action when you need to modify merge request details, manage assignees/reviewers, update labels, close/reopen merge requests, or configure merge settings like squash or auto-removal of source branch. This action is idempotent and can be called multiple times with the same parameters.
- [update_merge_request_discussion](update_merge_request_discussion.json): Resolve or reopen a resolvable merge request discussion thread.
- [update_merge_request_discussion_note](update_merge_request_discussion_note.json): Update the content of a merge request thread note, or resolve/reopen it. Set exactly one of body or resolved. An empty resolved value is a no-op. See https://docs.gitlab.com/api/discussions/#update-a-merge-request-thread-note.
- [update_merge_request_note](update_merge_request_note.json): Update an existing merge request note's content and optional confidential flag. This edits a published note, not an unpublished draft note or a diff discussion. See https://docs.gitlab.com/api/notes/#update-a-merge-request-note.
- [update_milestone](update_milestone.json): Updates an existing milestone in a GitLab project, allowing you to modify the title, description, dates, or state. Use this action when you need to change milestone details, adjust deadlines, or close/reopen a milestone.
- [update_project](update_project.json): Update an existing GitLab project's settings, visibility, features, and CI/CD configuration. Requires Maintainer or Owner; some settings require Owner, administrator access, a paid tier, or a newer GitLab version. Only supplied settings are changed. Topics replace existing topics. Avatar accepts an image URL to upload. To clear an array, send an empty array in a separate call without avatar.
- [update_project_issue](update_project_issue.json): Tool to update an existing issue in a GitLab project (title, description, labels, assignees, state, etc.). Use when you need to modify issue details, close/reopen issues, or manage labels and assignments.
- [update_release](update_release.json): Update a project release's name, description, milestones, or release date. Requires Developer access. Omitted fields remain unchanged; pass an empty milestones array to remove all milestone associations. See https://docs.gitlab.com/api/releases/#update-a-release.
- [update_release_asset_link](update_release_asset_link.json): Update an existing asset link for a project release. Supply at least one of name or url; optionally change the direct asset path or link type. Supported URL protocols are HTTP, HTTPS, and FTP. See https://docs.gitlab.com/api/releases/links/#update-a-release-link.
- [update_repository_file](update_repository_file.json): Updates an existing file in a GitLab repository. Commits the changes to the specified branch with the provided commit message. Use this action when you need to modify file contents, change file permissions, or update files in a specific branch. Note that if concurrent modifications occur (detected via last_commit_id), the update will fail.
