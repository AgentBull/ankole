# salesforce operations

Choose the operation below, then read only its linked contract.

- [add_contact_to_campaign](add_contact_to_campaign.json): Adds a contact to a campaign by creating a CampaignMember record to track campaign engagement. Fails if the contact is already a member of the campaign; pre-check membership via SOQL before calling.
- [add_lead_to_campaign](add_lead_to_campaign.json): Adds a lead to a campaign by creating a CampaignMember record, allowing you to track campaign engagement. Both `campaign_id` and `lead_id` must be valid Salesforce IDs of active, existing records — names or emails cannot be substituted, and deleted or inactive records will cause the call to fail. This is a persistent CRM write; confirm the correct lead and campaign before calling.
- [add_opportunity_line_item](add_opportunity_line_item.json): Adds a product (line item) to an opportunity. The product must exist in a pricebook entry that's associated with the opportunity's pricebook.
- [associate_contact_to_account](associate_contact_to_account.json): Associates a Salesforce contact with an account by updating its AccountId, replacing any existing association. It can also update additional contact fields supplied in custom_fields.
- [clone_opportunity_with_products](clone_opportunity_with_products.json): Clones a Salesforce opportunity, with optional name, close date, and stage changes, and optionally copies its product line items. The opportunity is created before products are copied, so a later failure can leave a partial clone.
- [clone_record](clone_record.json): Creates a copy of an existing Salesforce record by reading its data, removing system fields, and creating a new record. Optionally apply field updates to the clone.
- [complete_task](complete_task.json): Updates a Salesforce task with status Completed, optional completion notes, and additional field values. Additional field values can override the status or description set by the action.
- [create_account](create_account.json): Creates a new account in Salesforce with the specified information. Returns the created Account's ID at `data.response_data.id`.
- [create_campaign](create_campaign.json): Creates a new campaign in Salesforce. Only `name` is universally required, but org-level validation rules commonly enforce `type`, `status`, `start_date`, and `end_date` as well — omitting them may cause creation to fail.
- [create_contact](create_contact.json): Creates a new contact in Salesforce with the specified information. Writes to live CRM data — obtain explicit user confirmation before executing. Failures may reflect org-specific validation rules, permission restrictions, or duplicate rules rather than invalid inputs.
- [create_lead](create_lead.json): Creates a new lead in Salesforce. `LastName` and `Company` are required. Org-level validation rules (e.g., email format, custom required fields) may reject requests beyond these; inspect the error response body for the failing field. The created lead `id` is returned in a response wrapper, not at the top level.
- [create_note](create_note.json): Creates a new note attached to a Salesforce record with the specified title and content. Does not deduplicate — identical calls create duplicate notes. High-volume creation can trigger REQUEST_LIMIT_EXCEEDED; apply exponential backoff on retries.
- [create_opportunity](create_opportunity.json): Creates a Salesforce opportunity with the specified information. The contact ID parameter is ignored, and standard amount and probability values are sent only when positive.
- [create_s_object_record](create_s_object_record.json): Tool to create a new Salesforce SObject record. Use when you need to create any type of standard or custom Salesforce object record by specifying the object type and field values.
- [create_task](create_task.json): Creates a new task in Salesforce to track activities, to-dos, and follow-ups related to contacts, leads, or other records. Ensure who_id, what_id, and owner_id reference existing records before calling; invalid IDs cause silent linkage failures or validation errors.
- [delete_account](delete_account.json): Deletes a Salesforce account by its ID.
- [delete_campaign](delete_campaign.json): Permanently deletes a campaign from Salesforce. This action cannot be undone.
- [delete_contact](delete_contact.json): Permanently deletes a contact from Salesforce. This action cannot be undone. Associated records (activities, opportunities) lose the contact reference upon deletion — ensure related data is migrated or acceptable to lose before proceeding. Returns HTTP 204 with empty body on success.
- [delete_lead](delete_lead.json): Permanently deletes a lead from Salesforce. This action cannot be undone.
- [delete_note](delete_note.json): Permanently deletes a note from Salesforce. This action cannot be undone.
- [delete_opportunity](delete_opportunity.json): Permanently deletes an opportunity from Salesforce. This action cannot be undone.
- [delete_report](delete_report.json): Delete a saved Salesforce report by moving it to the Recycle Bin.
- [delete_sobject](delete_sobject.json): Delete a single Salesforce record by object type and record ID. Works with standard and custom objects.
- [execute_sosl_search](execute_sosl_search.json): Execute a SOSL search to search across multiple Salesforce objects. Use when you need to search for text across multiple object types simultaneously.
- [get_account](get_account.json): Retrieves a Salesforce account by ID and returns the fields represented in the account response schema.
- [get_all_fields_for_object](get_all_fields_for_object.json): Retrieves all fields (standard and custom) for a Salesforce object with complete metadata including field types, constraints, picklist values, and relationships.
- [get_campaign](get_campaign.json): Retrieves a Salesforce campaign by ID and returns the fields represented in the response model.
- [get_child_records](get_child_records.json): Tool to get child records for a specified parent record and child relationship name. Use when you need to retrieve related records from a parent-child relationship in Salesforce, such as getting all Contacts for an Account or all Opportunities for an Account. Results are paginated with configurable page size.
- [get_contact](get_contact.json): Retrieves a Salesforce contact by ID, optionally requesting selected fields. The response is limited to fields represented by the tool's response schema.
- [get_deleted_records](get_deleted_records.json): List record IDs and deletion times for one Salesforce object and time window.
- [get_lead](get_lead.json): Retrieves a specific lead by ID from Salesforce, returning all available fields.
- [get_note](get_note.json): Retrieves a specific note by ID from Salesforce, returning all available fields. Notes with IsPrivate=true require the integration user to have sufficient permissions; inaccessible private notes will not be returned.
- [get_opportunity](get_opportunity.json): Retrieves a Salesforce opportunity by its ID, optionally requesting a selected set of fields. Use it to inspect the opportunity's details without retrieving every available field.
- [get_report_instance](get_report_instance.json): Gets the results of a report instance created by running a report. Poll `attributes.status` until it equals 'Success' before parsing results. Response data is nested under `factMap` and `reportExtendedMetadata`; an empty `factMap` or zero rows is a valid successful result, not an error.
- [get_s_object_record](get_s_object_record.json): Tool to retrieve a single Salesforce record by ID from any sObject type. Use when you need to get detailed information about a specific record.
- [get_s_objects_updated](get_s_objects_updated.json): Retrieves IDs of sObject records updated within a specified timeframe, along with the latest date covered. Use it to track changes or synchronize records of a specified object type.
- [get_supported_objects_directory](get_supported_objects_directory.json): Tool to get a Salesforce org's active theme and directory of supported objects. Use when you need to discover available objects that are supported by the User Interface API, including their CRUD permissions, labels, and theme information.
- [get_user_info](get_user_info.json): Retrieves information about the current user or a specific user in Salesforce.
- [list_accounts](list_accounts.json): List Salesforce accounts using a SOQL query with filtering, sorting, and field selection. Results are paginated; the response retains only fields defined in the account response model, so other selected fields may be omitted.
- [list_campaigns](list_campaigns.json): Lists campaigns from Salesforce using SOQL query, allowing flexible filtering, sorting, and field selection. Results returned under `response_data.records`; use `Id` (not `Name`) to identify campaigns in downstream operations.
- [list_contacts](list_contacts.json): Lists Salesforce contacts using a SOQL query with filtering, sorting, and field selection, returning one page with pagination indicators. Records must include Id, and fields outside the response schema are not preserved.
- [list_leads](list_leads.json): Lists leads from Salesforce using SOQL query, allowing flexible filtering, sorting, and field selection. Results are paginated; follow nextRecordsUrl in the response to retrieve subsequent pages — the first page may silently omit matching records beyond the page limit.
- [list_notes](list_notes.json): Lists Salesforce Note or ContentNote records using a SOQL query with filtering, sorting, and field selection. Include Id in the selected fields so returned records can be validated.
- [list_reports](list_reports.json): Lists reports with basic metadata including name, ID, and URLs. Note: the Analytics REST API (GET /analytics/reports) returns only up to ~200 recently-viewed reports, not the org's entire report catalog.
- [log_call](log_call.json): Logs a completed phone call as a task in Salesforce with call-specific details like duration, type, and disposition.
- [log_email_activity](log_email_activity.json): Creates an EmailMessage record to log email activity in Salesforce, associating it with related records. Requires EmailMessage insert permissions enabled at the org level; some orgs block this entirely.
- [query_all](query_all.json): Tool to execute SOQL queries including soft-deleted and archived records. Use when you need to query records that have been deleted via merge or delete operations, or when accessing archived Task and Event records.
- [query_more](query_more.json): Retrieve the next page of SOQL results using a query locator (GET /query/{queryLocator}). SOQL queries return at most ~2000 rows per response plus a nextRecordsUrl when more remain; this action follows that locator. Call it repeatedly, passing each response's nextRecordsUrl, until done=true. Without it, run_soql_query / query results beyond the first page are unreachable.
- [remove_from_campaign](remove_from_campaign.json): Delete a CampaignMember record by its ID, or find and delete the first matching member for a campaign and lead or contact ID. When a CampaignMember ID is supplied, it is deleted directly without checking the campaign ID.
- [run_report](run_report.json): Runs a report synchronously (GET /analytics/reports/{id}?includeDetails=true) and returns the results in one call. This does NOT create an asynchronous report instance — for that, use the async run resource. Results are returned in a nested structure (factMap, reportExtendedMetadata), not a flat record list; an empty factMap/rows is a valid result. Avoid repeated calls when freshness allows.
- [run_report_async](run_report_async.json): Run a Salesforce report asynchronously (POST /analytics/reports/{id}/instances). Returns an instance id and status; the report runs in the background. Retrieve results later with get_report_instance using the returned instance id. Use this (instead of the synchronous run_report) for large reports or to avoid blocking. Without this action, get_report_instance had no obtainable instance id.
- [run_soql_query](run_soql_query.json): Executes a SOQL SELECT query against Salesforce data and returns a page of matching records with pagination information. Queries using FIELDS(ALL) or FIELDS(CUSTOM) are limited to 200 records.
- [search_accounts](search_accounts.json): Search Salesforce accounts by name, industry, type, location, or contact information. Multiple filters are combined with OR, so accounts matching any filter can be returned; without filters, returns recent accounts.
- [search_campaigns](search_campaigns.json): Search for Salesforce campaigns using multiple criteria like name, type, status, date range, or active status. Requires access to the Campaign object (Marketing User feature must be enabled in the org). For complex sorting (multi-field ORDER BY), use salesforce.run_soql_query instead.
- [search_contacts](search_contacts.json): Searches Salesforce contacts by name, email, phone, account name, or title using partial matches. Multiple criteria are combined with OR; without criteria, it returns recent contacts up to the requested limit.
- [search_leads](search_leads.json): Searches Salesforce leads by name, email, phone, company, title, status, or lead source, combining supplied criteria with OR. Without criteria, it returns recent non-converted leads; partial matches may return multiple candidates, so confirm identifying fields before using a lead ID.
- [search_notes](search_notes.json): Search Salesforce Note records by title, body, parent name, owner, creation date, or privacy. Parent-name searches cover Accounts, Contacts, Leads, Opportunities, and Cases; failed parent or owner lookups can return empty results, and body matches are limited before other filters apply.
- [search_tasks](search_tasks.json): Search for Salesforce tasks using multiple criteria like subject, status, priority, assigned user, related records, or dates. Always provide at least one filter criterion — no filters produces broad, slow results. For complex filtering not supported here, use salesforce.run_soql_query.
- [send_email](send_email.json): Sends an email through Salesforce with options for recipients, attachments, and activity logging. Check the returned action success status and errors to determine whether Salesforce accepted the request.
- [send_email_from_template](send_email_from_template.json): Sends an email using a predefined Salesforce email template with merge field support.
- [update_account](update_account.json): Updates an existing account in Salesforce with the specified changes. Only provided fields will be updated.
- [update_campaign](update_campaign.json): Updates an existing campaign in Salesforce with the specified changes. Only provided fields will be updated.
- [update_contact](update_contact.json): Updates an existing contact in Salesforce with the specified changes. Only provided fields will be updated. Returns HTTP 204 with no body on success; use salesforce.get_contact to verify applied changes. Org-level validation rules, duplicate rules, or field-level permissions may reject correctly formatted requests with HTTP 400; inspect the error response to identify the constraint.
- [update_lead](update_lead.json): Updates an existing lead in Salesforce with the specified changes. Only provided fields will be updated.
- [update_note](update_note.json): Updates an existing note in Salesforce with the specified changes. Only provided fields will be updated.
- [update_opportunity](update_opportunity.json): Updates an existing Salesforce opportunity with supplied standard or custom fields, omitting empty standard strings. The response can contain update results or structured Salesforce errors; a successful 204 response is represented by an empty result.
- [update_record](update_record.json): Tool to update a record's data in Salesforce via UI API. Use when you need to modify field values on an existing record. Salesforce validation rules are enforced. Pass If-Unmodified-Since header to prevent conflicts.
- [update_task](update_task.json): Updates an existing task in Salesforce with new information. Only provided fields will be updated.
- [upsert_sobject_by_external_id](upsert_sobject_by_external_id.json): Upsert a Salesforce record by external ID, creating or updating it based on the matching value. An update-only option prevents creation when no record matches.
