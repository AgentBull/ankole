Deep Research 适合文献梳理、竞品研究、多来源事实核查，也适合需要比较不同解释的预测判断和对既有预测的复盘。这类工作需要反复搜索、阅读和交叉验证，不适合让当前对话一直等待。Agent 会把它交给[后台 Agent 任务](../background-jobs/)执行，同时继续处理你的其他消息。

一次严肃的调研通常需要 30–90 分钟：任务要经过多轮收集、分析和复核才能给出高质量报告。只需要一个快速回答时，直接问即可，不必使用 Deep Research。

## 开始前

先完成[快速开始](../quickstart/)，并确认 Agent 可以在聊天渠道中正常回复。需要搜索公开网页时，还要为 Agent 配置 `web_search` 和 `web_fetch` 模型档案。

后台任务可以使用 Ankole 的 LLM Provider，也可以使用已经添加的 [ChatGPT 订阅账号](../codex-accounts/)。运行方式在 **Console → 智能体 → 后台 Agent 任务** 中设置。

任务会自动获得该 Agent 当前启用、且允许在后台任务中运行的全部 Skills。实例启用了数据源类 Skill 时（例如财经数据接口），任务会优先使用这些数据源，其次才是公网搜索。

## 发起调研

直接说明研究对象、时间范围、证据要求和交付形式，并明确要求后台执行：

```text
请把这项工作作为 Deep Research 后台任务执行：
比较这三家厂商过去两个季度的定价和产品更新。
引用原始来源，区分事实与推断，最后给我一份带链接的中文报告。
如果需要扩大范围或使用付费数据源，请先问我。
```

### 确认研究要求

创建任务前，Agent 会像访谈一样澄清每个还没定下来的研究选择：目标和用途、成功标准、范围和时间边界、证据规则、交付形式。它一次只问一个问题，并附上自己建议的答案；环境里查得到的事实它自己查，只把需要你决定的问题交给你。任务只在你确认后创建。

不想逐条回答时，直接说“不用再问了，直接创建，剩下的你决定”。Agent 会简述它的假设，然后创建任务。

明确的范围比“深入研究一下”更有用。请求里下面这些内容写得越清楚，报告越接近你要的东西：

- 研究对象和要回答的问题，而不只是一个主题；
- 时间范围和信息截止点；
- 证据规则：只接受官方来源、必须给出处、事实与推断分开；
- 分析方法（可选）：例如要求用 ACH 比较竞争假说；
- 交付形式与语言：默认交付 Markdown 报告；要求 PDF、PPT 或网页时只交付该格式（除非你同时要 Markdown 源文件），未指定视觉风格时采用该 Agent 的 `DESIGN` 视觉规范；
- 边界：预算、付费数据源、是否允许扩大范围，以及截止时间。

篇幅按约数处理：“3 页 PDF”指大约 3 页，除非你要求精确值。

## 任务如何执行

了解任务内部的工作方式，有助于解读进度和判断结果的可信度。每个 Deep Research 任务都在自己的持久工作区中按四个阶段推进：

1. **规划**。任务先列出工作区中可用的 Playbook 并读取与问题相关的方法，必要时先做一次快速探查，确认研究对象的当前含义、关键概念和数据源，再制定详细的收集计划。
2. **收集**。多个子 Agent 并行收集。所有有价值的材料整理为 `sources/` 下的来源笔记，记录出处、发布时间、置信度和链接。每个数据源只由一个负责人收集一次，避免重复抓取；已启用的 Skill 数据源优先于公网搜索。
3. **分析与复核**。结论必须从证据一步步推导出来；报告区分事实、观点、假说和推断，列出不确定性。然后由一个看不到研究过程的独立复核者审查：核对引用、检查逻辑一致性、寻找其他解释。复核者只提意见，最终判断仍由研究者负责；无法达成一致的分歧会连同理由保留在报告里。
4. **交付**。任务先对照成功标准逐条审计报告：每条标准要么有证据支撑，要么作为公开缺口连同对结论的影响写明。之后生成你要求的格式，并做一次轻量终检。

任务把私有工作状态记在工作区的 `research-state.md` 中：成功标准和当前状态、候选结论和未补上的缺口、已排除的方向和原因。Worker 中断后任务可以据此恢复，不重复已经完成的工作。研究中途发现框架错了（对象认错、问题读偏、核心假设不成立）时，任务会丢弃被污染的分析、重做受影响的阶段，但保留已收集的来源。

## Playbook：可复用的研究方法

Playbook 是任务工作区 `playbooks/` 目录下的方法论文件，随 deep-research Agent Plugin 的工作区模板分发。每个 Playbook 声明自己适用的场景；任务在规划阶段读取与当前问题相关的那些，Playbook 也可以用自己的复核流程替换默认复核。

当前内置两个通用方法：

- **ach**（Analysis of Competing Hypotheses，竞争假说分析）。适合在信息不完整、互相冲突甚至可能被误导时，对重要的预测或诊断比较多个合理解释。任务维护一个假说与证据的对照矩阵，评估每条证据在各个假说下的预期程度，找出真正有区分力的证据和关键假设。它带有自己的三轮复核：复核者先只看来源、独立重建比较，再对照矩阵找缺陷，最后核对报告，防止被研究者的结论带偏。
- **analogical-foresight**（类比预见）。适合用历史案例为前瞻分析提供机制、变量和检验点。每个类比要给出完整链条：来源案例中成立的机制、到目标的具体映射、迁移成立的条件、目标侧可观察的信号。只有表面相似的历史故事不构成证据。

你可以在请求中直接指定方法（例如“用 ACH 比较这三种解释”），也可以交给任务自己选。私有部署可以在模板中加入自己领域的 Playbook，例如内部研究方法和行业数据源清单；新创建的任务会在规划阶段自动看到它们。

## 任务运行时

Agent 创建任务后，当前聊天不会被占住。你可以继续提问，也可以在 **Console → 后台 Agent 任务** 中查看计划、进度、模型用量和当前状态。

任务需要你决定方向时，会回到原会话提问。请在同一会话中回答；`waiting_on_user` 表示正在等你，不是故障。你也可以随时在原会话补充材料或修正要求，主 Agent 会把它们转给任务。

## 查看结果

任务完成后，主 Agent 会先读取报告再交付：报告声明的缺口或限制影响研究目的时，它会指出来；当缺的是它掌握的信息或你的决定时，它会补给任务并让任务继续完善。

拿到报告后，检查结论是否有来源支撑、时间范围是否正确、事实与推断是否分开。报告应当自包含；需要核对某条证据时，让 Agent 从任务工作区把对应的来源笔记读给你。需要补充时，直接让 Agent 基于这项任务继续，不必重新描述全部背景。

任务失败或长时间排队时，打开任务详情读取错误和状态。各状态的含义、取消方法和运行方式见[后台 Agent 任务](../background-jobs/)。
