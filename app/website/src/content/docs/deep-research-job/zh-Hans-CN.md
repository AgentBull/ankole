Deep Research 非常适合开展系统性文献梳理、深度竞品调研、多信源交叉事实核查，也适合需要横向权衡多种合理解释的前瞻预测与事后复盘。这类工作往往需要反复检索、精读原始材料并交叉印证，不适合卡住当前聊天窗口干等——Agent 会将其委派给独立的[后台 Agent 任务](../background-jobs/)异步推进，同时继续在聊天中响应你的其他日常消息。

它和“随手搜几个网页再拼一篇摘要”完全是两码事。每个 Deep Research 任务都会在专属的持久化工作区里按严谨的四阶段流程推进：先摸底规划，再并行采集原始资料沉淀为来源笔记，接着从证据链一步步推导结论，随后交由一名完全看不到前置推理过程的独立复核者做对抗性挑刺，最后对照成功标准逐条审计通过后才正式交付。一场严肃的深度调研通常耗时 30 至 90 分钟；如果手头问题只需要几分钟内的快速解答，直接在对话里提问即可，不必动用 Deep Research。

## 开始前

请先完成[快速开始](../quickstart/)中的基础配置，确认目标 Agent 已能在聊天渠道中正常收发消息；若调研涉及检索公开互联网信息，还需为该 Agent 配好 `web_search` 与 `web_fetch` 模型档案。

所有后台任务均统一经由 AIGateway 调用模型。若希望使用 ChatGPT 订阅额度承载长时调研，可先创建一个 [ChatGPT 订阅 Provider](../chatgpt-subscription-provider/)，再前往 **Console → 智能体 → 后台 Agent 任务**模型档案中绑定该 Provider。

任务启动时会自动继承该 Agent 当前已启用、且允许在后台任务中运行的全部 Skills。如果实例已接入专用数据源 Skill（如金融终端接口或企业内部业务系统），调研任务会优先调取这些权威内部与专业数据源，其次才用公网搜索补全，无需为单次后台任务重复配置权限。

## 发起调研

直接在对话中交代清楚研究对象、时间跨度、证据要求与期望交付形式，并点明“作为 Deep Research 后台任务执行”即可：

```text
请把这项工作作为 Deep Research 后台任务执行：
比较这三家厂商过去两个季度的定价和产品更新。
引用原始来源，区分事实与推断，最后给我一份带链接的中文报告。
如果需要扩大范围或使用付费数据源，请先问我。
```

### 创建前的澄清

收到指令后，Agent 不会只凭一句话就仓促开工。正式创建后台任务前，它会像资深研究员做需求访谈一样，与你逐项敲定尚未明确的四梁八柱：核心研究目的与决策用途、交付成功标准、时间与范围边界、证据采信规则以及最终交付格式。每次它只聚焦追问一个关键问题，并附上自己的默认建议供你拍板；凡是它自己能在现有环境里查明的背景事实绝不拿来烦你，只把真正需要你拿主意的取舍摆到台面上，待你确认无误后才正式立项启动。

花两三分钟配合完成这轮澄清非常值得：一旦最初的研究靶向偏了，后面整整一个小时的资料搜集与推演都会沦为无用功，而提前校准方向往往只需回复一句话。

如果你手头正忙、不想逐条确认，也可以直接告诉它：“不用再问了，直接创建任务，未尽细节由你自行决定。”此时 Agent 会先简明扼要地列出它代你设定的默认前提与授权给任务自主裁量的边界，随即直接启动后台任务。

### 一份好请求包含什么

清晰的边界条件远比一句笼统的“帮我深入研究一下”管用得多。以下要素交代得越具体，最终拿到的报告就越贴合你的实际决策需要：

- **明确的研究对象与待解问题**（而非宽泛的大词）：问“分析一下新能源行业”与问“这三家头部厂商谁在未来两个季度最可能率先降价、核心依据是什么”，产出的报告深度截然不同。
- **时间跨度与信息截止点（Cutoff）**：尤其是在做历史决策复盘或模拟当时视角做推演时，信息截止点直接决定了任务是否允许引用事后才披露的“上帝视角”信息。
- **证据采信规则**：例如是否只采信官方一手披露、是否每条关键数据都必须附原始链接、是否要求严格区分客观事实与主观推论。
- **指定分析方法论（可选）**：例如明确要求采用竞争假说分析法（ACH）横向比对多套解释，或要求采用类比预见法借历史先例推演未来；未指定时任务会根据问题性质自主挑选。
- **交付格式与语种**：默认交付结构化 Markdown 报告；若明确要求生成 PDF、演示文稿（PPT）或独立网页，则仅交付所要求的成品格式（除非你同时要求保留 Markdown 源码），未额外指定视觉风格时默认套用该 Agent 的 `DESIGN` 品牌视觉规范。
- **资源与时间红线**：预算上限、是否允许调用付费外部数据源、中途能否自行拓宽关联范围，以及最晚交付时间。

注：对篇幅的要求默认按合理约数把握（例如要求“3 页 PDF”即按约 3 页体量编排，除非你明确要求严格卡死页数）。

## 任务如何执行

了解任务在工作区内部的推进逻辑，能帮你更好地看懂实时进度、把关结论成色，并在关键节点精准追问。每个 Deep Research 任务都在专属持久化工作区内分四个阶段稳步推进：

### 一、规划

启动后，任务会先扫描工作区内置的全部方法论指南（Playbook），载入与当前课题匹配的规程。如果研究命题跨度较大、目标定义尚存模糊之处，或相关行业格局在模型训练截止日之后可能已发生重大演变，任务会先派出一个轻量探路子 Agent 做一轮快速摸底。这轮探路既不攒证据也不下结论，纯粹用来厘清研究对象当下的真实边界，摸清模型先验知识之外的新术语、核心竞争维度、精准检索词与权威数据入口。

完成摸底后，主任务才会落笔制定详尽的信息采集计划——“先探路、后立项”是为了确保整套搜集方案扎根于当下的客观现实，而不是照着大模型记忆里的过时旧地图按图索骥。

### 二、收集证据

进入采集阶段后，多个子 Agent 会并行推进搜集计划，将一切有价值的原始素材沉淀为 `sources/` 目录下的标准 Markdown 来源笔记，并在文件开头的 YAML 元数据区完整登记出处、发布日期、作者、可信度评估与原始链接。后续一切分析推演都必须锚定到这些落盘笔记上，严禁凭某次临时网页搜索的模糊印象下判断。

采集过程严格遵守**单一所有权规则**：每一个外部数据源、每一份原始文档都只指派唯一一个子 Agent 负责拉取并落盘写入，其余子 Agent 直接读取这份本地文件，绝不重复发起外部请求；同一份监管公告、财报或数据集只下载一遍，并以清晰易辨的规范文件名保存以便下游查阅。凡是外部工具支持批量查询的，一律按批次合并请求，避免低效的逐条零星调用。

在信源优先级上，已启用的专业数据源 Skill 始终排在公网网页搜索之前：任务会先查阅相关 Skill 说明并调用专业接口，只有在 Skill 覆盖范围之外、或实测确认接口无对应数据时，才会动用 `web_search` 与 `web_fetch` 补充，绝不拿真假混杂的公网二手网页去顶替本该出自权威接口的一手数据。如果某项关键数据连专业 Skill 也无法获取，任务会将其如实记入 `sources/` 作为明确的“证据缺口”，绝不装作没看见悄悄略过。

此外，证据不仅靠“搜”，也靠“算”：遇到原始结构化数据时，任务会直接编写处理脚本统计核算所需指标。完成首轮归集后，任务还会全面复盘现有素材是否存在断层、多方口径是否打架、下游推演所需的背景拼图是否完备，并针对缺口定向补采。

### 三、分析与复核

进入分析阶段，所有结论都必须从手头核实过的证据一步步严密推导得出，形成闭环论证链，严禁“先拍脑袋定调子、再去材料堆里挑顺眼的论据”。报告正文会清晰剥离客观事实、各方观点、待验假说与分析推断；当现有证据同时兼容多种合理解释时，报告会将各派解释悉数摆出，坦诚说明倾向哪一种以及手头的把握有多大。行文全程对公关通稿与二手媒体叙事保持审慎怀疑，主动防范确认偏误、幸存者偏差与事后诸葛亮式的叙事谬误。

初稿成型后，会移交一名**完全隔离的独立复核者**审校：这名复核者既不继承此前的任何对话轮次，也无权读取任务私有的过程状态文件，手里只拿到这份报告初稿与你最初确认的研究目标。它会从“形式规范”与“实质逻辑”两路发起挑刺：形式上核查事实与推断是否混为一谈、引证是否扎实、结论对决策者是否有真知灼见；实质上开展对抗性审视，拷问论证链条能否自圆其说、是否漏掉了更简单的替代解释、有否倒果为因或先射箭后画靶。

独立复核者只负责提出尖锐质询，最终拍板权与文责仍在主研究者肩上：面对复核指出的每一处实质性分歧，研究者要么推翻重写站不住脚的分析段落，要么把双方的分歧点及各自依据原原本本写进报告明面，绝不和稀泥抹平争议。

### 四、交付

正式交卷前还有最后一道**成功标准逐条审计**：报告必须对你立项时确认的每一条成功标准给出明确交代——要么拿出有据可查的扎实证据予以满足，要么将其列为公开声明的未决缺口，并讲透这一缺口对最终结论的影响边界。倘若某处缺口足以动摇整场调研的核心价值、而剩余时间窗口尚允许补救，任务会立即回炉针对可获取的线索继续深挖——毕竟，交出一份关键链条残缺的半成品，与严重超时一样都意味着调研失败。

审计过关后，任务按你指定的目标格式渲染生成最终交付物，并交由一个轻量排版核验子 Agent 做最后一遍成稿巡检。报告默认使用你提问时的语种撰写，秉承乔治·奥威尔《政治与英语》中的六条简明写作准则，行文干净利落，不堆砌套话与免责声明。

### 工作状态、恢复与重启

整个运转过程中，任务会将内部推演状态实时维护在工作区的 `research-state.md` 文件中，完整记录每条成功标准的当前达成度、初步成型的候选结论及证据短板、已被证伪排除的死胡同及排除理由，以及尚待核实的信源可信度疑点。这份文件纯粹是研究者自己的工作草稿本，既不作为最终交付物外发，也严禁透露给独立复核者——因为独立复核必须从零建立自己的判断，绝不能顺着研究者的草稿思路被带偏。

这份状态文件最重要的工程价值在于**保障跨故障断点续跑**：万一中途遇到底层 Worker 实例切换或模型上下文重置，新拉起的执行进程只需读取 `research-state.md` 即可瞬间接上全部思路，无需把已经探明的方向重跑一遍。

更进一步，如果在调研中途发现最初立论的分析框架本身立错了——比如搞混了同名业务主体、曲解了核心问题，或是赖以展开的前提假设被一手数据直接推翻——任务绝不会在歪楼上勉强打补丁，而是会将校准后的新框架写入 `research-state.md`，果断废弃已被错误前提污染的半成品分析并重跑相关阶段；与此同时，此前已在 `sources/` 下沉淀好的客观原始资料笔记会悉数保留复用，只需补采新框架下新增的那部分缺口。相比硬着头皮产出一篇建立在错误前提上的废报告，局部推倒重来反而是成本最低的选择。

## Playbook：可插拔的研究方法

Playbook 是存放在任务工作区 `playbooks/` 目录下的方法论规程文件，随内置的 `deep-research` Agent Plugin 工作区模板一并下发。每份 Playbook 都在文件头部清晰标明适用场景；任务在第一阶段规划时会遍历全部可用 Playbook，按需加载与当前课题契合的方法论。

Playbook 远不止几句锦上添花的写作提示词——它可以直接接管并替换默认的分析推演、交叉验证与复核成文流程（例如下文介绍的 `ach` 就用一套严密的三轮盲审替代了默认的单轮复核）。正因把研究方法沉淀在可读可改的模板文件里，而非写死在模型权重或底层业务代码中，整套研究方法论才具备了真正的模块化替换与定制扩展能力。

目前系统开箱内置了两套经典通用方法论：

### ach：竞争假说分析

当外部信息残缺不全、多方信源相互抵牾，甚至不排除存在利益相关方刻意放烟雾弹误导时，重大的前瞻预测或根因诊断就必须在多套讲得通的解释之间正面交锋。竞争假说分析法（Analysis of Competing Hypotheses，简称 ACH）通过把这场交叉比对彻底摊在阳光下，使最终判断全链路可审计。当然，它并不能点石成金把劣质证据变可靠，也不会代替人直接算出标准答案。

如果手头只是答案唯一的简单事实查证，根本无需动用 ACH；如果已经握有干净完备的数据集与成熟的统计或因果推断模型，也应直接运行量化模型求解，而非拿定性的 ACH 去凑数。

**1. 先立齐全部假说，再下场评估证据。**
动工伊始，任务必须先把待解命题、信息截止点、预测时间窗口及结果判定口径白纸黑字写清楚，随后在深入评估具体证据之前，先把所有站得住脚的合理假说一次性全部列出来。这一先后次序至关重要，能从机制上阻止“第一个看上去挺顺眼的解释”先入为主统治整场调研。所有候选假说都必须针对同一个核心问题、处在同一解释颗粒度、覆盖同一时间跨度，并明确界定彼此之间是否严格互斥、合起来是否穷尽了可能性空间。假说数量不设死板指标；在交叉比对拿出令人信服的排除依据之前，每个候选假说都会保留在桌面上——毕竟“暂时没搜到支持证据”绝不等于“该假说已被证伪”。

**2. 所有证据统一进入可机检的假说矩阵。**
任务维护一份名为 `competing-hypotheses.yaml` 的矩阵文件，作为跨假说评估的唯一权威账本：矩阵中的每一行代表一条可对全部候选假说逐一打分的命题——它既可以是一条一手客观观察、一段媒体转述、一个按理本该出现却迟迟未见的“缺席信号”，也可以是一条显式分析假设、一段逻辑推演或一个行业基准概率（Base Rate）。每行都必须如实登记命题类别、本地来源文件路径或推演依据，并原样保留原始信源的限定措辞（例如信源写的是“据知情人士称”，入表时就绝不能偷换成既成事实）。每次更新矩阵后，任务都会运行结构校验脚本：

```bash
bun tools/ach_check.ts
```

该检查脚本专门负责揪出字段漏填、假说漏评以及不安全或失效的本地来源笔记路径；至于假说本身立得高不高明、命题真不真、引用的原文是否真能撑起那句论断，仍由模型与人工复核把关——让确定性脚本管住机械格式，把认知精力留给真正的实质判断。

**3. 看重“区分度”，而非单纯堆砌“支持票数”。**
面对矩阵中的每一行证据，ACH 追问的核心问题是：“假如某个假说为真，观察到这条现象的概率有多大？”而不是顺着假说去找“这条材料能不能替我佐证它”。评估关系严格限定使用六个标准标签：**预期（Expected）**、**相容（Consistent）**、**张力（Tension）**、**矛盾（Contradiction）**、**未知（Unknown）**与**不适用（N/A）**，且每个标签旁都须附上一句简明判定理由。阅读矩阵必须“先横向逐行比、再纵向按列看”——真正的诊断区分力完全来自同一行证据在不同假说下表现出的反差；倘若某条背景信息放在所有假说底下全都“相容”，那它哪怕本身再重要，对帮你分辨谁真谁假也几乎毫无助益。

**4. 穿透同源转载依赖，排查检索通道盲区。**
十家媒体互相洗稿转载同一篇爆料，只能算作**一个**独立信源；由同一起突发事件衍生出的多项二级指标、或基于同一份底层样本集换着花样算出的多个统计口径，同样不能重复累加充当多重独立铁证——保留相关行可以补充细节拼图，但绝不能虚增证据权重。比同源重复更隐蔽的陷阱在于**检索通道盲区**：不同假说若成立，其蛛丝马迹往往会浮现在截然不同的信息渠道里；如果印证假说 B 的关键线索本该出现在某个你压根没去检索过的渠道中，那么账面上的比对结果反映的其实只是你的搜索偏科，而非客观世界的真相。因此，任务必须为每个假说预先指明“假如它为真，迹象应当在哪些通道显露”，随后实地去那些通道检索核查，若受权限所限拿不到则诚实记为通道覆盖缺口。

**5. 审慎对待“缺席信号”，反复敲打少数关键支点。**
“没看到某件事发生”只有在以下两个前提同时成立时才构成有力的反面证据：其一，倘若该假说为真，这一信号按常理必然会留下公开可观测的痕迹；其二，我们当前的检索手段确实有充分把握捕捉到它。在此基础上，任务还会筛出真正左右最终倾向的那寥寥几根“关键支点证据”，逐一做压力测试：倘若这一条其实是假消息、断章取义、残缺不全、暗中依赖另一条脆弱前提，甚至是对手盘故意放出来的诱饵，我们的核心结论会发生怎样的逆转？最终报告给出的整体把握度，取决于假说空间的覆盖完整度、核心证据成色、信源独立性以及对关键支点的敏感度，绝不取决于凑出了多少字的材料。

**6. 三轮渐进盲审复核协议。**
启用 ACH 后，系统会用一套严密的三轮渐进披露协议替换默认的单轮复核，由**同一个独立复核者**严格按顺序走完三关——披露次序本身就是防锚定偏误的核心防线：

1. **A 轮（盲审独立重建）**：复核者此时只能拿到你的原始研究目的、确切的 ACH 命题、信息截止点以及 `sources/` 来源笔记目录的读取权，**完全看不到**假说矩阵、报告初稿及主研究者的任何倾向或草稿。它必须仅凭原始来源笔记，独立梳理出合理假说集合、最具区分力的核心证据、证据与假说的对应关系以及关键支点，给出自己的独立排序，并主动挑出潜在的缺席信号、隐含前提、同源依赖、截止点后信息穿越泄漏以及蓄意隐瞒欺骗迹象。
2. **B 轮（亮出矩阵逐行对质）**：唯有等复核者将自己那份独立重建方案白纸黑字落盘锁定之后，系统才会向它公开主研究者的 `competing-hypotheses.yaml` 矩阵。复核者随即逐项比对两份独立分析的异同，顺着来源路径回查原文引述，重点拷问每一个关键支点与分歧行，输出有理有据的缺陷清单。
3. **C 轮（终审成稿保真度）**：待 B 轮暴露的所有实质分歧全部消解或妥善注记后，主研究者才基于定稿矩阵撰写最终报告，并再次交由该复核者做最后一关核对——确认成稿是否不偏不倚地还原了各假说的相对强弱、关键区分性证据、反面证据、悬而未决的疑点，以及置信度背后的真实依据与局限。

整套设计的精髓不在于换人，而在于**严控信息揭晓的先后次序**：必须在复核者交出自己的独立答卷之后才能让它看见研究者的矩阵，否则人类与大模型一样，第一眼读到的现成结论瞬间就会变成难以挣脱的思维锚点。

**7. 绝不把定性矩阵硬凑成伪精确概率。**
定性的 ACH 矩阵本身并不产出数学意义上的后验概率：表里的六个定性标签不是条件似然值，支持行数多少更不等于概率高低。如果业务决策确实需要给出数字评估，报告必须严格区分“明确标注为主观判断的经验估计”与“真正经由贝叶斯公式推算出的概率结果”——而后者必须具备完备互斥的状态空间划分（或显式联合概率模型）、明确的先验分布、条件似然设定以及对证据相关性依赖的严谨修正。

**8. “现有证据不足以下定论”可以是诚实结论，但绝不是偷懒挡箭牌。**
承认“难分伯仲”永远是最四平八稳、最不容易背锅的表态，但也最容易吞噬掉一场原本再深挖半步就能见分晓的分析。因此当多套假说确实无法拉开差距时，报告绝不能两手一摊草草收场，而必须向读者讲透：这一僵局对实际业务决策意味着什么、万一被暂且排在后面的那个假说成真会带来多大代价，以及**未来紧盯哪一个具体的先行观测指标**就能第一时间把它们区分开来。后续跟进研究的方向也完全按“谁最能一锤定音区分假说”来排优先级，而不是盲目去攒更多无关痛痒的周边背景。

### analogical-foresight：类比预见

面对缺乏直接先例的新兴变局，历史案例往往能为前瞻推演提供宝贵的演化机制、关键变量与早期观测信号。在类比预见法中，一切分析的最小基本单元是一条完整的**迁移主张（Transfer Claim）**：

```text
历史来源案例中有据可查的运行机制 → 映射到当前目标对象的具体对应关系
  → 该机制得以跨时空成立的边界条件 → 当前目标侧可观测验证的先行信号
```

唯有把这四环链条严丝合缝地扣上，历史先例才真正构成有效论据；单凭表面特征看着眼熟、外加一段娓娓道来的历史故事，根本无法证明同一套底层机制正在今天的目标对象身上重演。

**1. 先立住当前目标的自身骨架，再去翻历史老黄历。**
动工之初，任务必须先明确界定当前目标命题、信息截止点、推演时间跨度及目标当下所处的演化阶段，搜集充足的目标一手现状，并在提及任何历史先例之前，先把目标自身的内部结构勾勒清楚：目前已观测到的客观前提、已发生的事件序列、硬约束条件与阶段性结果，初步推断的内部因果链条及各自依据，以及足以左右全局走向的关键未知数与尚未跑通的空白阶段。一旦把顺序搞反、上来先抱住一个绘声绘色的著名历史典故不放，那个历史故事就会反客为主替你裁剪现实。同样地，在做还原历史时点的复盘推演时，严禁动用截止点之后才曝光的后续演变去倒推挑选案例、修饰目标结构或评判映射优劣。

**2. 从目标的因果缺口出发，跨界广撒网寻找候选先例。**
去历史中找什么，完全由当前目标结构里“哪段因果关系还吃不准、哪个关键驱动变量缺失、哪个演化阶段尚无头绪”来牵引：跨越不同行业主体、不同历史时期与不同学科领域，去搜寻具有同构有向关系、相似博弈动力学或同等硬约束条件的历史片段。务必坚持“先广撒网生成候选池、再集中过筛评估”，防止脑海里蹦出的第一个教科书常客早早终结了搜索视野。如果发现手头攒出的候选池全都挤在同一个熟人圈子里打转、翻来覆去讲着同一套老故事，任务会专门派生一个**只准看目标抽象结构框架的隔离探路子 Agent**，责成它跳出本行业去提名跨界案例、半途折戟的失败案例以及条件相似但结局截然相反的反面案例——该子 Agent 只管贡献多样化候选名单，不参与对当前目标的定性评判。

**3. 先把历史案例本身的真实机制核实清楚。**
“A 发生之后紧接着发生了 B”只是一串时间先后顺序，远不等于因果机制。对每一个准备留用的历史案例，任务都必须先核查其史实准确性，确认支撑所谓“核心机制”的一手依据是否过硬，并严肃排查：共同的宏观外生冲击、其他替代解释、纯属巧合的偶然因素、幸存者选择效应或是后人添油加醋的叙事美化，是否同样能解释当年那一串事件？同一历史事件换个马甲的别称、局部子事件、上位统称或换汤不换药的同义复述，均不得充当多重独立印证。反倒是那些作用方向相反、照搬失败、所处阶段错位或因边界条件破裂而失效的历史案例同样极具价值——它们恰恰标出了某条机制失灵的护栏边界。

**4. 对每一条影响结论的迁移主张做六要素逐条审计。**
凡是会实质影响最终判断的类比迁移主张，都必须将以下六项要素同框摆明：来源案例中的底层机制及其史实依据、映射到当前目标的具体对应关系、双方的实质性差异（涵盖前置条件、博弈角色、作用方向、节奏时序、体量规模、波及范围与利益激励等边界条件）、使迁移成立所必须依赖的桥接假设、案例间的潜在同源依赖（如出自同一史料母本、嵌套子事件、遭遇同一场宏观浪潮冲击、跨国政策互相抄作业、处于同一制度框架或采用同一套统计口径），以及**至少一个在当前目标身上可公开追踪观测、足以证实或证伪该条迁移主张的具体信号**。剖析各方博弈主体时，必须立足该主体自身真实的目标函数、硬约束、利益激励、信息视野与决策流程来推演——“假如换作我坐在这个位置上会怎么干”纯属一厢情愿的代入投射，绝非关于对方的有效证据。最终保留在报告里的每一个历史案例，都至少要实质贡献出一条候选运行机制、一个此前忽略的隐蔽变量、一条条件演化分支、一个目标侧先行观测指标、一个有力反例或一道适用边界；凡是只能拿来凑热闹讲段历史故事的装饰性案例，一律果断剔除。

**5. 跨案例综合印证前，先剥离暗藏的同源传导。**
找到多个彼此真正独立的历史先例，确实能减轻“孤证难鸣、单靠一个故事撑全场”的脆弱性，但这依然不等于直接证明该机制眼下正在目标身上生效。在做跨案例横向归纳前，任务会严格排查表面上的“惊人相似”背后是否其实共享着同一段历史母体、同一套制度设计、同一家叙事源头、同一轮外部宏观冲击、同一条跨境传染链、政策扩散效仿或同一种测量偏差。每当总结出一条正面演化规律时，也必须主动去搜寻对应的反面案例：即历史上同样具备这些前因要素却并未引发预期结果，或虽然结局相似但走的是另一条全然不同的因果路径。更要清醒认识到：人为按图索骥挑出来的几个类比案例绝不构成统计学上的“参照类（Reference Class）”，凑齐了五六个相似案例绝不能直接换算成基准发生率、客观概率或把握度百分比。

**6. 坦然接受“未找到站得住脚的历史类比”。**
整场类比分析达到完备交付的标准是：每一条支撑结论的迁移主张都已厘清底层机制（及排他性依据）、映射关系（含方向、阶段与范围）、实质差异与同源依赖及成立前提，并给出了明确的目标侧核验指标；同时所有足以动摇结论的反例与映射失效风险均已充分交代。倘若筛遍所有候选历史片段，没有一个能严丝合缝跑通上述迁移链条，那么最专业、最负责任的结论就是如实写明“本研究未找到可严密辩护的历史类比”，绝不为了凑篇幅硬留一个听着耳熟顺耳却经不起推敲的故事。

### 两种方法可以组合

`analogical-foresight` 与 `ach` 各自攻克不同维度的认知难题，在同一场复杂调研中往往能无缝接力：先借助类比预见从历史纵深中启发提炼出几条原本容易漏掉的候选演化假说、或是点明应当去哪些冷门渠道搜寻先行指标；随后交由 ACH 将这些假说连同常规解释一并摆进矩阵，开展讲求区分度的正面交锋。在此过程中始终坚守一条底线：历史先例永远不是针对当前目标的直接观测证据，它只有化作一条前提清晰、可被目标侧现实信号证伪的迁移主张，才有资格为当下的判断背书。

### 为你的领域增加 Playbook

在企业私有部署环境中，团队完全可以将自身沉淀的内部研究规程写成专属 Playbook 放入工作区模板——例如投前尽职调查标准清单、特定垂直行业的权威信源名录、或是某类技术选型与合规评审的打分准则。只需在 Markdown 文件的头部附上 `name` 与 `description` 两个元数据字段，新建的调研任务便会在规划阶段自动发现它们，并在课题高度相关时主动载入遵循，全程无需改动底层代码或微调大模型。

## 任务运行时

任务转入后台运行后，你当前的聊天窗口完全保持自由：既可以继续和主 Agent 聊别的工作，也可以随时打开 **Console → 后台 Agent 任务**看板，直观查看任务拆解计划、实时阶段进展、Token 消耗与当前运行状态。

当调研推进到关键分岔口需要你拿主意时，任务会暂停并回到发起任务的原会话向你提问——请在**同一个会话窗口**中直接回复（此时看板显示 `waiting_on_user` 代表正在等你拍板，并非运行故障）。调研途中如果你拿到了新的内部补充材料或想微调侧重点，也随时可以在原会话里直接发给主 Agent，主 Agent 会自动将其转交进正在运行的后台任务中。

## 查看结果

后台调研跑完后，主 Agent 不会当甩手掌柜原样转发了事，而是会先自己通读审阅一遍报告：倘若报告中坦陈的某处证据缺口或局限已经实质损害了你最初交代的研究目的，主 Agent 会主动向你点明；而如果所缺的那块拼图恰好主 Agent 自己手头就掌握、或是只需向你补问一句话就能敲定，它会直接把补充信息喂回给后台任务要求继续打磨完善，绝不把一份明知不合用的半成品直接塞给你。

收到正式报告后，建议重点从以下几个维度核验成色：核心结论是否条条有据可查、时间跨度与截止点是否严守约定、客观事实与分析推断是否界限分明、以及报告是否坦诚交代了未知缺口与整体把握度。一份合格的交付报告应当完全自包含——读者无需再去翻看任何外部附件，光读报告正文就能完整掌握核心判断、支撑证据、适用边界与不确定性所在。如果你想抽查核实某条具体论据，只需在对话里让 Agent 从任务工作区的 `sources/` 目录调出对应的原始来源笔记即可；若当次调研采用了 ACH 方法，还可以随时让它展示假说矩阵中某一行具体证据的打分理由。

读完报告后若想顺着某个子方向继续深挖，直接让 Agent 基于这次后台任务的工作区接力往下做即可，无需把前因后果重新交代一遍。万一遇到任务报错终止或长时间排队停滞，可点开控制台任务详情查看具体报错原因；各任务状态的详细含义、取消操作及排障方法请参阅[后台 Agent 任务](../background-jobs/)。

具体而言，我们在架构上作出了五项关键的工程取舍：

**1. 把方法论写成外置文件，而非训进模型权重。**
CANA 采用专用智能体框架编排，MiroThinker 则通过中期训练（Mid-training）提升单步推理可靠性并将核查内化进模型自身的思维链——这两条路线都深度绑定特定模型发布。我们则选择将研究方法论彻底外置为工作区里的纯文本 Playbook 文件，由任务在规划阶段动态读取，甚至允许单份 Playbook 直接接管替换默认的复核协议。这样做的代价是执行上限受制于所选底座模型的指令遵循能力；但换来的巨大收益是底层换任何新旗舰模型都无需重新训练，且每家私有部署企业都能随手增删贴合自身业务的专属方法论——而在真实的企业级调研中，拉开差距的恰恰是行业独有的尽调方法与内部专有数据源，而非通用百科问答能力。

**2. 靠严格的上下文物理隔离保障独立复核，而非依赖模型“自我反省”。**
MiroThinker 在同一条推理轨迹内部对前序步骤开展自我审计。而在 Ankole 中，独立复核者是一个既不继承历史对话轮次、也彻底拿不到 `research-state.md` 内部状态草稿的全新隔离上下文；在 ACH 模式下，复核者甚至必须先仅凭 `sources/` 原始素材盲审重建出一整套独立评估并落盘锁定，随后才获准看到主研究者的假说矩阵，最后才审阅报告正文。背后的认知逻辑非常朴素：顺着同一条思维链做自我反省时，脑子里依然带着催生那条轨迹的同一套先验偏见；而但凡让审稿人第一眼先看到了现成结论，那个结论就会立刻变成极难摆脱的心理锚点。

**3. 将持久化扎根在受管控的任务生命周期层，而非止步于上下文外存文件。**
FS-Researcher 提出利用本地文件系统突破大模型单次上下文窗口限制，我们的 `sources/` 来源笔记与任务工作区同样沿用了这一思路。关键差异在于，Ankole 的工作区归属于一个受数据库租约栅栏保护、支持跨容器崩溃恢复、支持中途追加补充指令、并能挂起释放资源等待人类拍板的持久化后台任务——不仅上下文溢出了能接着跑，哪怕整台底层 Worker 容器重启替换了也照样接着跑。此外，我们刻意不采用机械拆分的“搜集员 + 撰稿人”双角色流水线：真正有深度的分析写作本身就是推演收敛的过程，硬把搜集分析与动笔成文割裂开来，极易把深度报告退化成对零散读书笔记的表面拼贴转述；因此我们在采集侧实行“每个信源唯一负责人”的防重规则，而把强制上下文隔离精准用在独立复核这一刀刃上。

**4. 要求历史类比必须给出一整条可证伪的迁移链。**
Analogical Deep Research（ADR）敏锐指出大模型天然倾向于按表面字面相似性而非深层机制去抓历史类比，并据此提出“机制对齐”与“跨类比交叉印证”两条准则，这与我们的实践判断高度一致。我们的 `analogical-foresight` 将其进一步固化为一条六要素缺一不可的显式迁移链，并额外加上两道硬约束：一是跨案例印证前必须先穿透排查同源依赖（防止同一场宏观冲击、同一家媒体母本或同一套统计口径造出的表面雷同冒充独立佐证）；二是每条迁移主张都必须指明当前目标身上可公开追踪的先行观测信号，让历史类比在随后的现实演进中真正接受证伪检验，而不是只停留在报告字里行间显得雄辩动听。

**5. 一切围绕决策者确认的真实研究目的闭环，而非迎合公开评测集刷分。**
学术论文天然面向标准化静态基准集调优，而我们面向的是屏幕前那位要拿这份报告去拍板做业务决策的具体读者：立项前先访谈对齐成功标准，交卷前逐条核销审计，拿不到的数据坦诚写清缺口及潜在后果，一旦缺口伤及核心目的就由主 Agent 补齐上下文打回继续深挖；在信源调度上同样坚持内部与专业数据源 Skill 优先于公网泛搜、专业接口查无所得则明确立为证据缺口。毕竟，在严肃的企业应用场景里，一份调研报告究竟能不能派上用场，归根结底取决于它用没用对权威一手数据、有没有把没查清的盲区老老实实摆在明面上——而这两件事，恰恰都不会体现在通用公开基准的打分表里。

任务工作区中的内置 Playbook 体系、渐进式盲审复核协议、研究状态恢复机制及交付标准审计流程，均由 AgentBull Ankole 团队原创设计与实现。
