在 Pod 中，**对话**（Chat）承载人与 Agent 的实时互动交流，而 **Jobs**（`/jobs`）则将空间内所有异步执行与常驻调度汇集到同一块看板上。无论是单次运行的后台 Agent 作业、多步编排的工作流，还是周期性 Cron 定时任务、稍后跟进计时器与页面专属的 Applet 自动化作业，都会按“接下来排期什么、此刻正在运行或等待你处理什么、已经完成了什么”清晰呈现。

## 打开 Jobs 看板

在 Pod 左侧边栏切换到 **主页** 标签，点击位于 **与我共享** 正上方的 **Jobs** 即可打开看板；你也可以随时按下 `⌘K`（Windows 与 Linux 为 `Ctrl+K`），在命令面板中直接跳转到 **Jobs**。

当后台存在活跃作业时，侧边栏的 **Jobs** 入口会实时显示计数徽标：

- 若 **运行中** 列存在需要你介入的卡片（例如等待你补充回答，或近期运行失败），入口会显示醒目的琥珀色计数徽标。
- 若所有活跃任务都在正常推进，入口会显示蓝色计数徽标，标明当前正在执行的项数。

看板顶部会列出此刻正在工作的 Agent，支持在 **按状态** 与 **按 Agent** 两种 **看板视图** 之间切换，并提供 **筛选** 菜单，方便按执行 Agent（或 **页面自动化**）以及卡片 **类型** 快速过滤。

## 单次作业与常驻例行卡片

Jobs 看板通过 **待运行**、**运行中**、**已完成** 三列，统一呈现两类生命周期截然不同的异步工作：

- **单次作业**（**Agent 作业** 与 **工作流**）从启动、执行直至结束，完成后归入 **已完成** 列。如果你对某个已结束的后台 Agent 作业继续追问并触发续跑，Ankole 会将整条续跑链折叠在同一张卡片上，让你始终围绕同一件事跟进全过程，而不会在看板上拆出多张零散卡片。
- **常驻例行任务**（**Cron 定时**、**自动化** 与 **稍后跟进**）代表持续生效的调度规则、Applet 触发器与延时提醒。每一条规则固定对应唯一一张常驻卡片，不会在每次触发时重复生成新卡片。当 Cron 定时任务或页面自动化触发执行时，这张卡片会从 **待运行** 移入 **运行中**（并将当次运行派生的后台 Agent 作业或工作流汇总在内）；当次执行顺利结束后，同一张卡片会自动回到 **待运行** 列，并更新 **上次运行** 与 **下次运行** 时间。

### 三列状态说明

- **待运行**：正在排队等待 Worker 槽位的单次 Agent 作业、处于空闲生效或 **已暂停** 状态的 Cron 定时任务、空闲且健康的页面自动化，以及尚未到期的 **稍后跟进** 提醒。
- **运行中**：当前正在执行的任务，以及所有需要人工关注的项目。Pod 会将需要处理的卡片固定置顶在 **运行中** 列最上方——包括处于 **等待输入**（`waiting_on_user`）状态的 Agent 作业、最近 48 小时内运行失败的作业 / 工作流 / Cron 调度，以及因凭证或权限失效而变为 **不可用** 的页面自动化；正常推进中的活跃任务则紧随其后排列。
- **已完成**：已结束的单次 Agent 作业与工作流（最多保留最近 120 条终态记录）。

如果你想按负责人查看工作负荷，可将右上角的 **看板视图** 切换为 **按 Agent**，按每个 Agent（以及独立的 **页面自动化** 分组）聚合查看其运行中、待运行和近期已完成的任务。

## 新建单次作业或周期性 Cron

在日常 **对话** 中，你随时可以让个人助理或 AI 同事启动后台任务或设置定时计划——从对话列表发起的后台 Agent 作业、工作流、Cron 调度和稍后跟进都会自动同步到 **Jobs** 看板。

如果你希望不经过聊天窗口、直接下发异步任务，点击看板右上角的 **新建作业**（或在空看板上直接点选预设模板）：

1. **单次作业**：选择已具备后台执行环境的 **Agent**，填写 **标题** 与 **执行指令**，并选择 **结果投递** 方式：
   - **仅在 Jobs 面板查看（不创建会话）**：直接在所选 Agent 的 Worker 上独立运行后台作业（`pod_job:<request_id>`），全程在 **Jobs** 面板内查看进度与结果，不在 **对话** 列表中额外创建聊天房间。
   - 选择已有对话房间：将该次运行关联到对应房间，作业完成后 Agent 会把结果摘要自动同步回该对话。
2. **周期性 Cron**：选择 **Agent**，填写 **标题** 与 **执行指令**，选用常用时间预设（如 **每个工作日 09:00**）或输入 **自定义 Cron 表达式**（5 段）与 **时区**，并指定投递会话（或使用 **Agent 私聊会话**）。默认开启 **仅在需要关注时发送会话通知**，让常规无异常的例行巡检静默完成，仅在发现异常或需要你拍板时才向对话发送提醒；勾选 **创建后立即触发首次运行** 则会在保存规则的同时立刻启动第一次执行。

### 通过 API 调用

已认证的 Pod 成员也可以通过脚本或工具调用 `/api/v2/pod/jobs` 接口读取和操作看板（请求体采用 JSON:API 动作格式 `{"data": ...}`）：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/v2/pod/jobs/summary` | 获取 `scheduledCount`、`runningCount` 与 `attentionCount` 概览计数 |
| `GET` | `/api/v2/pod/jobs` | 列出当前成员可见的看板卡片 `items` 及可调用的 `agents` |
| `POST` | `/api/v2/pod/jobs` | 创建 `one_off` 单次作业或 `cron` 定时任务（传入 `mode`、`agentUID`、`title`、`task`、`requestID`，以及可选的 `conversationID`、`repeat`、`quietSuccess`、`runNow`） |
| `GET` | `/api/v2/pod/jobs/routines/:kind/:raw_id` | 查看 `cron`、`automation_job` 或 `checkback` 卡片的完整指令、派生执行记录与运行历史 |
| `PATCH` | `/api/v2/pod/jobs/routines/:kind/:raw_id` | 操作本人创建的例行规则（`cron` 支持 `pause`、`resume`、`run`、`remove`；`checkback` 支持 `cancel`） |
| `GET` | `/api/v2/pod/jobs/executions/:kind/:run_id` | 读取 `background_agent_job` 或 `workflow` 的实时计划、工具步骤与输出日志 |
| `POST` | `/api/v2/pod/jobs/executions/:kind/:run_id/stop` | 停止排队中或运行中的 `background_agent_job` 或 `workflow` |
| `POST` | `/api/v2/pod/jobs/executions/background_agent_job/:run_id/messages` | 回答作业提问、在运行中中途引导，或对已结束作业发起续跑（传入 `requestID`、`text`） |

## 查看详情、中途引导与控制

点击任意卡片即可在看板右侧打开详情抽屉（你也可以将 `/jobs?item=<id>` 链接分享给拥有同一对话或页面访问权限的协作者）：

- **Agent 作业与工作流**：打开实时执行详情面板，展示 Agent 的执行计划、每一步工具调用以及产出摘要。当后台 Agent 作业处于 **等待输入**、正在运行，或已在工作区会话中结束时，你可以直接在面板底部输入消息回答问题、调整方向或继续追问，也可以点击 **停止** 终止正在运行的任务。若该运行关联了聊天房间，点击 **在对话中打开** 即可跳回原对话。
- **Cron 定时、稍后跟进与页面自动化**：打开例行任务检查器，查看 **下次运行**、**上次运行**、常驻 **作业指令**、**派生执行记录**（点击任一派生任务即可继续下钻查看完整步骤日志）以及历次 **运行历史**。对于由你创建的 Cron 调度与稍后跟进提醒，可直接在面板顶部执行 **立即运行**、**暂停**、**恢复**、**移除** 或 **取消**；对于页面自动化，点击 **打开 Applet** 即可前往所属页面。

## 可见性与权限边界

每位成员的 **Jobs** 看板都严格遵循其在当前 Pod 中的权限范围：

- 选择 **仅在 Jobs 面板查看** 的独立单次作业仅对发起人本人可见。
- 关联在 **对话** 列表房间中的后台作业、工作流、Cron 调度与稍后跟进提醒，对该房间的参与成员可见（页面评论串中的运行保留在各自页面内，不进入全局 **Jobs** 看板）。其中，Cron 调度和稍后跟进提醒仅允许其创建者执行暂停、恢复、立即运行或删除操作。
- **页面自动化** 展示你有权访问的页面上的活跃 Applet 自动化作业；若某项 Applet 自动化以其他成员的个人身份（`human` 授权模式）运行，则仅对该所有者本人可见。
