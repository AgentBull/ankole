后台 Agent 任务非常适合开展深度资料调研、整理大批量文件、撰写长篇文档、分析数据集或修改代码仓库等耗时工作。任务派发后在后台独立运行，不会阻塞当前聊天窗口，你仍可随时与主 Agent 继续交流其他事务。

如果你熟悉 <a href="https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/delegation.md" target="_blank" rel="noreferrer">Hermes Agent</a> 或 <a href="https://docs.openclaw.ai/subagents" target="_blank" rel="noreferrer">OpenClaw</a>，不妨将它理解成一种强持久化的子智能体（Subagent）委派机制：主 Agent 把一项边界清晰的长任务交给另一个独立的执行上下文去推进。

不同之处在于，Ankole 将每个后台任务都实现为具备完整生命周期、可跨故障断点恢复的持久化任务，而非一次性的内存调用。即便运行途中遭遇 Worker 重启、进程异常退出或整机维护，任务也能在恢复后接着中断处继续执行。

运行期间，主 Agent 仍可随时向后台任务补充最新背景或调整方向。默认情况下，后台任务会将需要拍板的疑问、异常报错与最终交付成果发回原对话；如果你不希望中途被打扰，也可以指示它全程静默运行，等方便时再主动过问结果。

## 选择 Workflow 还是后台 Agent 任务

Workflow 与后台 Agent 任务都能帮主 Agent 分担工作，但各自适用的任务形态截然不同：

| 机制 | 适用场景 |
|---|---|
| [Workflow](../workflows/) | 输入条目数量固定、各子任务彼此独立，且在启动前就能确定执行阶段。适合并行展开有界核验，并在当前回合汇总返回一份结果。 |
| 后台 Agent 任务 | 周期较长、需要持久化工作区、涉及文件读写或浏览器操作、中途可能追加新要求、需要向你追问确认，或需要可恢复的 Codex 线程。 |

简言之，Workflow 中的子任务既不能中途接收补充消息、也不能继续派生子任务或挂载持久化任务工作区；而后台 Agent 任务则能在长周期运转中持续接纳新信息并灵活调整方案。凡是需要保留连贯工作现场的长线任务，请选择后台 Agent 任务；若只是想在单轮对话里并发核查一批独立条目，请选择 Workflow。

## 让 Agent 创建后台任务

无需调用特殊命令，直接在日常聊天中说明任务目标，并明确交代“放到后台执行”即可。例如：

```text
请把这项工作作为后台 Agent 任务执行：阅读这些材料，整理一份决策备忘录，
列出依据、分歧和仍需确认的问题。完成后把结果发回这个会话。
```

建议在派发时一次性把输入资料、交付标准与期望的输出格式交代清楚；若有明确的截止时间，也请一并写明。主 Agent 会自行规划拆解步骤并提交任务，但请注意：把工作转入后台并不会赋予 Agent 任何超出平时范围的额外权限。

## 在任务运行时继续沟通

后台任务启动后，你依然可以通过主 Agent 向它补充参考资料、微调输出要求或过问当前进度：如果任务正在运行，新消息会实时转交进当前执行轮次；如果任务正挂起等待你的答复，你的回复会直接唤醒它沿着既有上下文继续推进。

你可以在布置任务时直接约定偏好的协作方式：

- **完成后通知我**：适合可自主跑完全程的长任务。派发后你可继续聊别的话题，任务完工后会自动把成果发回当前会话。
- **先在后台查清，再继续回答**：适合手头问题必须依赖深度调研结论才能作答的场景。主 Agent 会等待后台任务跑出结果后，再结合结论完成回复。
- **遇到关键取舍时问我**：适合涉及方案走向或额外成本、需要人工拍板的任务。遇到分岔口时任务会暂停并在原会话向你提问，收到答复后再接着往下跑。
- **静默执行**：适合只需在后台默默产出文件、准备稍后自行查阅的任务。只需叮嘱 Agent 完工不必主动播报，之后你可随时在原会话询问进展，或直接进 Console 查看。
- **在上一项任务的基础上继续**：直接告诉 Agent 想接着哪项历史任务往下做、新增了哪些要求。只要原任务工作区仍支持续接，系统就会完整保留此前的上下文与文件现场，无需推倒重来。

例如：

```text
请在后台比较这三份方案。完成后告诉我；如果需要扩大调研范围，
或要使用付费数据源，请先在这个会话里问我。
```

若任务需要用到特定的代码仓库、资料集或预装工具链，直接在消息里提一句即可——Agent 会自动匹配合适的工作区环境，无需你手动查找模板 ID 或调用底层接口。

## 选择模型 Provider

所有后台任务均通过 AIGateway 统一发起模型调用。创建任务时，Ankole 会锁定当下为该 Agent 配置的“后台 Agent 任务”专属模型档案；若该档案留空，则自动回退沿用该 Agent 的 `heavy` 档案。

如果希望后台任务使用 ChatGPT 订阅额度，请先按指南添加 [ChatGPT 订阅 Provider](../chatgpt-subscription-provider/)，随后前往 **Console → 智能体**，在目标 Agent 的模型档案区域找到**后台 Agent 任务**，选定该订阅 Provider 以及账号有权访问的模型、推理强度与快速模式（Fast Mode）。若池中绑定了多个订阅账号，Provider 凭据池会自动完成账号挑选与轮换。

## 在 Console 中查看任务

打开 Console 的**后台 Agent 任务**页面，任务看板按状态分为“待处理”、“进行中”与“已结束”三栏。点开任意任务卡片，即可查看原始需求指令、当前执行计划、历轮运行明细、Token 消耗统计以及最终产出或报错详情。

| 状态 | 含义 | 处理建议 |
|---|---|---|
| `queued` | 任务已入队，正在等待该 Agent 的 Worker 就绪或腾出空闲并发槽位 | 通常稍候即可；若长时间停滞不前，请前往 **Console → 工作节点**检查该 Agent 的 Worker 状态 |
| `running` | 正在后台执行 | 可点开任务详情查看拆解计划与实时进展 |
| `waiting_on_user` | 暂停等待主 Agent 或你的答复 | 主 Agent 能自行解答的会直接回复；若主 Agent 转而向你提问，请回到发起该任务的原会话作答 |
| `succeeded` | 已顺利完成 | 查看交付结果；若此前要求了完工播报，可核对原会话是否已收到通知 |
| `failed` | 执行失败 | 查看报错原因；修正相关配置或补充输入材料后，让 Agent 重新发起新任务 |
| `stopped` | 已人工取消 | 任务已终止，不再继续推进 |

看到 `waiting_on_user` 状态不必担心，它并不是运行报错：后台任务遇到疑问时，主 Agent 若掌握信息会先行代答，只有确实需要你拍板确认或补充外部资料时才会转问你。等待期间任务会主动让出并发运行槽位，收到回复后即刻恢复。当 Agent 向你提问时，**请务必在发起该任务的原会话中直接回复**——如果另开一个无关的新窗口作答，后台任务将无法把你的回复关联到待决问题上。

## 取消任务

如需终止任务，点开任务详情并选择**取消**即可。若当前轮次已在执行途中，可能需要数秒钟收尾停机，因此状态未必瞬间变为 `stopped`。取消任务不会删除工作区中已生成的文件与过往运行记录。

如果你只是想微调产出要求或补充背景，直接在原会话里告诉 Agent 即可，无需取消重来；只有在任务方向完全跑偏、白白消耗配额或需求本身已作废时，才需要手动取消。

## 常见问题

- **任务长时间停在 `queued`**：请检查该 Agent 的 Worker 实例是否已正常就绪，并确认同一 Agent 名下是否已有其他后台任务占满了并发槽位上限（`background_agent_jobs.max_running_per_agent`）。
- **任务刚启动就立即变为 `failed`**：请检查该 Agent 已保存的“后台 Agent 任务”模型档案配置是否完整，以及所选 Provider 的凭据池是否有可用密钥。
- **状态显示 `waiting_on_user`，但聊天窗口没收到提问、主 Agent 也没代答**：请检查原会话关联的信号路由规则及外部聊天渠道连接是否正常、消息能否成功投递。
- **任务已显示 `succeeded`，但没有发回聊天窗口**：先确认派发任务时是否指定了静默模式；若并非静默执行，点开任务详情确认结果已正常生成后，再排查原会话的信号路由规则。
- **修改了模型档案，但正在跑的任务没有切换模型**：后台任务的 Provider 与模型绑定在首次准入执行（Admission）时即已锁定，修改档案仅对尚未准入执行的新任务生效。
