**Ankole 是一套自托管的 AgentOS，让你能够在私有服务器上组建真正的 AI 同事团队。** 它们领的是目标，不是指令：在团队群里接揽任务，自主拆解、执行并交付，最终凭成果说话。

这种差异可以从一个典型场景说起：两位同事在投研群里讨论估值口径，敲定“周期股看 7 年分位，不用 3 年”——过程中没有任何人 @ AI。三天后，另一位同事在群里请它出一份有色板块的估值报告，它交出的报告便自动采用了 7 年分位。只存在于私人对话框里的传统 AI 助手无法做到这一点：因为当时它根本不在场。

## 它和助手的区别

差异在于定位与权责，而非单纯的模型能力。传统助手回答的问题是“它怎么帮我”；AI 同事回答的则是“这段工作默认由谁负责”。具体到实际使用中，有五处根本不同：

- **它属于工作场域，不属于带它进群的人。** 记忆归属于团队频道，权限按场景授予，行为对所有人公开透明，结论沉淀为团队的公共事实——而这一切都保存在你自己的服务器上，而非厂商的公有云租户里。
- **岗位是权责单元，而非简单的技能组合。** 会做不等于该做，装上技能也不等于能承担责任。Ankole 提供的是将 AI 能力转化为正式岗位所需的结构支撑：独立身份、组织授权、审计轨迹、升级路径与考核口径。
- **它贯穿完整的业务闭环，而非仅局限于局部环节。** 感知现场、判断轻重、形成承诺、推进行动、追踪结果、处理例外、对组织产生交代——SaaS 系统记录结果，RPA 自动化执行动作，问答机器人处理咨询入口，而 Ankole 负责接管整个闭环。
- **它不只记录秩序，更能生成秩序。** 群内通过自然语言形成的承诺、风险、口径与截止日期，会当场转化为可追踪、可执行、可退役的组织规则。开头提到的估值口径就是这样纳入账本的，全程无需任何人专门给它下达配置指令。
- **日常闭环默认由它负责，人类在关键节点把关。** 请示、审批、异常干预与问责时人类在场；交付物、决策过程与已提交的操作均记录在持久账本中，交付产出天生具备“事后可量化评估”的特性。

生成的秩序靠记忆维护。多数 Agent 的记忆只是只增不减的日志：新旧规则无差别堆叠，缺乏时间线与覆盖关系。Ankole 的记忆则具备裁决机制——新规则生效时，旧口径及其生效周期同步退役；矛盾的结论依据时间、来源与置信度分出主次；对于预测过的事项，在真实结果公布后还会自动回头对账复盘。

## 一个实例包含哪些部件

在阅读后续文档时，你会频繁遇到以下核心概念：

| 部件 | 说明 | 详见 |
|---|---|---|
| **Agent** | 具备明确使命、授权、工具、记忆与对外身份的工作主体。使命与交付标准通过配置文件定义，可随时调整。单套部署支持运行多个 Agent。 | [Agent](../agents/) |
| **会话（Session）** | 长时执行单元，也是上下文、工作区状态、动态干预（插话）、取消与恢复的交汇点。 | [Actor 运行时](../actor-runtime/) |
| **信号路由规则** | 把指定 Agent 连接到某个信号源，并定义它在该场景中的行为边界。 | [信号路由规则](../signal-bindings/) |
| **后台任务** | 从会话派发出的长时任务（可连续运行数小时），完成后自动回到原频道提交交付物。 | [Background Agent Jobs](../background-agent-jobs/) |
| **记忆** | 包含频道规则与长程记忆。后者构建了一个动态世界模型：基于经验做出预测，再由真实结果予以校正。 | [记忆](../memory/)、[Brain](../brain/) |
| **技能** | 针对特定工作的标准作业程序（SOP）。Agent 可主动提出改进方案，经人工批准后在下一会话生效。 | [Skills](../skills/) |
| **主体（Principal）** | 人员、Agent 和系统服务在 Ankole 中使用统一的身份，权限与审计由运行时统一管控。 | [主体与 AuthZ](../principal-authz/) |
| **Agent Computer Worker** | 执行基座：负责运行 LLM 循环、工具调用、文件管理、终端状态与流式输出。 | [Agent Computer Worker](../agent-computer-worker/) |

此外，Agent 还可以通过 [Deep Research](../deep-research-job/) 完成长时间、多来源调研，也可以通过[浏览器自动化](../browser-automation/)操作真实网页。

## 它能胜任哪些岗位

能够远程完成、具备明确交付物、事后可通过数据评估——符合这三项特征的任务，才足以构成一个真正的岗位。

例如，二级市场研究员按事后复盘的预测命中率考核，云成本优化师按单位业务量的云支出降幅考核，药品注册专员按申报一次通过率与发补轮次考核。它们的共同点不在于“回答某个提问”，而在于**胜任特定岗位、基于全量上下文独立履职，并最终以成果说话**。

## 当前状态

Ankole 是一套完整且可自托管的 AgentOS，已在生产环境实际运行，但目前仍处于早期阶段。系统的控制面、Agent Computer Worker、内核及运维控制台已实现端到端可用。当前暂未提供公共 API 的向下兼容承诺，版本迭代中可能包含破坏性变更（Breaking Changes）。
