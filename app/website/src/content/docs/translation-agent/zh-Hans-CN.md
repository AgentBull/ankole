一个翻译 agent 拿一种语言的内容，产出另一种语言的忠实呈现——保留含义、技术术语和源文本的语气。本指南是那个 agent 的实际形态，从设置到翻译循环。

先把决定性的性质说清楚：agent **忠实翻译，不改写**。它保留源文本的结构，保留技术术语和专有名词的公认形态，匹配源文本的语体（正式、随意、技术）。翻译是呈现，不是改编——除非人设明确说要改编。

## 需要什么

- **绑定 `primary` profile**——翻译质量取决于模型的多语言能力。
- **一个 signal binding** 到翻译到达和发出的频道。
- **可交付的源内容**——粘贴的文本、上传的文件、或经 `web_fetch` 抓取的 URL。

## 工作流

1. **源内容到达**——频道消息、上传文档或 URL。
2. **agent 识别源语言**——或从请求接受（"把这个从英文翻成日文"）。
3. **agent 翻译**——保留结构（段落、列表、标题）、保留技术术语和专有名词的目标语言公认形态、匹配语气。
4. **agent 交付**——把翻译发到频道，或写成文件。

## 人设控制什么

- **语言对**——"在英文和中文、英文和日文之间翻译。"命名 agent 处理的对。
- **技术术语策略**——"代码标识符、API 名和产品名保留英文；翻译周围的散文。"这是技术内容最常见的策略。
- **语气匹配**——"匹配源文本语气。不要把随意的文本正式化或把正式的文本随意化。"
- **格式保留**——"保留 Markdown 格式、代码块和链接语法。"
- **术语表**——"对领域术语使用项目的术语表（存为 Brain 知识条目）。"

## 术语表

为跨会话的一致翻译，维护一份**术语表**作为 Brain 知识条目：

- 领域专属术语及其公认的翻译
- 不应翻译的产品名
- 缩写及其在两种语言中的展开

agent 在翻译时召回术语表，所以"deployment"总是变成同一个词，不是每次不同的同义词。

## 一个完整示例

设置一个在英文和中文之间翻译产品文档的 agent：

1. 创建 agent，绑 `primary`/`light`/`heavy` + `embedding`（术语表召回）。
2. 撰写 `MISSION.md`："在英文和简体中文之间翻译产品文档。代码标识符、API 名和产品名保留英文。匹配源文本语气。保留 Markdown 格式。对领域术语使用 Brain 里的项目术语表。"
3. 策展 Brain 知识：术语表条目（领域术语+公认翻译）。
4. 在频道里粘贴或上传源文档。
5. agent 翻译、保留结构和术语、发结果。

## 本指南不是什么

它不是本地化服务——agent 翻译文本；它不改编日期、货币、法律声明或 UI 布局。它不是实时口译——agent 处理文档，不处理实时对话（尽管被问时可以翻译频道消息）。它也不是高风险翻译人工复核的替代——法律、医疗或品牌关键内容仍需人工过一遍。
