Ankole には、用途に応じて使い分けられる 2 種類のスケジューリングツールが用意されています。

- **Cron：** 毎朝のブリーフィング、週次のプロジェクト確認、30 分おきのステータスチェックなど、定期的に繰り返す作業を管理します。
- **Checkback：** 現在の会話を指定時間後に一度だけ起こし、Agent が少し時間を置いてから作業を再開できるようにします。

## Cron

Cron は繰り返し実行する作業を管理します。カレンダー上の時刻を指定することも、基準時刻（anchor）から一定間隔で繰り返すこともできます。

### Agent に作成してもらう

通常は Console を開く必要はありません。結果を受け取りたいチャット会話の中で、「何をするか」「いつ実行するか」「どのタイムゾーンを使うか」をそのまま Agent に伝えてください。

依頼を受けた Agent がスケジュールを作成し、以降の実行結果をその会話へ届けます。

```text
Create a schedule for every workday at 09:00. Summarize yesterday's progress,
current blockers, and today's follow-up items, then post the result in this
conversation. Use Asia/Shanghai. Run it once now so I can confirm the content
and delivery location.
```

<DocsKnowledgeNote label="💡 ご存知ですか？">Agent を処理先とする Cron ルールは専用 Session で実行し、設定した会話へ最終結果を配信します。</DocsKnowledgeNote>

### 応用: Console で schedule を作成する

Console からスケジュールを作成する前に、配信先のチャット会話で一度 Agent とやり取りを行い、ルーティングルール経由でメッセージを送受信できることを確認しておいてください。

1. Console で **Schedules** を開きます。
2. 対象の Agent と、スケジュールを管理する Session を選択します。一覧に目的の Session が表示されない場合は、Session ID を入力します。
3. **Cron** タブを開き、**New schedule** を選択します。
4. 配信に使用するルーティングルールを選び、分かりやすいスケジュール名を入力します。
5. 必要な背景情報を含むタスクを入力し、スケジュールの種類と実行タイミングを指定します。
6. 配信先の会話を選ぶか、Ankole の Conversation ID を入力します。外部チャットで特定のトピックやスレッドに返信する場合だけ、Provider のスレッド ID も入力します。
7. スケジュールを保存したら **Run now** を実行し、本番の定期実行が始まる前にタスク内容と配信先が意図どおりか確認します。

### 時刻ルールの選択

**Cron（式）** は、毎営業日の 09:00 のようにカレンダー上の時刻で動かす作業に適しています。標準の 5 フィールド形式、または先頭に秒を加えた 6 フィールド形式で指定できます。タイムゾーンには `UTC+8` のような曖昧な表記ではなく、`Asia/Shanghai` のような IANA タイムゾーン名を指定してください。

```text
0 9 * * 1-5
```

この例は月曜から金曜の 09:00 を表します。実行時刻はブラウザーや Worker のローカル時刻ではなく、スケジュールに保存されたタイムゾーンにもとづいて評価されます。

**Every（間隔）** は、30 分ごとのヘルスチェックのように一定間隔で繰り返す作業に適しています。間隔を入力し、秒・分・時間・日の単位を選びます。基準時刻（anchor）を起点として実行グリッドが決まります。カレンダー時刻に意味を持たないポーリング処理にはこちらを使ってください。

### タスクと配信

Agent を処理先とする Cron ルールは、作成元の会話とは別の専用 Session で実行されます。作成元 Session の履歴は引き継がないため、各回に必要な背景情報を含め、タスク単独で作業内容が分かるように記述してください。Agent の役割や恒久的な指針は読み込まれるため、`AGENTS.md` や文体の指示を重複して記載する必要はありません。

配信先の会話を選ぶか、Ankole の Conversation ID を入力します。外部チャットでは対応するルーティングルールも選び、同じトピックやスレッドに返信する場合だけ Provider のスレッド ID を追加してください。

初回セットアップ後は必ず **Run now** を実行し、タスク内容自体は正しいのに意図しない場所へ投稿されてしまうといった設定ミスを防いでください。

### 一時停止、再開、削除

- **Pause：** 設定を残したまま定期実行だけを一時停止します。連休中やメンテナンス時の休止に便利です。
- **Resume：** 一時停止を解除し、次回の実行予定時刻を再計算します。
- **Run now：** 元のスケジュール設定を変更せずに、即時実行を 1 回だけ追加します。
- **Remove：** スケジュールを完全に削除します。後から再開する可能性がある場合は Pause を使ってください。

スケジュール詳細画面を開くと、直近の実行履歴を確認できます。結果が届かない場合は、まずスケジュール自体が発火したかを確認し、続いて Agent の実行状況とメッセージ配信結果を確認してください。

## Checkback

Checkback は、Agent が作業の途中で登録する一度かぎりの遅延フォローアップです（例：「30 分後にデプロイ結果を再確認する」）。デフォルトでは、指定時刻になると Ankole が同じ会話を起こし、Agent はそれまでのコンテキストを保ったまま作業を再開できます。

Agent は具体的なフォローアップが必要なときに Checkback を 1 件予約します。期限が到来するとコントロールプレーンが一度だけ起動イベントを配信し、待機中に確認目的のモデル Turn を繰り返す必要はありません。

チャットから依頼する際は、「いつ戻ってきてほしいか」「何を確認するか」「どういう場合に通知するか」を伝えてください。たとえば次のように指示します。

```text
Check this deployment again in 30 minutes.
Tell me if it failed, became blocked, or changed state. Stay silent if nothing changed.
```

Console の **Checkbacks** タブでは、選択した会話でまだ発火していないリマインダーの一覧を確認できます。予定時刻、理由、ルーティングルールを確認できるほか、不要になったリマインダーを手動でキャンセルすることも可能です。

## Applet Job のスケジュール

定型処理は Applet Action として公開し、自動化パネルで Job とそのスケジュールを作成します。Agent セッション、タスクプロンプト、チャット送信先は不要です。Cron、一定間隔、日時指定を選び、タイムゾーンと Action に渡す JSON を設定します。

編集、一時停止、再開、即時実行、削除に対応し、発火履歴から Run の結果、失敗、入力の統合状態を確認できます。Action は `ctx.signal.data` と永続化される `ctx.state` を使います。個人用スケジュールは Job 所有者、チーム用はページの編集権限に従います。

Agent が作成した Cron や Checkback も、関連付けによって Applet Job に配信できます。毎回判断や会話が必要なら Agent を処理先にしてください。[Automation Jobs](../automation-jobs/)と[Worker CLI](../cli-capabilities/)を参照してください。

## よくある問題

- **スケジュールが発火しない：** スケジュールが有効（Active）になっているか、および Cron 式、タイムゾーン、次回実行予定時刻が正しいかを確認してください。
- **発火したのに結果が届かない：** 実行履歴を開き、ルーティングルール、配信先チャネル、対象 Agent が利用可能な状態にあるかを確認してください。
- **実行時刻が毎回決まった時間だけずれる：** 正しい IANA タイムゾーンが設定されているか、およびインスタンス側のタイムゾーン設定を確認してください。
- **別の会話に結果が投稿される：** 配信先の会話または Provider のスレッド ID を修正し、**Run now** で配信先を確かめてください。
- **Checkback で Agent が戻ってこない：** **Checkbacks** タブに該当リマインダーが残っているか、予定時刻や元の会話のルーティングルールに問題がないかを確認してください。

詳しい失敗レコードの見方や復旧手順については、[スケジュールのトラブルシューティング](../faq/) を参照してください。
