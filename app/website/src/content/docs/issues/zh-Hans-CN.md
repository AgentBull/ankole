Issue 是你交给 Agent 的一项后台工作。它有标题、描述和一个负责执行的 Agent。每个 Issue 都有自己的对话，Agent 的回复、提问，以及它发起的 Background Agent Job 和 Workflow 都显示在这里，和 Chat 里的呈现方式一样。

## 打开 Work

在 Pod 侧边栏选择 **Work**。这个标签相当于后台工作的收件箱：标签上的数字是等你回答或等你验收的 Issue 数，列表按进展列出你未完成的 Issue，这两类排在最前。点 **看板** 进入 Work 页面。页面可以用看板或列表查看 Issue，下方是定时任务。Issue 带标签时，在看板上方点一个标签，就只显示带这个标签的 Issue。

Work 只包含你 Chat 列表里的对话。页面评论和外部 IM 里的对话不在 Work 里，它们的执行和定时任务要到各自的对话里查看。

看板有五列：

- **待开始**：Agent 还没有收到这项工作。
- **进行中**：Agent 正在工作，或者它发起的后台执行还在运行。
- **等你处理**：Agent 提了问题，或者在等你批准。
- **待验收**：Agent 已经停下，结果等你查看。
- **已完成**：你已经验收。

**进行中** 和 **等你处理** 反映的是 Agent 的真实状态，卡片会自己在这两列之间移动。卡片上显示 Agent 正在运行的执行、已执行的步数和用时，点 **停止** 可以停掉它。

## 新建 Issue

1. 选择 **新建 Issue**。
2. 填写标题，并描述要做什么。
3. 需要的话加上标签，多个标签用逗号分隔。
4. 选择 Agent：你的个人助理，或者一位 AI 同事。
5. 选择 **立即开始** 或 **稍后开始**，然后选择 **创建 Issue**。

选择 **立即开始** 时，标题和描述会作为你在这个 Issue 的对话里的第一条消息发给 Agent，Agent 随即开始工作。选择 **稍后开始** 时，Issue 停在 **待开始**，你还可以修改描述；点 **开始**，或者把卡片拖到 **进行中**，它才开始。

## 让 Issue 按计划重复

在 **重复** 里选 **按计划重复**，再设定运行时间，比如每周一 9:00。每次运行都会把这个 Issue 的描述发给 Agent，结果发在 Issue 的对话里，所以每次运行后 Issue 都会回到 **待验收**，上一次验收过也一样。选 **立即开始** 时马上运行第一次；选 **稍后开始** 时等到第一个计划时间才运行。

卡片和面板上会显示下次运行的时间。在面板里或看板下方的 **定时** 里，可以暂停、恢复或立即运行。也可以在 Issue 的对话里请 Agent 修改计划。

## 拆成子 Issue

打开一个 Issue，在面板里选 **新建子 Issue**。子 Issue 是一个独立的 Issue，有自己的 Agent 和对话；它的卡片上写着属于哪个 Issue，父 Issue 的卡片上显示子 Issue 的完成数。你验收一个子 Issue 后，父 Issue 的 Agent 会在父 Issue 的对话里收到子 Issue 的结果（以你的名义发出），接着做父 Issue 的工作。

## 交给 Squad 协作

Agent 选的是你的个人助理时，可以在 **Squad** 里勾选几位 AI 同事。描述里会点名这些同事，助理会把工作分给他们。同事在做自己那部分时，Issue 保持在 **进行中**。

## 跟进和验收

点一张卡片，它会在看板旁边打开。**待开始** 的卡片打开的是 Issue 的标题、Agent 和描述，描述还可以修改。其他卡片打开的是 Issue 的对话，你可以在这里补充说明、回答问题、给正在运行的执行追加指示，或者停掉它。面板标题下方一行显示 Issue 的标签：点 **添加标签** 加一个，点标签上的 × 去掉它。

Agent 停下后，Issue 进入 **待验收**。点 **完成**，或者把卡片拖到 **已完成**，就是验收。点 **重新打开** 可以把已完成的 Issue 放回 **待验收**；还没开始就被关闭的 Issue 会带着描述回到 **待开始**。如果 Agent 在已完成的 Issue 的对话里又发起了后台工作，Issue 会自动重新打开。

## 谁能看到 Issue

Issue 对话里的人都能看到它。想让同事看到，就把同事邀请进这个对话。交给个人助理的 Issue 只有你自己能看到。

对话里只有你一个人时，你发的每条消息 Agent 都会回复。同事加入后，你的消息默认仍然发给这个 Issue 的 Agent。如果只想和同事说话、让 Agent 自己决定要不要回，把输入框下方的收件人改成 **允许主动回应的 Agent**。

## 从 Chat 发起的后台工作

你 Chat 列表里的对话，只要 Agent 在里面发起了第一个 Background Agent Job 或 Workflow，就会成为 Issue，不论是和个人助理的对话、和 AI 同事的私聊，还是群聊。不需要你做任何操作，这项工作就出现在看板上，一直留到你验收。同一个对话里再发起新的 Background Agent Job，它会重新打开。

## 定时任务

看板下方的 **定时** 列出 Agent 在你 Chat 列表的对话里维护的周期任务和待回访事项，以及下次运行的时间。点一行可以打开管理它的对话。以你的名义运行的周期任务（比如按计划重复的 Issue）旁边有按钮，可以暂停或恢复、立即运行、删除。其他定时任务要新建或修改，在对应的对话里告诉 Agent 即可。
