Issue は、Agent に任せるバックグラウンドの作業です。タイトルと説明、そして作業を担当する Agent が 1 つあります。Issue ごとに専用の会話があり、Agent の返信や質問、Agent が開始した Background Agent Job と Workflow が、Chat と同じ形でそこに表示されます。

## ボードを開く

**未着手** または **進行中** の項目があるあいだは、Pod のサイドバーの **ホーム** タブで、**自分と共有** のすぐ上に **バックグラウンド Agent タスク** が表示されます。これを選ぶとボードが開き、その下にはスケジュールされたタスクが表示されます。

ボードに表示されるのは、Chat の一覧にある会話です。ページのコメントと外部チャットチャネルの会話はボードには表示されないため、そこでの実行やスケジュールはそれぞれの会話で確認してください。

ボードには 5 つの列があります。

- **未着手**：Agent はまだ依頼を受け取っていません。
- **進行中**：Agent が作業しているか、Agent が開始したバックグラウンド実行が動いています。
- **対応待ち**：Agent が質問しているか、あなたの承認を待っています。
- **確認待ち**：Agent の作業が止まり、結果があなたの確認を待っています。
- **完了**：あなたが結果を受け取りました。

**進行中** と **対応待ち** は Agent の実際の状態を表すので、カードはこの 2 つの列の間を自動で移動します。カードの 1 行目には、最新の実行中の作業がどこまで進んだかと、いまの状態が表示されます。2 行目はタイトル、3 行目は Agent と最後に動きがあった時刻です。1 行目の **+** は、そのカードにほかの実行中の作業がいくつあるかを示します。カードにポインターを重ねると **停止** ボタンが表示されます。ボードの上には作業中の Agent が表示され、**フィルター** を使うと選んだ Agent のカードだけを表示できます。

## Issue を作成する

Agent に作業を任せるときは、Chat でパーソナルアシスタントか AI 同僚に依頼します。Agent がその作業を Background Agent Job または Workflow として引き受けると、その会話が Issue になり、ボードに表示されます。詳しくは、後述の **Chat から始まったバックグラウンド作業** を参照してください。

スクリプトなどから Issue を直接作成するときは、`POST /api/v2/pod/issues` に `title` と、何をしてほしいかを書いた `description`、作業を担当する Agent の `agentUID` を送ります。Agent にはパーソナルアシスタントか AI 同僚を指定できます。タイトルと説明は Issue の会話の最初のメッセージとして Agent に届き、Agent が作業を始めます。`start: false` を付けると、Issue は **未着手** のまま待ちます。その間は説明を編集でき、**開始** を選ぶか、カードを **進行中** にドラッグすると作業が始まります。

Issue を整理したいときは、作成時に `labels` でラベルを 10 個まで付けられます。ラベルは `PATCH /api/v2/pod/issues/:id` でいつでも付け替えられ、`GET /api/v2/pod/issues` の一覧で Issue ごとに確認できます。

## Issue をスケジュールで繰り返す

Issue を繰り返すには、`repeat` を付けて作成します。`repeat` には、5 つのフィールドからなる cron 式を `expression` に（毎週月曜 9:00 なら `0 9 * * 1`）、あなたのタイムゾーンを `timezone` に指定します。実行のたびに Issue の依頼が Agent に届き、結果は Issue の会話に返ってきます。そのため、前回の結果を受け取ったあとでも、実行するたびに Issue は **確認待ち** に戻ります。最初の実行は作成するとすぐに始まりますが、`start: false` を付けて作成した場合は最初の予定時刻まで待ちます。

次回の実行時刻は、ボードの下の **スケジュール** に表示されます。スケジュールを一時停止、再開、削除したり、今すぐ実行したりするには、Issue の会話で Agent に頼むか、`PATCH /api/v2/pod/issues/scheduled/:id` に `change`（`pause`、`resume`、`remove`、`run` のいずれか）を送ります。スケジュールの ID は、`GET /api/v2/pod/issues` が返す Issue の `repeat.id` です。

## サブ Issue に分ける

サブ Issue は、より大きな Issue の一部を受け持つ独立した Issue で、専用の Agent と会話を持ちます。作成するには、`POST /api/v2/pod/issues` の `parentID` に親 Issue の ID を指定します。この ID は親 Issue の会話の ID で、あなたがその会話を開けることが条件です。`GET /api/v2/pod/issues` の結果では、サブ Issue には親 Issue が示され、親 Issue にはサブ Issue の数と完了数が示されます。サブ Issue を完了にすると、親 Issue の Agent が親の会話でその結果をあなたからのメッセージとして受け取り、親の作業を続けます。

## Squad で作業を分担する

Squad は、パーソナルアシスタントが Issue の作業を分担する AI 同僚のグループです。Issue に Squad を付けるには、Agent をパーソナルアシスタントにして作成し、`squadUIDs` に同僚の UID を並べます。依頼にはその同僚の名前が入り、アシスタントが同僚と作業を分担します。同僚が担当分を進めている間、Issue は **進行中** のままです。パーソナルアシスタントとの会話でも、同じように同僚に作業を任せられます。メッセージで同僚をメンションすると、アシスタントがその同僚に作業を依頼します。

## 進み具合を確認して結果を受け取る

カードを選ぶと、ボードの横に開きます。**未着手** のカードでは、Issue のタイトルと Agent、依頼の内容が表示され、内容はまだ編集できます。**開始** を選ぶか、カードを **進行中** にドラッグすると、タイトルと説明が Issue の会話の最初のメッセージとして Agent に届きます。それ以外のカードでは、会話でタスクを開いたときと同じように、バックグラウンド実行の詳細（実行計画、ステップ、結果）が開きます。そこで実行からの質問に答えたり、指示を追加したり、実行を止めたりでき、**チャットで開く** を選ぶと Issue の会話に移動します。

Agent の作業が止まると、Issue は **確認待ち** に移ります。**完了にする** を選ぶか、カードを **完了** にドラッグすると、結果を受け取ったことになります。**再開** を選ぶと、完了した Issue が **確認待ち** に戻ります。開始する前に完了にした Issue は、依頼の内容を保ったまま **未着手** に戻ります。完了した Issue の会話で Agent が新しいバックグラウンド作業を始めた場合、Issue は自動的に再開されます。

## Issue を見られる人

Issue の会話に参加している人が、その Issue を見られます。同僚と共有したいときは、会話に招待してください。パーソナルアシスタントに任せた Issue は、あなただけが見られます。

会話にいるのがあなただけの間は、あなたが書いたすべてのメッセージに Agent が返信します。同僚が参加したあとも、あなたのメッセージは既定で Issue の Agent 宛てになります。同僚だけに向けて書き、返信するかどうかを Agent に任せたいときは、入力欄の下の宛先を **応答可能な Agent** に変更してください。

## Chat から始まったバックグラウンド作業

Chat の一覧にある会話では、Agent が最初の Background Agent Job または Workflow を開始すると、その会話が Issue になります。パーソナルアシスタントとの会話でも、AI 同僚との 1 対 1 の会話でも、グループでも同じです。あなたが何もしなくてもその作業はボードに表示され、あなたが完了にするまで残ります。同じ会話で新しい Background Agent Job が始まると、Issue は再開されます。

## スケジュールされたタスク

ボードの下の **スケジュール** には、Agent が Chat の一覧にある会話で管理している定期実行と、後で確認する予定が、次回の実行時刻とともに並びます。一時停止しているものには **一時停止中** と表示されます。行を選ぶとそれを管理している会話が開くので、スケジュールの作成や変更はその会話で Agent に依頼してください。繰り返す Issue のように、あなたの権限で実行される定期実行は、`PATCH /api/v2/pod/issues/scheduled/:id` で一時停止、再開、今すぐ実行、削除することもできます。行の ID は `GET /api/v2/pod/issues/scheduled` で確認できます。
