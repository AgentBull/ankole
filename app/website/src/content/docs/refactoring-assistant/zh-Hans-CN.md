一个重构助手读代码库、识别重构机会（重复逻辑、死代码、过于复杂的函数）、提议变更、跑测试验证不破坏、开 draft PR 供人复核。本指南是那个 agent 的实际形态。

先把决定性的性质说清楚：agent **提议和验证，不合并**。它识别改什么、写重构后的代码、证明测试仍通过。人复核 diff 并决定是否合并。价值在于机械工作——找重复、应用模式、跑测试——不在于架构判断。

## 需要什么

- **WorkerEnv 里的 git 凭证**（`GIT_TOKEN`）。见 [Git 集成](../git-integration/)。
- **绑定 `primary` 和 `coding` profile**——重构需要既读复杂代码又写正确替换。
- **一个 signal binding** 到提议发帖的频道。
- **repo 从 worker 可达**，带 agent 可跑的测试套件。

## 工作流

1. **重构任务到达**——"重构支付模块减少重复"、或 agent 按调度扫描机会。
2. **agent 读代码**——识别模式：重复逻辑、一个函数做太多事、死代码、或错过的抽象。
3. **agent 提议变更**——写重构后版本，保持公共接口不变。
4. **agent 跑测试**——`bun test`、`pytest`、`mix test`、或 repo 声明的任何命令。提议发出前测试必须通过。
5. **agent 开 draft PR**——或发 diff 供复核，附变更了什么和为什么的摘要。

## 人设控制什么

- **重构什么**——"目标超过 50 行的函数、出现 3+ 次的重复块、和未使用导出标识的死代码。"
- **不碰什么**——"不改公共 API 签名。不改测试断言。不重命名导出标识。"
- **证明**——"提议前始终跑完整测试套件。任何测试失败则还原并报告。"
- **风格**——"匹配现有代码风格。用项目的 ESLint/Prettier 配置。"

## 安全边界

重构 agent 强大且可能有破坏性。人设必须执行：

- **测试是门**——测试不过不出提议。若测试套件不完整（重构代码无覆盖），agent 应说明并提议先加测试。
- **公共接口稳定**——重构改实现不改契约。agent 需改公共 API 时升级给人而非自作主张。
- **小而可复核的 diff**——"一个 PR 一个重构。不批量不相关的变更。"

## 一个完整示例

为 TypeScript repo 设置重构助手：

1. 在 WorkerEnv 存 `GIT_TOKEN`。
2. 创建 agent，绑 `primary`/`heavy`/`coding`。
3. 撰写 `MISSION.md`："重构代码库以提升清晰度和减少重复。目标：>50 行的函数、出现 3+ 次的重复块。保持公共接口不变。提议前跑 `bun test`。一个 PR 一个重构。匹配现有风格。测试失败则还原并报告。"
4. 在频道里："重构 `src/payments/` 里的 `refund` 函数——80 行、有重复验证逻辑。"
5. agent 读、重构、跑测试、开带 diff 的 draft PR。

## 委派大型重构

跨多文件的大型重构，把机械工作委派给后台任务（见[委派模式](../delegate-patterns/)）。任务跨文件应用模式；agent 复核结果、跑测试、任务完成时开 PR。

## 本指南不是什么

它不是自动合并器——agent 提议和验证；人复核和合并。它不是架构师——agent 对已有代码应用已知模式；架构决策（新抽象、模块拆分）是人的。它也不是代码审查的替代——diff 是提案；审查者对照代码库意图检查它。
