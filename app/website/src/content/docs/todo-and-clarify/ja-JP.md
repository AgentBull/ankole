`todo` と `clarify` は、`Ankole.Sessions.Tools.Session` が所有するコントロールプレーン側の組み込みツールです。セッション Driver が引数を検証し、モデル向けの実行結果を AIGateway に保存したうえで現在の Run の状態へ反映します。

## タスクリスト

`todo` ツールは、タスクリストの読み取り、全体の置き換え、または項目 ID 単位でのマージ更新を行います。各項目のステータスは `pending`、`in_progress`、`completed`、`cancelled` の 4 種類で、1 回の宣言につき最大 256 項目まで指定できます。システムプロンプトの指示では、3 ステップ以上の複雑な作業で `todo` を活用し、優先度順に並べること、`in_progress` を常に 1 項目だけに絞ること、完了したら即座に更新すること、失敗時には軌道修正した項目を追加することが求められます。

タスクリストは `Ankole.Sessions.Run` に紐づく実行中の作業状態です。障害復旧時には、現在の Run の履歴に記録されている成功済みのツール呼び出しからリストが再構築されます。新しい Session が別の Session のタスクリストを引き継ぐことはありません。Session をまたいで共有すべき知見は [Brain](../brain/) に保存します。

## 1 つの判断質問

`clarify` ツールは、最終成果物の方向性や次のアクションを決めるためにどうしてもユーザーの確認が必要な場面に限り、それ単体で文脈が伝わる質問を 1 つ提示します。Agent はまず今回の依頼内容と過去の会話履歴を確認し、すでに示されている希望を聞き直さないようにします。また、安全で低リスクな既定値を選べる場合は、作業を止めずにそのまま進めます。

回答形式には、自由記述または互いに重複しない 2〜4 個の選択肢を指定できます。文字数上限は、質問文が 2,000 文字、選択肢ラベルが 200 文字、任意の補足説明が 500 文字です。実行を見送ることができる操作については、「何もしない（見送る）」ための選択肢も含めます。

呼び出しが成功すると、正規化された質問と選択肢が記録され、その時点で現在の Turn が終了します（同じ Turn 内で追加のツール呼び出しや通常の最終応答は出力されません）。ネイティブの **Pod Chat** では、コントロールプレーンが `rich_content["clarify"]` にスナップショットを保存して対話型の **`ChoiceCard`** として描画し、Delivery のインタラクションチェックポイントが `pending -> answered | superseded` の状態遷移を管理します（同じ Agent が新しい質問を出すと、未回答だった古い質問は `superseded` に遷移します）。ルームメンバーは `ChoiceCard` 上で選択肢をクリックするかテキストを入力して回答でき（先着優先ロックにより、後から競合した回答には HTTP `409` が返されます）、Pod Chat や外部チャットチャネルで通常の自由テキストメッセージを返信した場合も継続 Turn が開始されます。提示された質問と受理された回答は、永続的な会話履歴に記録されます。

## Background Job と運用

ネイティブの Codex Job は、これとは独立した独自の入力要求経路を持っています。人間の判断待ちになった Job は `waiting_on_user` 状態へ遷移して Worker の実行スロットをいったん解放し、オーナーから返信が届いた時点で処理を再開します。このライフサイクル契約の詳細については、[Background Agent Jobs](../background-agent-jobs/) を参照してください。

なお、計画管理や Turn 終了の挙動を Console から切り替える設定フラグはありません。計画の立て方や質問の頻度を調整したい場合は、Agent のシステム指示（`MISSION.md` / `SOUL.md`）や有効な能力セットを見直してください。詳しくは [Agents](../agents/) および [Agent loop](../agent-loop/) を参照してください。
