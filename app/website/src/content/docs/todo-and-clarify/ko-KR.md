`todo`와 `clarify`는 `Ankole.Sessions.Tools.Session` 모듈이 소유하는 제어 플레인 도구입니다. Driver가 호출 인수를 검증한 뒤 AIGateway를 통해 모델 가시 결과를 기록하고, 그 변경을 현재 실행 상태에 반영합니다.

## 작업 목록

`todo` 도구는 현재 작업 목록을 조회하거나 전체 교체하고, 항목 ID 기준으로 변경 사항을 병합합니다. 각 항목은 `pending`, `in_progress`, `completed`, `cancelled` 중 하나의 상태를 가지며 최대 256개 항목까지 등록할 수 있습니다. 시스템 지침에서는 세 단계 이상으로 이루어진 복합 작업을 수행할 때 목록을 우선순위 순으로 구성하고, 동시에 `in_progress`인 항목은 하나만 유지하며, 단계가 끝나는 즉시 완료 표시를 남기고 실패 시 수정 항목을 추가하도록 안내합니다.

이 목록은 `Ankole.Sessions.Run` 내부의 실행 중 작업 상태입니다. 프로세스 복구 시에는 현재 실행 이력에 기록된 성공 도구 호출들을 바탕으로 목록을 다시 재구성하며, 새 Session을 시작할 때 다른 Session의 목록을 물려받지는 않습니다. 여러 Session 사이에 공유해야 하는 지식은 [Brain](../brain/)에 기록합니다.

## 결정 질문 하나

`clarify` 도구는 사용자의 답변에 따라 최종 결과나 다음 행동이 달라질 때만, 그 자체로 맥락이 완결된 질문 하나를 던지는 데 사용합니다. Agent는 먼저 현재 요청과 앞선 대화 기록을 살펴보며, 이미 밝혀진 선호 사항을 되묻지 않고 안전하고 위험 부담이 낮은 기본값이 있다면 작업을 멈추지 않고 그대로 진행합니다.

질문에는 자유 텍스트 응답을 받을 수도 있고, 서로 겹치지 않는 2~4개의 선택지를 제시할 수도 있습니다. 길이 한도는 질문 본문 2,000자, 선택지 라벨 200자, 선택지 설명 500자이며, 사용자가 실행을 원치 않을 수 있는 작업에는 취소·보류에 해당하는 선택지를 함께 넣어야 합니다.

호출이 성공하면 정규화된 질문과 선택지를 기록하고 즉시 현재 턴을 종료하며, 같은 턴에서 추가 도구를 호출하거나 별도 최종 답변을 덧붙이지 않습니다. 네이티브 **Pod Chat**에서는 제어 플레인이 질문 스냅샷을 `rich_content["clarify"]`에 저장해 대화형 **`ChoiceCard`**로 렌더링하고, Delivery 상호작용 체크포인트가 `pending -> answered | superseded` 상태 전이를 관리합니다(같은 Agent가 새 질문을 보내면 미해결 상태였던 이전 질문은 `superseded`로 전환됩니다). 대화방 구성원은 `ChoiceCard`에서 선택지를 고르거나 직접 텍스트를 입력해 응답할 수 있으며(선착순 잠금이 적용되어 동시에 들어온 중복 응답은 HTTP `409`를 반환), Pod Chat이나 외부 메신저 채널에서 일반 채팅 메시지로 답장해 다음 턴을 이어갈 수도 있습니다. 질문과 채택된 답변은 모두 영구 대화 기록에 남습니다.

## Background Job과 운영

Native Codex 기반의 Background Job은 별도의 사용자 입력 요청 경로를 사용합니다. 작업 도중 사람의 확인을 요청하면 Job 상태가 `waiting_on_user`로 바뀌면서 점유하던 실행 슬롯을 반납하고, 소유자가 답변을 보내면 그 시점에 실행을 재개합니다. 자세한 수명 주기 계약은 [Background Agent Jobs](../background-agent-jobs/)를 참조하세요.

계획 목록 관리와 질문 후 턴 종료 동작을 켜고 끄는 별도의 Console 플래그는 없습니다. Agent가 계획을 세우거나 되묻는 기준을 조정하려면 Agent의 지침 문서와 활성화된 기능을 수정하세요. 관련 내용은 [Agents](../agents/)와 [Agent loop](../agent-loop/)를 참조하세요.
