一个邮件摘要 agent 拿一批到来的消息——邮件、通知、频道摘要——产出结构化的每日简报：需要行动的、信息性的、可忽略的。这是[摘要 agent](../summarization-agent/) 应用到周期性批量输入的变体，也是[每日简报机器人](../daily-briefing-bot/)的近亲。

先把决定性的性质说清楚：简报是**分诊过的，不是穷尽的**。agent 不逐字摘要每封邮件；它把每条消息分类（需要行动/FYI/忽略），只摘要人设说要紧的。价值在于分诊，不在于压缩。

## 需要什么

- **绑定 `primary` profile**——分类和摘要需要推理。
- **一个 signal binding** 到简报发帖的频道。
- **一个调度**——每天，工作日开始时。见 [Cron 调度](../cron-schedules-ops/)。
- **一种交付批量的方式**——消息作为频道讨论到达、粘贴的批量、投递通知的 webhook、或 agent 读取的文件。

## 简报结构

agent 发的一个好的每日简报：

```text
**每日简报 — <日期>**
**需要行动**（今天回复或决定）：
- <发件人>：<主题>——<他们想要什么的一句话摘要>
**FYI**（有空时读）：
- <发件人>：<主题>——<一句话摘要>
**已忽略**（自动分类，无需行动）：
- 来自监控、通讯或自动化系统的<count>条消息
```

三层结构（行动/FYI/忽略）是核心价值。50 封邮件的扁平摘要不是简报；它是一个稍短的收件箱。3 个行动项加 47 条忽略消息的计数才是有用的。

## 人设控制什么

- **分类规则**——"邮件提问、请求审查或提到截止日期时分类为'需要行动'。信息性的为'FYI'。来自监控系统、通讯或自动通知的为'忽略'。"
- **摘要深度**——"每个行动项一行；忽略的只给计数。"
- **阈值**——"若无行动项，发'今天无需行动'加 FYI/忽略计数。不发空简报。"
- **交付**——"早上 9 点发到频道。"

## 一个完整示例

为团队负责人设置每日邮件摘要 agent：

1. 创建 agent，绑 `primary`/`light`。
2. 撰写 `MISSION.md`："每天早上，读转发到摘要频道的隔夜邮件批量。把每封分类为 需要行动/FYI/忽略。行动项各一行摘要。FYI 和忽略给计数。早上 9 点发简报。无行动项时说'今天无需行动'。"
3. 设置邮件转发到频道（通过 webhook 或把邮件作为消息投递的集成）。
4. 加一条每日调度：`cron: "0 9 * * 1-5"`（工作日 9 点）。
5. agent 读批量、分类、摘要、发简报。

## 本指南不是什么

它不是邮件客户端——agent 读和摘要；它不发、回复或管理收件箱。它不是垃圾邮件过滤器——它为简报分类消息，但收件箱仍接收一切。它也不是读重要邮件的替代——简报告诉你读什么；它不替代读行动项。
