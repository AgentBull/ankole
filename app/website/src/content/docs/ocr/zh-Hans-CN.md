只需将文件发给 Agent 并说明想提取哪些内容，即可完成文字识别。Ankole 已在 Agent Computer Worker 中内置本地 OCR 引擎，无需额外配置模型提供商、API Key 或第三方 OCR 服务。

例如，你可以直接发送以下指令：

```text
读取这张截图中的全部文字，保持原来的阅读顺序。

提取这份扫描 PDF 的第 2 到第 5 页，无法确定的文字请明确标出。

读取这张收据，列出商家、日期、商品、税费和总金额。
```

## 普通 CPU 也能运行的先进识别能力

Ankole 内置了业界领先且原生支持 CPU 推理的 [PaddleOCR PP-OCRv6 medium](https://www.paddleocr.ai/latest/version3.x/algorithm/PP-OCRv6/PP-OCRv6.html) 检测与识别模型。在 PP-OCRv6 模型系列中，Medium 档位专注于更高识别精度；根据 PaddleOCR 官方评测，相比 PP-OCRv5_server，其文字检测精度提升 4.6%，文字识别精度提升 5.1%。

单个模型即可覆盖 50 种语言，包括简体中文、繁体中文、英文、日文以及 46 种拉丁语系语言；不仅适用于常规文档扫描件，也能准确识别屏幕截图、街头招牌、商品标签和数码显示屏等真实场景中的文字。

Ankole 借助 OpenVINO 对 CPU 推理路径做了深度加速，使普通 Worker 节点无需挂载 GPU 也能在本地快速完成识别。所有模型均随 Worker 镜像直接分发，文档无需外发至第三方识别服务，也不会产生按页计费的调用成本。

## Ankole 会选择更准确的读取方式

OCR 本质上是从图像像素中还原文字，而文本提取则是直接读取文件中的原始字符。只要文件内包含可直接读取的文本层，Ankole 就会优先采用更精确的提取方式：

- **带文字层的 PDF**：直接提取内嵌原文；
- **纯扫描版 PDF**：逐页执行 OCR 识别；
- **图文混排的混合 PDF**：仅对扫描页运行 OCR，其余含文字层的页面直接提取原文；
- **DOCX、PPTX 与 XLSX 文档**：直接按原生文档结构解析内容，而非将页面渲染成图片再识别。

使用时无需手动指定读取方式，直接上传原始文件并说明所需结果即可。

## Agent 可以返回什么

根据你的指令，Agent 可以返回原始识别文本、整理排版后的文稿、内容摘要，或是按字段提取的结构化数据。由于底层 OCR 引擎会一并输出每行文字的坐标位置与置信度，Agent 既能据此还原原有的阅读顺序，也能在扫描件模糊不清时主动提示哪些内容不够可靠。

若想获得最佳识别效果，请尽量上传清晰、摆正且分辨率充足的图片；遇到字号较小的材料时，请直接发送原文件，避免发送经过二次压缩的截图。此外，你还可以明确要求 Agent 标出存疑字句，防止其自行猜测补全。

## 能力边界

- 当前内置的 50 语种模型暂不支持韩文、阿拉伯文、西里尔字母、泰文等其他文字系统。
- 遇到手写体、数学公式、复杂表格、弯曲排版，或模糊、明显倾斜的照片时，识别准确率可能下降；处理表格时会返回带位置坐标的文字行，但不保证完整还原表格行列结构。
- OCR 仅负责读取并返回文字内容，不会向原 PDF 文件回写可搜索的隐藏文字层。

`ocr` Skill 默认处于启用状态。如果 Agent 提示 OCR 不可用，请确认当前使用的是最新版 Worker 镜像，并在 **Agent 能力库** 中检查该 Skill 是否已开启。
