技能教训是 Agent 在加载某个 Skill 时一并读取的简短过程提示，每条均附有创建日期。借助这一机制，Agent 能够避开执行环境中反复踩到的工具报错、依赖陷阱与操作偏差，同时保持全局共享的 `SKILL.md` 原文干净不变。

这一设计汲取了 GBrain 技能优化实验的思路，将 Agent 在实战调用某个 Skill 时踩过的坑沉淀为带日期的经验卡片。出于稳健性考虑，Ankole 严格禁止机器自动改写 `SKILL.md` 正文，仅允许自动生成带有有效租约、且限定于单个 Agent 的简短过程提示。

每条教训严格绑定至单个 Agent 与单个 Skill；如果某条规范对所有 Agent 都普遍适用，则应当直接修入该 Skill 的源码正文。

## 什么内容可以成为教训

Ankole 仅收录以下两类可复用的过程性注意事项：

- 在多次后台 Agent 任务（Job）中反复出现的工具调用故障或特定环境约束；
- 人类用户在任务运行中途发出的、同样适用于日后同类任务的操作方式纠偏。

一条合格的教训只能围绕“何时应当中止、执行前需核查什么条件、或应当如何正确传参调用工具”展开；不得规定产出物应当写得多么深入或详尽，也不得干涉观点立场、行文语气或排版风格。此外，Ankole 不会依靠对最终任务结果打分来评判某条教训是否有效。

仅针对单次任务的临时要求不属于技能教训——例如一次性的调研范围、特定文件格式或专有名词约定，只约束当次任务本身。在实际运行中，绝大多数历史执行批次都不会提炼出新教训。

## 证据需要达到什么条件

系统仅分析已运行结束的后台 Agent 任务，且仅回溯最近 30 天内的记录；候选任务中必须实际发生过命令或工具调用失败，或者在任务启动后收到过人工干预消息。

只有当某个 Agent 名下积累的未处理候选任务达到阈值后，后台 Dreaming 机制才会拉起一次专门的复盘任务（默认阈值为 `10`，单次复盘最多读取最近 `30` 个符合条件的任务记录）。

生成机器教训通常要求至少在两个彼此独立的任务中观察到同类证据；唯一例外是某次任务中的人工指导消息本身已经明确给出了具有普适价值的纠偏准则，此时单条任务证据即可采信。

复盘任务仅获准在本地工作环境中执行只读核查，严禁修改任何文件、发起外部网络请求或擅自修复环境故障；历史报错信息与工具标准输出一律按不可信外部数据审慎对待。

## Agent 会收到什么

当 Agent 读取某项 Skill 的完整说明时，当前生效的教训会按日期标注，集中追加在正文末尾的 `Agent-specific additions` 区块中，其中管理员添加的人工教训始终排在 Dreaming 提炼的机器教训之前。

已手动退场的教训，以及逾期未完成复审宽限的机器教训，均不会注入 Agent 上下文；一旦关闭该 Skill，其关联教训也会一并停止下发。所有历史记录仍完整保留在数据库中，供运维人员随时调阅审计。

## 让机器教训保持有效

由 Dreaming 自动提炼的机器教训初始附带 7 天有效租约。每当租约临近到期、Ankole 实例升级版本或所属 Skill 正文发生变更时，定时运行的 Dreaming 任务都会对该教训重新发起复审。

复审会产生以下三种结论之一：

- **续期**：经核查底层环境约束依然存在，或近期尚无相反新证据时，延长租约继续保留；
- **已过时**：底层环境问题已消除，或更新后的 `SKILL.md` 正文已正式涵盖该注意点时，将其标记退场；
- **租约到期**：近期运行记录未能再次印证该条件，同时也无法断言其已彻底过时，租约期满后自动退场。

若因模型不可用等原因未能按时产出复审结论，该教训在额外经过 7 天宽限期后也会自动停止下发，但数据库记录依然保留以便排查原因。

相比之下，由运维人员手工录入的人工教训不设租约期限，Dreaming 绝不会擅自修改或清退人工教训。

## 新增或让教训退场

1. 打开 Console 中的 **Agent 能力库**。
2. 将页面顶部的作用域从**全局默认值**切换为目标 Agent。
3. 在 Agent Plugin 详情或 **Skills** 标签页中定位到目标 Skill。
4. 点击**新增教训**，先写明触发或适用条件，再写明需要采取的具体动作。
5. 当某条现有教训有误、已过时或不再适用时，点击**退场**将其停用。

仅支持为当前处于启用状态的 Skill 添加人工教训。人工教训不受机器教训的短句字数限制，但同样禁止包含任何 URL。教训一经创建不支持原地编辑正文；如需修订措辞，请先将旧条目退场，再重新创建新条目。

在 Console 卡片上可直观查看每条教训的创建者、生成时间、上次复审日期、核对过的系统版本、支撑证据任务列表以及退场原因。凡是被人工主动清退的教训都会记入 Dreaming 的“禁止重复学习”名单，防止机器日后又把内容雷同的教训重新加回来；从下一轮推理回合起，Agent 便不再读取已退场的条目。

## 配置和观察学习状态

可通过以下 `brain.*` 配置项管理系统级的技能教训行为：

| 配置项 | 默认值 | 用途说明 |
|---|---|---|
| `brain.skill_learning_enabled` | `true` | 控制复盘提炼、租约复审与教训下发的总开关。设为 `false` 后，既有的人工教训与机器教训均会暂时隐藏停止下发，但底层数据不会被删除。 |
| `brain.skill_learning_reflection_threshold` | `10` | 触发一次复盘任务所需的未处理候选任务累计数量（最小允许值为 `2`）。 |
| `brain.maintainer_agent_uid` | 未设置 | 指定负责日常维护 Brain 的 Agent，并借用其 `heavy` 模型档案执行租约教训复审；若未配置或 `heavy` 档案不可用，则跳过依赖模型的复审步骤。 |
| `brain.dreaming_task_cron` | `0 5 * * *` | 控制 Dreaming 每日定时检查复盘触发条件及复审临期教训的 Cron 排期。 |

打开 **Brain → 健康** 页面，即可总览当前技能学习总开关状态、各 Agent 名下的生效教训条数、过去 7 天内的新增与退场动态，以及现存最早一条生效机器教训的持续天数。

## 限制与安全

- **精炼英文表述**：机器自动生成的教训统一使用英文撰写，由 1 至 3 个短句组成，上限为 100 Token，结构涵盖适用条件、应对动作及可选的验证方法。
- **数量封顶**：单次复盘最多为同一个 Skill 新增 2 条教训；当某个 Skill 名下已满 10 条生效教训时，Dreaming 将停止继续追加。
- **防注入过滤**：机器教训严禁包含任何 URL，且必须通过提示词注入检测规则校验。
- **单 Agent 严格隔离**：每条教训仅归属单个 Agent，系统绝不会在不同 Agent 之间横向共享机器教训。
- **先核实后采信**：在不完整重放原任务的情况下，系统无法绝对证明某条经验永远成立；因此教训均采用带日期的条件式表述，引导 Agent 在真正执行动作前先核对当下实际环境。
