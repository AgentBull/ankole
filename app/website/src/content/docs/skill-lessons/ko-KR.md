Skill 교훈(lesson)은 Agent가 Skill을 읽을 때 본문 뒤에 함께 전달되는 짧은 작업 주의 사항으로, 각 항목에 작성 날짜가 표시됩니다. 공유 원본 파일인 `SKILL.md`를 직접 고치지 않고도 반복되는 도구 호출 실패나 환경 제약, 작업 절차상 실수를 줄일 수 있도록 돕습니다.

이 기능은 GBrain의 Skill 최적화 실험에서 착안한 것으로, Agent가 실제 작업에서 Skill을 사용하는 동안 날짜가 찍힌 운영 노트를 축적하는 방식입니다. Ankole에서는 자동 생성되는 항목을 유효 기간(리스)이 있는 Agent별 프로세스 노트로 엄격히 제한하며, 원본 Skill 본문은 절대 수정하지 않습니다.

각 교훈은 특정 Agent 하나와 특정 Skill 하나에만 귀속됩니다. 모든 Agent에 공통으로 적용되어야 하는 규칙이라면 교훈 대신 Skill 소스 본문에 직접 반영하세요.

## 교훈이 될 수 있는 내용

Ankole이 교훈으로 기록하고 유지하는 주의 사항은 다음 두 가지 범주입니다.

- 여러 Background Agent Job에서 반복 관찰된 도구 오류나 실행 환경 조건
- Job이 실행되는 도중 사람이 남긴 피드백 가운데 이후 다른 작업에서도 재사용할 수 있는 절차상 교정 사항

교훈에는 언제 실행을 멈출지, 무엇을 먼저 확인할지, 도구를 어떤 방식으로 호출할지를 적을 수 있습니다. 반면 산출물의 품질 수준, 분석 깊이, 완결성, 관점, 어조, 문체(style)를 규정하는 용도로는 사용할 수 없으며, Ankole 역시 작업 결과물을 채점해 교훈의 효과를 평가하지 않습니다.

단발성 작업에만 해당하는 요구 사항은 교훈으로 추출되지 않습니다. 특정 요청에만 적용되는 범위, 출력 형식, 용어 지정은 해당 작업 안에서만 유효하며, 실제로도 대부분의 실행 기록에서는 새 교훈이 생성되지 않습니다.

## 필요한 증거

Ankole은 최근 30일 이내에 종료된 Background Agent Job 가운데 명령·도구 호출 실패가 발생했거나 Job 시작 이후 사람의 후속 메시지가 들어온 Job을 추려 분석 대상으로 삼습니다.

특정 Agent에 아직 검토하지 않은 대상(signal) Job이 기준치 이상 쌓이면 Dreaming이 성찰(reflection) Job을 생성합니다. 기본 임계값은 `10`개이며, 성찰 Job 한 번에는 조건을 충족하는 최신 Job이 최대 30개까지 전달됩니다.

기계가 자동으로 교훈을 작성하려면 원칙적으로 서로 다른 두 개 이상의 Job에서 뒷받침되는 증거가 확인되어야 합니다. 단일 Job만으로 교훈이 만들어지는 예외는, 그 Job 도중 사람이 보낸 메시지 자체에 앞으로도 재사용할 만한 일반화된 수정 지침이 직접 담겨 있는 경우뿐입니다.

성찰 Job은 로컬 환경에서 읽기 전용 확인 명령만 실행할 수 있으며, 파일을 수정하거나 외부 네트워크에 접근하거나 문제를 직접 고치지는 못합니다. 또한 로그에 남은 오류 메시지와 도구 출력은 모두 신뢰할 수 없는 데이터로 취급합니다.

## Agent가 받는 내용

활성 상태인 교훈은 전체 Skill 본문 뒤에 붙는 `Agent-specific additions` 섹션에 날짜와 함께 나열되며, 사람이 직접 등록한 교훈이 Dreaming이 생성한 교훈보다 위에 배치됩니다.

폐기된 교훈이나 재검토 유예 기간을 넘긴 기계 생성 교훈은 프롬프트에 포함되지 않습니다. 해당 Skill 자체가 비활성화되어 있을 때도 교훈이 Agent 컨텍스트로 전달되지 않지만, 저장된 교훈 이력은 Console에서 계속 조회할 수 있습니다.

## 기계 교훈을 최신 상태로 유지하기

Dreaming이 생성한 기계 교훈에는 처음 7일짜리 리스가 부여됩니다. 이후 정기 실행되는 Dreaming 작업이 리스 만료가 임박했거나 Ankole 릴리스 버전이 바뀌었을 때, 또는 대상 Skill 본문이 수정되었을 때 해당 교훈을 다시 검토합니다.

재검토 판정은 다음 세 가지 중 하나로 내려집니다.

- **갱신:** 해당 환경 조건이 여전히 유지되고 있거나 반대되는 새 증거가 없을 때 리스를 연장해 교훈을 유지합니다.
- **더 이상 유효하지 않음:** 환경 문제가 해소되었거나 해당 내용이 이미 Skill 원본 본문에 반영되었을 때 교훈을 폐기합니다.
- **리스 만료:** 최근 실행 기록만으로 조건 지속 여부를 확인할 수 없고 무효화 근거도 부족한 채 리스가 끝났을 때 교훈을 만료 폐기합니다.

제때 재검토 판정을 받지 못한 기계 교훈은 7일의 유예 기간이 지나면 전달이 중단됩니다. 폐기되거나 중단된 항목도 이력에는 그대로 남아 운영자가 언제든 경위를 확인할 수 있습니다.

반면 사람이 직접 추가한 교훈에는 리스 만료가 없으며, Dreaming이 임의로 수정하거나 폐기하지도 않습니다.

## 교훈 추가 또는 폐기

1. Console에서 **Agent Library**를 엽니다.
2. 상단 범위를 **전역 기본값**에서 대상 Agent로 전환합니다.
3. Agent Plugin 또는 **Skills** 목록에서 대상 Skill을 찾습니다.
4. **교훈 추가**를 누르고 적용 조건을 먼저 적은 뒤 취해야 할 행동을 입력합니다.
5. 기존 교훈이 잘못되었거나 시효가 지났다면 해당 항목에서 **폐기**를 선택합니다.

사람이 직접 등록하는 교훈은 현재 활성화된 Skill에만 추가할 수 있습니다. 기계 교훈과 달리 짧은 토큰 제한은 없으나 본문에 URL을 넣을 수는 없습니다. 등록된 교훈 본문은 직접 수정할 수 없으므로, 내용을 고치려면 기존 항목을 폐기하고 새로 추가하세요.

Console 화면에는 작성 주체, 생성 시각, 재검토 예정일, 검증된 릴리스 버전, 근거가 된 증거 Job, 폐기 사유가 모두 표시됩니다. 운영자가 직접 폐기한 내용은 Dreaming의 재학습 금지 목록에 기록되므로, 이후 Dreaming이 같은 취지의 교훈을 다시 만들어 내지 않습니다. 폐기된 교훈은 Agent의 다음 턴부터 즉시 제외됩니다.

## 학습 설정 및 상태 확인

Skill 교훈 동작은 다음 `brain.*` 설정으로 제어합니다.

| 설정 | 기본값 | 효과 |
|---|---|---|
| `brain.skill_learning_enabled` | `true` | 성찰(reflection), 재검토, 교훈 전달 기능을 활성화합니다. `false`로 바꾸면 저장된 사람·Dreaming 교훈을 삭제하지 않은 채 전달만 숨깁니다. |
| `brain.skill_learning_reflection_threshold` | `10` | 성찰 Job 하나를 시작하기 위해 쌓여야 하는 미처리 signal Job 수입니다(최솟값 `2`). |
| `brain.maintainer_agent_uid` | 설정되지 않음 | Brain 유지보수 담당 Agent를 지정하고, 그 Agent의 `heavy` 프로필을 사용해 리스 교훈을 재검토합니다. 사용 가능한 `heavy` 프로필이 없으면 모델 기반 재검토를 건너뜁니다. |
| `brain.dreaming_task_cron` | `0 5 * * *` | Dreaming이 성찰 트리거 조건을 점검하고 만료 임박 교훈을 재검토하는 실행 시각입니다. |

**Brain → 상태** 화면을 열면 Skill 학습 활성화 여부, Agent별 활성 교훈 수, 최근 7일간 추가·폐기된 교훈 수, 가장 오래된 활성 Dreaming 교훈의 경과 기간을 한눈에 확인할 수 있습니다.

## 제한과 안전

- 기계 생성 교훈은 최대 100 토큰 이내의 짧은 영어 문장 1~3개로 작성되며, 적용 조건과 수행할 행동, 선택적 사전 확인 방법을 담습니다.
- 성찰 Job 한 번이 단일 Skill에 추가할 수 있는 교훈은 최대 2개까지이며, 해당 Skill의 활성 교훈이 이미 10개에 도달해 있으면 Dreaming은 더 이상 추가하지 않습니다.
- 기계 생성 교훈에는 URL이나 프롬프트 인젝션 탐지 규칙에 걸리는 구문이 포함될 수 없습니다.
- 모든 교훈은 개별 Agent 단위로 격리 보관되며, 다른 Agent와 자동 공유되지 않습니다.
- 실제 작업을 다시 실행해 보기 전까지는 특정 교훈의 정확성이나 효과를 단정할 수 없습니다. 대신 각 교훈에 작성 날짜와 구체적인 전제 조건이 명시되므로, Agent가 실행 전에 현재 환경에서도 그 조건이 맞는지 먼저 점검할 수 있습니다.
