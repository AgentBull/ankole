Skill 教訓（Skill lessons）は、Agent が Skill を読み込む際に一緒に渡される、日付付きの短い作業メモです。繰り返し発生するツールの失敗や環境固有の制約、作業手順の誤りを防ぐために使われ、共有の `SKILL.md` 本体には一切手を加えません。

この仕組みは GBrain の Skill 最適化実験から着想を得たもので、Agent が実際に Skill を使う過程で得られた知見を日付付きメモとして蓄積します。Ankole では、自動生成される内容を「有効期限（リース）付きの Agent 固有プロセスノート」に厳格に限定しており、Skill 本体の手順を勝手に書き換えることはありません。

各教訓は、特定の 1 体の Agent と 1 つの Skill の組み合わせに紐付きます。すべての Agent に共通して適用したいルールがある場合は、教訓ではなく Skill 本体のソースに記述してください。

## 教訓になる内容

Ankole が教訓として保持できるのは、次の 2 種類の作業上の注意事項です。

- 複数の Background Agent Job で繰り返し発生したツールエラーや環境固有の条件。
- Job の実行中に人間から指摘された、今後の別タスクでも再利用できる作業手順の改善点。

教訓には「どの条件で立ち止まるか」「事前に何を確認するか」「ツールをどう呼び出すか」といった具体的な手順を書けます。一方で、成果物の品質基準、掘り下げの深さ、網羅性、主張の方向性、文体やトーンを規定することはできません。また、Ankole がタスクの最終成果物を採点して教訓の良し悪しを自動判定することもありません。

特定の 1 タスクかぎりの指示（単発の調査範囲、出力フォーマット、用語指定など）は教訓の対象外であり、そうしたやり取りのログから教訓が自動生成されることもありません。

## 必要な証拠

Ankole は直近 30 日間に終了した Background Agent Job のうち、コマンドやツール呼び出しの失敗が含まれる Job、または開始後に人間から追加メッセージを受け取った Job を抽出して調査します。

対象となる未処理のシグナル Job が一定数に達すると、Dreaming が振り返り用の reflection Job を起動します（既定のしきい値は `10` 件）。1 回の reflection Job には、条件を満たす直近最大 30 件までの Job 履歴が渡されます。

自動生成される教訓（機械教訓）には、原則として 2 件以上の異なる Job からの裏付け（証拠）が必要です。例外として 1 件の Job だけで教訓化されるのは、その Job 内で人間が送ったメッセージ自体に、他の作業でもそのまま使える明確な手順修正が書かれている場合のみです。

なお、reflection Job はローカル環境の読み取り専用検査だけを実行でき、ファイルの変更や外部ネットワーク通信、問題の直接修復は行えません。ログ内のエラー文やツール出力はすべて信頼できない外部データとして安全に処理されます。

## Agent が受け取る内容

有効な教訓は、Skill 本体の手順の末尾にある `Agent-specific additions` セクションに日付付きで差し込まれます。人間が手動で追加した教訓は、Dreaming が自動生成した教訓よりも上に表示されます。

廃止（retire）された教訓や、再確認の猶予期間を過ぎた機械教訓は配信されません。また、対象の Skill 自体を無効化すると、その教訓も Agent のコンテキストには渡されなくなります。なお、廃止後も保存された履歴自体は残るため、運用者は後から経緯を確認できます。

## 機械教訓を最新に保つ

Dreaming が作成した機械教訓には、まず 7 日間のリース期間が設定されます。定期実行される Dreaming は、リース期限が近づいたとき、Ankole のリリースバージョンが更新されたとき、または対象の Skill 本文が変更されたときに教訓の妥当性を再確認します。

再確認の結果は、次の 3 つのいずれかになります。

- **更新（Renew）：** 該当する環境条件がまだ残っている場合、または否定する新しい証拠がない場合に、リースを延長して教訓を維持します。
- **陳腐化（Obsolete）：** 環境側の問題が解消された場合、または同じ内容がすでに Skill 本文へ取り込まれた場合に、教訓を廃止します。
- **リース期限切れ（Expired）：** 直近の実行履歴からは条件の存続を確認できず、かといって解消されたとも断定できない場合に、期限切れとして廃止します。

再確認が完了しないままリース期限から 7 日間の猶予期間を過ぎた教訓は、自動的に配信対象から外れます。履歴レコード自体は保持されるため、運用者はいつ・なぜ停止したかを確認できます。

一方、人間が手動で追加した教訓にはリース期限がなく、Dreaming が勝手に書き換えたり廃止したりすることもありません。

## 教訓を追加または廃止する

1. Console で **Agent Library** を開きます。
2. 上部のスコープを **グローバル既定** から対象の Agent に切り替えます。
3. Agent Plugin または **Skills** 一覧から対象の Skill を探します。
4. **教訓を追加** を選択し、「どのような条件のときに」「どの操作を行うか」の順で記述します。
5. 既存の教訓が誤っている、古くなった、または不要になった場合は **廃止** を選択します。

人間が教訓を追加できるのは、現在有効になっている Skill に対してのみです。手動追加の教訓には機械教訓のような厳しい文字数制限はありませんが、URL を含めることはできません。また、登録済みの教訓本文を後から直接編集することはできないため、文面を直したい場合は古い項目を廃止してから新しい項目を追加してください。

Console 上では、作成者、作成日時、最終再確認日、確認済みリリース、根拠となった証拠 Job、および廃止理由を確認できます。人間が手動で廃止した内容は Dreaming の再学習禁止リストに記録されるため、似た内容の教訓が再び自動追加されることはありません。廃止した教訓は、Agent の次の Turn からコンテキストに含まれなくなります。

## 学習を設定して状態を確認する

Skill 教訓の動作は、次の `brain.*` 設定キーで制御します。

| 設定 | 既定値 | 効果 |
|---|---|---|
| `brain.skill_learning_enabled` | `true` | reflection、再確認、および教訓の配信を有効にします。`false` にすると、保存済みの手動教訓・Dreaming 教訓を削除せずに配信だけを停止します。 |
| `brain.skill_learning_reflection_threshold` | `10` | 1 回の reflection Job を開始するのに必要な未処理シグナル Job の件数です（最小値は `2`）。 |
| `brain.maintainer_agent_uid` | 未設定 | Brain メンテナンス担当の Agent を指定し、その `heavy` プロファイルを使ってリース付き教訓の再確認を行います。利用可能な `heavy` プロファイルがない場合、モデルを使った再確認はスキップされます。 |
| `brain.dreaming_task_cron` | `0 5 * * *` | Dreaming が reflection の開始条件を評価し、期限間近の教訓を再確認するスケジュール時刻です。 |

**Brain → Health** 画面を開くと、Skill 学習の有効・無効、Agent ごとの有効な教訓数、直近 7 日間に追加・廃止された件数、および現在有効な最も古い Dreaming 教訓の経過日数を確認できます。

## 制限と安全性

- 機械教訓は英語 1〜3 文（最大 100 トークン）の短いメモに制限され、「発生条件・取るべき行動・任意の確認手順」の形式で記述されます。
- 1 回の reflection で 1 つの Skill に追加できる教訓は最大 2 件までです。対象の Skill に有効な教訓がすでに 10 件ある場合、それ以上の自動追加は行われません。
- 機械教訓には、URL やプロンプトインジェクション検査に抵触する表現を含めることはできません。
- 教訓はあくまで個別の Agent 固有であり、異なる Agent 間で自動的に共有されることはありません。
- 実際にタスクを再実行してみるまで、その教訓の正確さや効果を完全に保証することはできません。そのため、教訓には必ず日付と前提条件が添えられ、Agent が実行時に現在の環境と照らし合わせて確認できるようになっています。
