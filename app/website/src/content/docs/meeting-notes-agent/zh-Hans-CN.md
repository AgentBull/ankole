一个会议纪要 agent 拿会议的原材料——转写、频道讨论、或一组共享笔记——把它变成带行动项、负责人、决定的结构化纪要。本指南是那个 agent 的实际形态。

先把决定性的性质说清楚：agent **结构化，不决定**。它读原始讨论、提取说了什么、组织它。它识别的行动项是供团队确认的提案，不是 agent 做的分配。价值是结构化的速度，不是决策的权威。

## 需要什么

- **绑定 `primary` profile**——把讨论结构化为纪要需要综合。
- **一个 signal binding** 到纪要发帖的频道。
- **一种交付原材料的方式**——会议转写粘贴进频道、agent 读频道讨论（`may_intervene` 或会后）、或上传转写文件。

## 工作流

1. **原材料到达**——转写粘贴进频道、agent 观察的频道讨论、或上传的文件。
2. **agent 结构化**——识别讨论的话题、做的决定、未解决的问题。
3. **agent 提取行动项**——"谁说了在何时前做什么"，作为提案。
4. **agent 发结构化纪要**——话题、决定、行动项（带提议的负责人）、未解决问题。请求确认行动项。

## 纪要模板

agent 发的一个好的会议纪要结构：

```text
**会议纪要 — <日期>**
**话题**：<讨论了什么>
**决定**：<同意了什么>
**行动项**：
- [ ] @alice — 周三前起草 API 规格（提议）
- [ ] @bob — 周五前审查安全审计（提议）
**未解决问题**：<留下了什么未解决>
```

行动项标"提议"——agent 从讨论中提取了它们，但团队确认谁负责什么。

## 人设控制什么

- **结构**——模板、各节、详细程度。
- **行动项提取**——"只提取明确承诺，不提取暗示的任务。"vs"提取所有听起来像任务的东西。"
- **语气**——简洁摘要 vs 详细转写加评论。
- **请求**——"发纪要并请求确认行动项。不分配任务。"

## 一个完整示例

设置一个从 Slack 站会频道捕捉纪要的 agent：

1. 创建 agent，绑 `primary`/`light`/`heavy`。
2. 撰写 `MISSION.md`："在 #standup 的每日站会后，汇总讨论。结构为：话题、决定、行动项（提议）、未解决问题。发到 #notes。行动项标为提议——团队确认。"
3. 加一条站会结束后 30 分钟触发的调度：`cron: "30 10 * * 1-5"`（工作日 10:30）。
4. agent 读当天上午的讨论、结构化、发纪要。

## 本指南不是什么

它不是转录服务——agent 不把音频转文字。原材料必须是文本（转写、频道讨论或笔记）。它不是任务跟踪器——它提议行动项；团队的任务系统分配它们。它也不是决策者——它记录决定了什么；它不决定。
