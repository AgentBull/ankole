## 失敗した境界を見つける

| 観察される症状 | 最初に確認する箇所 |
|---|---|
| `/setup` または Console が開かない | デプロイ環境、`control-plane`、`function-runtime`、PostgreSQL、DNS、HTTPS |
| Console や Pod は開くが、サインインに失敗するかディレクトリが不完全 | エンタープライズ IdP SSO、パスワードレスのメール OTP（`authn.email.mail` による `SiteCredential`）、`principals.pod_login_policy`、および `siteadmin` / `pod_admin` メンバーシップ |
| Console 上では Agent と会話できるが、特定の IM でメッセージが処理されない | 該当する Channel Provider と signal routing rule |
| IM のメッセージは Ankole に届いているが、Agent が返信を生成できない | LLM Provider、Agent の model profile、Worker |
| 1 つのプラットフォームだけで問題が起きている | 下のタブから該当 Provider のみを確認する（他プラットフォーム向けの対処を混ぜて適用しない） |

問題を 1 回だけ再現させ、正確な発生時刻、Agent UID、ルーティングルール名、Provider 名、および画面に表示されたエラーメッセージ全文を控えてください。そのうえで、発生時刻前後の control plane と Worker のログだけを抽出し、イベント名を手がかりに最初のエラーを特定します。

なお、サポートや Issue で報告する際は、Client Secret、Bot Token、App Token、モデルの API key、環境変数の一括ダンプ、マスクしていない設定ファイルを絶対に含めないでください。ログ一式の丸ごと添付は避け、秘密情報をマスクした該当箇所のログと正確な再現手順を添えて共有してください。
