## 실패한 경계 찾기

| 관찰된 현상 | 먼저 확인할 것 |
|---|---|
| `/setup` 또는 Console이 열리지 않음 | 배포 상태, `control-plane`, `function-runtime`, PostgreSQL, DNS, HTTPS |
| Console 또는 Pod은 열리지만 로그인이 실패하거나 디렉터리가 불완전함 | 엔터프라이즈 IdP SSO, 패스워드리스 이메일 OTP(`authn.email.mail` 기반 `SiteCredential`), `principals.pod_login_policy` 및 `siteadmin` / `pod_admin` 멤버십 |
| Console 내부 대화는 동작하지만 특정 메신저의 메시지가 들어오지 않음 | 해당 Channel Provider 설정과 Signal Routing 규칙 |
| 메신저 메시지는 Ankole에 들어오지만 Agent가 답변을 생성하지 못함 | LLM Provider, 모델 프로필, Worker 상태 |
| 특정 플랫폼 하나만 실패함 | 아래에서 해당 프로바이더 탭을 선택해 점검(다른 플랫폼용 해결책을 섞어 적용하지 마세요) |

## Identity Provider 문제 해결

Identity Provider(IdP)는 콘솔 로그인과 연락처·조직도 동기화를 담당합니다. 조직에서 사용하는 인증 소스를 선택해 확인하세요. Slack Socket Mode, Entra ID Graph 웹훅 구독, Google Workspace 전체 동기화는 동작 방식이 서로 다르므로 점검 항목도 각각 다릅니다.

## 채팅 채널 문제 해결

채팅 채널은 외부 메신저 메시지를 수신하고 Agent의 응답을 전달합니다. 문제가 발생한 Signal Routing 규칙의 플랫폼을 선택하세요(로그인용 IdP에 어떤 플랫폼을 썼는지는 채팅 채널 선택에 영향을 주지 않습니다).

## 실패 경계가 여전히 불명확한 경우

문제를 한 번 다시 재현하면서 정확한 발생 시각, Agent UID, 라우팅 규칙 이름, 프로바이더 종류, 화면에 표시된 전체 오류 메시지를 기록하세요. 그런 다음 해당 시각 전후의 `control-plane` 및 Worker 로그만 발췌해 이벤트 이름을 기준으로 최초 오류 지점을 추적합니다.

이슈를 공유하거나 제보할 때 Client Secret, Bot Token, App Token, 모델 API 키, 전체 환경 변수 덤프, 마스킹하지 않은 설정 파일을 절대 첨부하지 마세요. 통째로 묶은 로그 아카이브 대신 민감 정보를 제거한 관련 로그 발췌본과 정확한 재현 절차만 전달해 주세요.

- [Ankole 로그 읽기](../log-reading/)
