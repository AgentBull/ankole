## Find the failed boundary

| What you observe | Check first |
|---|---|
| `/setup` or the Console does not open | Deployment, `control-plane`, `function-runtime`, PostgreSQL, DNS, and HTTPS |
| The Console or Pod opens, but sign-in fails or the directory is incomplete | Enterprise IdP SSO, passwordless Email OTP (`SiteCredential` via `authn.email.mail`), `principals.pod_login_policy`, and `siteadmin` / `pod_admin` membership |
| The Agent works in the Console, but one IM gets no message | That Channel Provider and its signal routing rule |
| The IM message enters Ankole, but the Agent cannot generate a reply | LLM Provider, model profiles, and Worker |
| Only one platform fails | Select that Provider below; do not apply another platform's fix |

## If the failing boundary is still unclear

Reproduce the failure once while noting the exact timestamp, Agent UID, routing-rule name, Provider, and full UI error message. Next, pull only the control-plane and Worker log lines around that timestamp and locate the earliest error event.

Never share a Client Secret, Bot Token, App Token, model API key, raw environment dump, or unredacted config file—when filing an issue, attach redacted log excerpts alongside exact reproduction steps rather than a full log archive.
