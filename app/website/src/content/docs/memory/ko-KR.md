장기 memory는 더 오래된 메시지를 더 많이 찾기 위해 존재하지 않습니다. 새로운 증거가 도착했을 때 Agent가 세계와 자신의 작업에 대한 이해를 수정할 수 있게 해 주는 것이 목적입니다.

2년 전에 “저는 바베큐를 좋아합니다”라고 말했다고 가정해 봅시다. 지난달에는 “저는 이제 채식주의자입니다”라고 말했습니다. 벡터 검색은 두 문장을 모두 찾아낼 수 있지만, 두 번째 문장이 첫 번째 문장의 의미를 바꾼다는 사실은 알 수 없습니다.

Ankole의 장기 memory 모듈의 코드네임은 **Brain**입니다. 소스 증거, 정리된 현재 지식, 백그라운드 Dreaming, 외부 소스 학습, Skill 경험을 연결합니다.

## Memory는 채팅 아카이브가 아닙니다

추가 전용 채팅 로그는 “누가 무엇을 말했는가”에 답할 수 있습니다. 하지만 “Agent가 지금 무엇을 믿어야 하는가”에는 답할 수 없습니다. 내구성 있는 memory 시스템은 세 가지 작업을 더 수행해야 합니다:

- **Memory compaction:** 여러 대화의 관련 정보를 하나의 안정적인 토픽으로 병합합니다.
- **Memory evolution:** 새로운 사실이 도착하면 옛 지식을 수정하고 유용한 시간 경계를 유지합니다.
- **Conflict handling:** 수정, 소스 간 불일치, 검증되지 않은 주장, Agent의 추론을 구분합니다.

Brain은 두 가지 형태의 지식을 유지합니다. 세계 모델(world model)에는 사람, 조직, 프로젝트, 정책과 그 관계에 대한 엔트리가 포함됩니다.

추론 memory(Reasoning memory)에는 Agent가 귀납하거나 연역한 판단, 경험, 작업 방법이 포함됩니다.

## 장기 memory에는 무엇이 포함되나

| 구성 요소 | 답하는 질문 | 사실로 직접 사용할 수 있나요? |
|---|---|---|
| **채팅 메시지** | 누가 언제 무엇을 말했나요? | 그 문장이 실제로 말해졌다는 것만 증명합니다 |
| **외부 소스** | Agent가 읽은 텍스트, 웹 페이지, 파일은 무엇인가요? | 증거가 되지만 각 주장은 여전히 틀릴 수 있습니다 |
| **에피소드 요약** | 채팅의 한 구간은 무엇에 관한 것이었나요? | 아니요. 원본 메시지만 찾아줍니다 |
| **지식 엔트리** | 한 토픽에 대한 현재 이해는 무엇인가요? | 현재 시점의, 인용이 있는, 수정 가능한 지식입니다 |
| **고정 메모** | 매 턴마다 반드시 존재해야 하는 규칙은 무엇인가요? | 지식의 간결한 투영입니다 |
| **Skill Overlay** | 이 Agent가 특정 Skill을 사용할 때 무엇을 기억해야 하나요? | 한 Agent를 위한 절차적 경험입니다 |

하나의 Knowledge entry는 하나의 안정적인 토픽을 소유합니다. 이름, 타입, 별칭, 요약, 속성, 본문 블록, 다른 엔트리와의 관계를 담을 수 있습니다.

엔트리와 관계는 작은 세계 모델을 형성합니다. 예를 들어, 사람이 조직에 속할 수 있고 프로젝트가 정책의 영향을 받을 수 있습니다. Brain은 증거가 명시하는 관계만 저장합니다. 모델의 추측이 그래프 에지가 되지는 않습니다.

Knowledge entry는 의심할 여지 없는 진실이 아닙니다. Agent가 눈에 보이는 증거에서 만든 최선의 현재 이해입니다. 소스, 작성자, 시각, audit 기록을 유지합니다.

## Dreaming이 정보를 지식으로 바꿉니다

**Dreaming**은 Brain의 백그라운드 큐레이션 프로세스입니다. 메시지마다 모델을 호출하지 않습니다. 대화가 조용해지거나 충분한 자료가 쌓일 때까지 기다립니다.

이 프로세스를 통해 Agent는 논의 전체를 볼 수 있고 모델에 반복적으로 입력하는 횟수를 줄일 수 있습니다.

### Stage A: 에피소드 인덱스 작성

Stage A는 각 channel의 오래된 메시지를 처리합니다. 하나의 채팅 윈도우를 하나 이상의 에피소드로 나눕니다. 브랜치는 별도의 에피소드가 될 수 있습니다. 노이즈는 무시할 수 있습니다. 끝나지 않은 토픽은 다음 배치를 기다릴 수 있습니다.

각 에피소드에는 토픽, 요약, 예상되는 향후 질문, 해결, 관련 시스템, 해결을 뒷받침하는 원본 메시지가 포함됩니다.

에피소드는 탐색 보조 수단일 뿐입니다. Stage A는 소스 메시지를 대체하거나 삭제하지 않습니다. Agent가 에피소드를 인용하거나 검증해야 할 때 Brain은 원본 채팅을 펼칩니다.

Brain은 모델 출력이 검증을 통과한 경우에만 에피소드와 커서를 하나의 트랜잭션으로 저장합니다. 실패하면 커서는 진행되지 않습니다. 구간이 건너뛰어져도 소스 메시지는 키워드 검색에 계속 사용할 수 있습니다.

### Stage B: 현재 지식 큐레이션

Stage B는 한 Agent의 자료를 처리합니다. 먼저 에피소드 요약과 가벼운 자료 인덱스를 스캔합니다. 그런 다음 관련 있는 소스 메시지, 현재 엔트리, 활성화된 Skill만 엽니다.

Stage B는 엔트리를 만들고, 오래된 블록을 변경하거나 제거하며, 요약, 별칭, 속성, 관계를 업데이트할 수 있습니다. 또한 pinned memo를 압축하고 재사용 가능한 교훈을 Skill Overlay에 기록합니다.

채팅 메시지는 사람, 팀, 결정, 외부 세계에 대한 주장을 뒷받침할 수 있습니다. task outcome은 Agent가 작업을 어떻게 수행했는지만 증명합니다. 최종 답변이 옳았다는 것을 증명하지는 않습니다.

일반적인 성공이 자동으로 경험이 되지는 않습니다. 사람의 수정, 오류 복구, 또는 쉽게 알 수 없는 다단계 성공은 재사용 가능한 작업 교훈을 정당화할 수 있습니다.

Stage B의 변경은 즉시 적용되며 같은 트랜잭션에서 audit trail에 들어갑니다. 감독은 변경 이후에 이루어집니다. 사람은 모든 큐레이션 작업을 먼저 승인하지 않아도 변경 사항을 검사, 수정, 복원할 수 있습니다.

Stage A는 조용한 시간이 30분 지난 후 또는 channel에 대기 중인 메시지가 200건 쌓인 후 실행됩니다. 하나의 윈도우에는 최대 200개 행과 약 8,000 token이 포함됩니다. 최신 20개 행과 최근 360분을 보호합니다.

이 값들은 고급 인스턴스 또는 Agent 설정입니다. 스캔은 자주 실행될 수 있지만, 자격 조건이 충족될 때만 모델을 호출합니다.

</details>

## 연역 memory와 귀납 memory

Brain은 문장을 복사하는 것 이상을 합니다. 증거 제약 아래에서 새로운 판단을 형성할 수 있지만, 연역과 귀납은 역할이 다릅니다.

### 연역: 알려진 사실의 의미 도출

연역은 알려진 사실과 명시적 관계에서 시작합니다. “이 사실들이 현재 작업에 어떤 의미를 갖는가?”에 답합니다. Agent는 관련 엔트리와 소스를 다시 열고 현재 컨텍스트에서 추론합니다.

내구성 있는 연역은 조건부로 남아 있어야 하며 Dreaming 작성자, 날짜, 증거를 기록해야 합니다. 추론된 관계는 그래프에 들어가지 않습니다. 소스가 명시하는 관계만 구조화된 관계가 될 수 있습니다.

### 귀납: 관찰에서 패턴 찾기

귀납은 서로 다른 메시지나 시점의 관찰을 트렌드, 선호, 규칙, 작업 교훈으로 결합합니다. 단일 이벤트는 내구성 있는 패턴이 될 수 없습니다. 현재 규칙은 서로 다른 증거 항목이 최소 2개 있어야 합니다.

결과는 해당 토픽을 소유한 엔트리를 업데이트합니다. Brain은 관찰마다 새 memory를 하나씩 만들지 않습니다. 이후의 증거는 귀납 결과를 좁히거나, 수정하거나, 기각할 수 있습니다.

Dreaming 결과는 더 완전하다고 해서 권위가 높아지지 않습니다. 새로운 원자재가 다음 실행을 촉발하며, 모든 내구성 있는 결론은 소스로 돌아가는 경로를 유지합니다.

## Memory가 압축되고 진화하는 방식

Stage B는 하나의 자료 배치에 대해 다음과 같은 일반적인 순서를 사용합니다:

1. 소스 메시지, task outcome, 임시 상태를 분리합니다.
2. 각 자료 항목의 안정적인 토픽을 찾고 현재 엔트리를 엽니다.
3. 새 증거를 현재 내용과 비교하고 가능하면 기존 토픽을 업데이트합니다.
4. 쓸모없어진 내용을 다시 쓰고 유용한 적용 날짜와 소스를 유지합니다.
5. 요약, 별칭, 명시적 관계, pinned memo, 관련 Skill 경험을 업데이트합니다.
6. 지식, Skill Overlay, audit, 커서 변경을 하나의 트랜잭션으로 커밋합니다.

앞서 든 음식 예에서, 현재 엔트리는 설명 없이 “바베큐를 좋아함”과 “채식주의자임”을 나란히 적어서는 안 됩니다. 이전 선호가 특정 날짜 이전에 적용되었고 현재 선호가 그 이후에 적용된다고 밝힐 수 있습니다.

Brain은 “최신 메시지가 항상 이긴다”를 사용하지 않습니다:

| 새로운 상황 | Brain의 처리 |
|---|---|
| 명시적 수정 또는 새로운 적용 날짜 | 옛 내용을 다시 쓰고 시간 경계를 밝힙니다 |
| 신뢰할 수 있는 두 소스가 서로 다름 | 둘 다 유지하고 충돌을 **미해결(unresolved)**로 표시합니다 |
| 검증되지 않은 주장 | **미검증(unverified)**으로 표시합니다 |
| 증거에 기반한 Agent 판단 | 조건부 표현을 사용하고 Dreaming 작성자와 날짜를 유지합니다 |
| 사람의 수정 | 사람의 수정을 유지합니다. 오래된 복원이 이후의 편집을 덮어쓸 수 없습니다 |

현재 릴리스는 이 결정을 위해 하나의 수치 신뢰도 점수를 사용하지 않습니다. 시각, 소스, 발화자, 명시적 수정, 미해결 상태는 내용과 audit 기록에 계속 표시됩니다.

## 대화뿐 아니라 외부 지식도 학습

**Knowledge → Materials → Ask an Agent to learn a source**를 엽니다. Agent와 memory scope를 선택한 다음 다음 소스 유형 중 하나를 제공합니다:

| 소스 유형 | Brain의 처리 |
|---|---|
| **붙여넣은 텍스트** | 편집 가능한 외부 문서 엔트리를 만듭니다 |
| **Web URL** | 페이지 본문을 가져와 편집 가능한 외부 문서 엔트리를 만듭니다 |
| **PDF 또는 기타 파일** | 변경 불가능한 소스 바이트를 저장한 다음 Agent에게 파일을 읽고 통합하도록 요청합니다 |

Brain은 학습 작업이 시작되기 전에 파일을 저장합니다. Worker를 사용할 수 없거나 학습 실행이 실패해도 소스는 유실되지 않습니다. 저장된 동일한 소스로 다시 시도할 수 있습니다.

소스는 증거이지 최종 지식이 아닙니다. Agent는 서로 다른 토픽을 집중된 엔트리에 배치하고 소스를 인용해야 합니다. 원본이 변경되면 소스를 다시 학습하거나 영향을 받은 엔트리를 수정하십시오.

외부 시스템의 이벤트도 신호 소스를 통해 Agent로 들어올 수 있습니다. 가격이나 재고처럼 빠르게 변하는 값은 작업 중에 소유 시스템에 직접 질의하십시오.

Brain은 안정적인 결론, 원인, 적용 날짜, 소스 경로를 유지해야 합니다.

인스턴스에 소스 Connector가 있으면 Brain은 버전이 관리되는 외부 문서를 동기화할 수도 있습니다. 문서는 읽기 전용 미러입니다. 소스가 변경되면 Brain이 문서를 교체하고, 소스가 삭제되거나 접근 권한을 잃으면 문서를 철회합니다.

<details>
<summary>고급: 소스 수명 주기 차이</summary>

붙여 넣은 텍스트와 가져온 웹 콘텐츠는 사람이나 Agent가 편집할 수 있는 일반 엔트리가 됩니다. 파일은 소스 바이트를 유지하며, 학습된 각 블록은 해당 파일을 인용해야 합니다.

Connector 미러는 외부 시스템에 속하므로 Ankole에서 편집할 수 없습니다. 소유 시스템에서 소스를 변경하십시오. 지역적 판단은 미러를 인용하는 별도의 엔트리에 넣으십시오.

소스를 제거해도 파생된 모든 지식이 무조건 제거되지는 않습니다. Brain은 무엇을 복원할 수 있는지 결정할 때 정확한 인용과 이후의 편집을 사용합니다. 사람이 나중에 변경한 내용을 오래된 자동 작업이 덮어쓸 수는 없습니다.

</details>

## Skill Overlay가 작업 방법을 개선합니다

Knowledge entry는 “지금 무엇이 사실인가?”에 답합니다. Skill은 “이런 종류의 작업은 어떻게 해야 하는가?”에 답합니다. 모든 작업 교훈을 지식 베이스에 넣으면 사실과 절차가 섞이게 됩니다.

따라서 Ankole은 Agent와 Skill마다 **Skill Overlay**를 저장합니다. Console에서는 **Skill experience**라고 부릅니다. 기본 제공 Skill에 추가되며 기본 Skill을 수정하지 않고 다른 Agent에도 영향을 주지 않습니다.

Agent는 작업하는 동안 경험을 추가할 수 있습니다. Dreaming은 수정, 오류 복구, 재사용 가능한 복잡한 절차에서 경험을 추출할 수도 있습니다. 다음에 Skill이 로드될 때 Agent는 기본 지침과 Overlay를 받습니다.

Dreaming은 활성화된 Skill만 업데이트할 수 있습니다. 새 Skill을 만들 수는 없습니다. 변경된 것이 없으면 업데이트를 내보내지 않습니다. 거의 중복된 내용을 추가하는 대신 기존 경험을 수정해야 합니다.

**Knowledge → Skill experience**를 열어 내용을 검사하십시오. 변경이나 제거에는 **Agent Library**를 사용하십시오. Skill이 비활성화되어 있으면 Overlay는 저장된 상태로 유지되지만 Agent 컨텍스트에는 들어가지 않습니다.

<details>
<summary>고급: Skill Overlay 작성 규칙</summary>

새 경험은 먼저 상황을 밝힌 다음 주의 사항을 밝힙니다. Dreaming은 날짜를 추가합니다. 기본적으로 한 상황은 최대 50 token이고 전체 Overlay는 최대 2,000 token입니다.

Dreaming은 중복이 심한 경험을 추가하는 대신 교체해야 합니다. 사람이 Overlay를 편집하는 동안 Dreaming이 Overlay를 변경했다면 콘텐츠 버전 검사가 오래된 저장을 거부합니다.

다이렉트 메시지나 기밀 channel의 자료는 전역 Skill Overlay를 업데이트할 수 없습니다. 비공개 콘텐츠가 다른 컨텍스트에서 Agent가 작업하는 방식을 바꿀 수는 없습니다.

</details>

## Agent가 memory를 회상하는 방식

각 턴은 작은 pinned memo를 받습니다. 검색 없이 적용되어야 하는 규칙만 포함하며 고정된 token 예산이 있습니다. Agent는 다른 모든 지식이 필요할 때 검색합니다.

하나의 `memory_search`는 현재 대화 범위 안에서 다음 경로를 실행합니다:

1. Knowledge entry 필드와 본문 블록에 대한 키워드 검색.
2. Knowledge 블록에 대한 벡터 검색.
3. 소스 채팅 메시지에 대한 키워드 검색.
4. 에피소드 요약에 대한 벡터 검색.

Brain은 네 가지 순위를 융합하고 시간 감쇠를 적용하며 선택적으로 reranker를 사용할 수 있습니다. 채팅은 전체 연령 감쇠를 받습니다. Knowledge는 제한된 감쇠를 받으며 최근에 편집되지 않았다는 이유만으로 사라지지 않습니다.

Brain은 채택된 후보만 펼칩니다. 에피소드는 소스 메시지를 펼칩니다. thread 안의 메시지는 thread를 펼칩니다. thread가 없는 메시지는 인접한 시간순 컨텍스트를 받습니다.

그런 다음 Brain은 가장 관련성 높은 항목을 전체 token 예산에 맞춥니다. 하나의 긴 후보를 제한하여 다른 모든 결과를 제거하지 못하게 합니다. Agent는 `memory_browse`를 사용해 전체 thread나 소스를 열 수 있습니다.

Embedding은 선택 사항입니다. 벡터 모델이 없어도 키워드 검색, 엔트리, audit, Dreaming은 계속 동작합니다. 누락되는 것은 동의어와 관련 표현에 대한 의미 회수뿐입니다.

## Memory scope가 가시성을 제어합니다

각 지식 항목에는 Agent 소유자와 store가 있습니다:

| 스토어 | 용도 |
|---|---|
| **Shared** | 여러 대화가 사용하는 회사 지식, 공통 규칙, 팀 정보 |
| **Agent self** | Agent의 pinned memo, 내구성 있는 역할 지식, 작업 방법 |
| **Direct message** | 한 사람과 Agent 사이의 내구성 있는 컨텍스트 |
| **Channel only** | 하나의 기밀 channel만 읽을 수 있는 자료 |

공유 channel은 기본적으로 Shared와 Agent-self 지식을 읽고 Shared에 씁니다. 다이렉트 메시지는 기본적으로 자체 비공개 store를 읽고 그 store에 씁니다.

[신호 라우팅 규칙](../signal-bindings/)의 **Memory scope**는 채팅 channel에 대해 Shared 또는 Channel-only memory를 선택합니다. 편의를 위해 고객 데이터나 격리된 프로젝트 자료를 Shared에 넣지 마십시오.

하나의 대화는 하나의 고정된 memory scope를 유지합니다. 변경된 신호 라우팅 규칙은 다음 대화부터 적용됩니다. Ankole은 기존 대화 콘텐츠를 새 가시성 경계로 옮기지 않습니다.

## Console의 장기 memory 기능

**Knowledge** 페이지에는 여섯 개의 탭이 있습니다. 모두 동일한 Owner Principal 선택기를 공유하지만 각 탭은 하나의 작업을 담당합니다:

| 탭 | 할 수 있는 일 |
|---|---|
| **Entries** | 현재 지식을 검색, 생성, 편집하고 큐레이션 가이드를 유지합니다 |
| **Materials** | 보관된 파일과 Connector 소스를 학습 및 동기화 상태를 포함해 검사합니다 |
| **Skill experience** | Dreaming이나 Agent가 작성한 Skill Overlay를 검사합니다 |
| **Status** | Dreaming, embedding, pinned memo, Job, 지식 품질을 확인합니다 |
| **Audit** | 지식 변경을 필터링, 미리 보기, 복원합니다 |
| **Dreaming** | 한 Agent에 대해 Stage B를 실행하고 Dreaming fitness를 검사합니다 |

### Entries와 큐레이션 가이드

1. **Knowledge → Entries**를 엽니다.
2. **Owner** Principal을 선택합니다.
3. 이름, 별칭, 요약, 본문으로 검색합니다.
4. 타입, store, 작성자, 업데이트 시각 필터가 필요하면 추가 필터를 엽니다.
5. 엔트리를 열고 블록, 소스, 관계를 검사합니다.

엔트리 편집기에는 **Edit**, **Projection**, **Audit** 탭이 있습니다. Edit는 메타데이터, 본문 블록, 관계를 변경합니다. Projection은 Agent가 읽는 Markdown을 보여주고 인용된 소스에 연결합니다.

본문 블록을 수정할 때는 이유를 입력하십시오. 각 블록은 최신 작성자와 버전을 유지합니다. 편집해도 기록은 제거되지 않습니다.

**Curation guide**는 엔트리 목록 위에 있습니다. 각 Principal은 self store에 가이드를 하나 가질 수 있으며 편집은 사람만 할 수 있습니다. 가이드는 Dreaming을 위한 도메인 타입, 페이지 임계값, 분류 체계, 업데이트 규칙을 정의합니다.

임시 진행 상황, 일회성 오류, 검증되지 않은 추측을 내구성 있는 지식으로 저장하지 마십시오.

### Materials와 Skill experience

**Materials** 탭은 보관된 바이너리 파일과 Connector가 관리하는 소스를 나열합니다. 붙여 넣은 텍스트와 웹 콘텐츠는 지식 엔트리가 되므로 Console은 이 목록에 추가하는 대신 새 엔트리를 엽니다.

보관된 파일을 열면 학습 상태를 검사하고, 변경 불가능한 원본을 다운로드하고, 실패한 학습 작업을 다시 시도하고, 해당 파일을 인용하는 엔트리를 열 수 있습니다.

**Skill experience** 탭은 읽기 전용 요약입니다. Skill Overlay를 변경하거나 제거하려면 **Edit in Agent Library**를 사용하십시오.

### Dreaming과 Dreaming fitness

**Knowledge → Dreaming**을 열고 Agent를 선택한 다음 **Run curation now**를 선택합니다. 이 작업은 선택한 Agent에 대해 Stage B만 실행합니다. channel 수준의 Stage A는 실행하지 않습니다.

결과에는 자료 수, 지식 작업 수, Skill experience 업데이트 수가 보고됩니다.

이 페이지에는 **Dreaming fitness**도 표시됩니다. 사람이 변경하거나 제거하지 않은 성숙한 Dreaming 블록 쓰기 비율을 측정합니다. 검토 신호이지 지식 정확도나 모델 품질 점수가 아닙니다.

### Audit와 복원

**Knowledge → Audit**을 엽니다. store, 작업, 실행 주체, Dreaming 실행, 날짜로 필터링할 수 있습니다.

복원 전에 이전 값과 이후 값을 미리 봅니다. 하나의 레코드를 복원하거나 여러 레코드를 선택해 한 번의 원자적 복원을 실행할 수 있습니다. 배치는 최신 것부터 실행됩니다. 현재 값이 하나라도 변경되었다면 전체 배치는 아무것도 쓰지 않습니다.

복원은 새 audit 기록을 만듭니다. 삭제된 엔트리는 audit trail을 유지하며 삭제 기록이 전체 엔트리를 복원할 수 있습니다.

검토 중에는 다음을 찾아보십시오:

- 내구성 있는 사실로 기록된 임시 상태;
- 여전히 결정에 영향을 줄 수 있는 만료된 규칙;
- 중복되거나 모순되는 엔트리;
- 소스가 없는 강한 주장;
- 쓸모없거나 중복된 Skill 경험.

### Status

**Knowledge → Status**는 장기 memory를 위한 단일 상태 화면입니다. 알림, 에피소드 및 엔트리 블록 벡터, 전역 embedding 구성, Stage A channel, Stage B, pinned memo 예산, 중단된 Job, knowledge lint를 표시합니다.

knowledge lint는 날짜가 있는 이름, 유사 중복 이름, 과대한 엔트리, 본문이 없는 엔트리를 집계합니다. 이 페이지는 문제를 보고합니다. 지식을 다시 쓰지는 않습니다.

## 고급: AppConfigure의 Brain 설정

<details>
<summary>Brain 설정 다섯 가지 보기</summary>

**AppConfigure**를 열고 **Brain** 그룹을 선택합니다. Console은 현재 다섯 가지 설정을 제공합니다:

| 설정 | 범위 | 용도 |
|---|---|---|
| `brain.knowledge` | 글로벌 | Pinned memo 예산과 회수 결과 수 |
| `brain.dreaming` | Global 기본값, Agent별 재정의 가능 | Stage A와 Stage B의 자격 조건과 실행 예산 |
| `brain.embedding` | 글로벌 | 단일 벡터 모델과 출력 차원 |
| `brain.search` | 글로벌 | 시간 감쇠와 선택적 reranking |
| `brain.sources` | 글로벌 | Connector 소스 폴링과 청킹 |

### `brain.knowledge`

| 필드 | 기본값 | 용도 |
|---|---:|---|
| `pinned_memo_max_tokens` | `1500` | 한 턴의 최대 pinned memo token 수 |
| `result_limit` | `10` | 최대 회수 후보 수 |

### `brain.dreaming`

Console은 전용 폼을 제공하며 **Stage A · channel episodes**와 **Stage B · Agent knowledge**를 분리합니다.

Stage A는 전역 값을 읽습니다:

| Console 필드 | 기본값 |
|---|---:|
| Channel quiet period | 30 minutes |
| Channel backlog rows | 200 |
| First-run lookback | 5 days |
| Window rows | 200 |
| Window tokens | 8,000 |
| Protected tail rows | 20 |
| Protected tail age | 360 minutes |

Stage B는 선택한 Agent의 유효 값을 읽습니다:

| Console 필드 | 기본값 |
|---|---:|
| Dreaming | 기본값을 따름. Agent에서는 활성화됨 |
| Curation quiet period | 30 minutes |
| Curation backlog rows | 50 |
| Material limit | 240 |
| Token limit | 0, 제한 없음을 의미함 |
| Knowledge operation limit | 0, 제한 없음을 의미함 |

**Read the full retained history**는 first-run lookback에 `null`을 저장합니다. 값이 `0`이면 현재 메시지부터 시작합니다. Stage A 값은 인스턴스에 적용되며, 한 번의 실행에서 선택된 프로세서 Agent에는 적용되지 않습니다.

### `brain.embedding`

Console은 활성화 스위치, **Embedding model Agent**, **Output dimensions**를 제공합니다. Agent 목록에는 `embedding` ModelProfile이 구성된 활성 Agent만 포함됩니다.

활성화한 다음 Agent를 선택하고 1부터 4096까지의 정확한 모델 벡터 크기를 입력하십시오. Knowledge 블록, 에피소드, 쿼리 벡터는 이 하나의 인스턴스 전체 벡터 공간을 사용합니다.

하나의 private deployment 인스턴스는 하나의 전역 벡터 공간을 사용합니다. 모델이나 차원을 변경한 후 Ankole은 오래된 벡터를 교체 대상으로 표시하고 백그라운드에서 다시 구축합니다.

### `brain.search`

| 필드 | 기본값 | 용도 |
|---|---:|---|
| `half_life_days` | `30` | 채팅 메시지의 시간 감쇠 반감기 |
| `knowledge_decay_floor` | `0.5` | Knowledge의 최소 시간 감쇠 배수 |
| `rerank_enabled` | `false` | 전역 reranker 활성화 |
| `rerank_model_agent_uid` | `null` | `rerank` ModelProfile을 제공하는 Agent |

rerank를 추가하기 전에 키워드 검색과 embedding 검색을 안정적으로 만드십시오. reranker는 회수할 때마다 모델 호출을 한 번 추가합니다.

### `brain.sources`

| 필드 | 기본값 | 용도 |
|---|---:|---|
| `enabled` | `true` | Connector가 관리하는 외부 소스 폴링 |
| `sync_interval_minutes` | `15` | 기본 동기화 간격 |
| `block_max_tokens` | `1500` | 동기화된 문서 블록 하나의 token 제한 |

이 설정은 Connector 동기화만 제어합니다. 수동으로 붙여 넣는 텍스트, 웹 가져오기, 파일 업로드는 비활성화되지 않습니다.

</details>

## Memory 상태 확인

**Knowledge → Status**를 엽니다. 먼저 **Active alerts**를 검사한 다음 페이지 순서대로 명명된 파이프라인을 검사합니다.

- **새 엔트리가 검색에서 누락됨:** 정확한 키워드로 시도해 보십시오. 의미 검색만 실패한다면 embedding 구성과 백로그를 검사하십시오.
- **Agent가 잘못된 것을 기억함:** 엔트리를 수정하십시오. 모든 변경을 취소해야 한다면 audit된 배치를 복원하십시오.
- **소스가 학습 상태에 남아 있음:** 소스 상태를 연 다음 Background Agent Jobs와 Worker를 검사하십시오.
- **같은 사실이 여러 번 나타남:** 중복 콘텐츠를 병합하고 유지된 엔트리에 공통 별칭을 추가하십시오.
- **Dreaming이 오랫동안 새 결과를 만들지 못함:** Agent `light` model profile과 상태 페이지의 사용 불가 사유 또는 실패한 작업을 확인하십시오.
- **그룹 자료가 잘못된 store에 나타남:** 해당 Channel Provider의 신호 라우팅 규칙과 memory scope를 검사하십시오.
