長期 memory の目的は、古いメッセージをより多く見つけることではありません。新しい証拠が届いたときに、Agent が世界と仕事に対する理解を改訂できるようにすることです。

2 年前に「バーベキューが好きだ」と言い、先月「今はベジタリアンだ」と言ったとします。ベクトル検索は両方の文を取り出せますが、2 番目の文が 1 番目の文の意味を変えることを知ることはできません。

Ankole の長期 memory モジュールのコードネームは **Brain** です。ソース証拠、整理された現在の知識、バックグラウンドの Dreaming、外部ソースの学習、Skill 経験をつなぎます。

## Memory はチャットのアーカイブではない

追記専用のチャットログは「誰が何を言ったか」に答えられます。「Agent が今何を信じるべきか」には答えられません。耐久性のある memory システムは、さらに 3 つの仕事をしなければなりません:

- **Memory compaction:** 複数の会話からの関連情報を、1 つの安定したトピックに統合します。
- **Memory evolution:** 新しい事実が届いたときに古い知識を改訂し、有用な時間境界を保持します。
- **Conflict handling:** 修正、ソースの不一致、検証されていない主張、Agent の推論を区別します。

Brain は 2 つの形態の知識を保持します。世界モデル (world model) は、人、組織、プロジェクト、ポリシー、およびそれらの関係のエントリを含みます。

推論 memory (Reasoning memory) は、Agent が帰納または演繹した判断、経験、作業方法を含みます。

## 長期 memory が含むもの

| 部分 | 答える質問 | 事実として直接使えるか |
|---|---|---|
| **チャットメッセージ** | 誰がいつ何を言ったか | 発言が行われたことだけを証明する |
| **外部ソース** | Agent が読んだテキスト、Web ページ、ファイルはどれか | 証拠にはなるが、各主張が誤っている可能性はある |
| **エピソード要約** | チャットの 1 つの区間は何についてだったか | いいえ。元のメッセージを特定するだけ |
| **知識エントリ** | 1 つのトピックについての現在の理解は何か | 現在の、引用付きの、修正可能な知識 |
| **固定メモ** | 毎ターン必ず存在すべき規則はどれか | 知識のコンパクトな投影 |
| **Skill Overlay** | ある Skill を使うとき、この Agent は何を覚えておくべきか | 1 つの Agent の手続き的経験 |

1 つの知識エントリは 1 つの安定したトピックを所有します。名前、タイプ、エイリアス、要約、プロパティ、ボディブロック、他のエントリへの関係を含められます。

エントリと関係は小さな世界モデルを形成します。例えば、人が組織に属する、プロジェクトがポリシーの影響を受ける、などです。Brain は証拠が述べる関係だけを保存します。モデルの推測はグラフのエッジになりません。

知識エントリは絶対の真実ではありません。Agent が見える証拠から形成した、最善の現在の理解です。ソース、著者、時刻、監査記録を保持します。

## Dreaming が情報を知識に変える

**Dreaming** は Brain のバックグラウンド整理プロセスです。メッセージごとにモデルを呼びません。会話が静まるか、十分な材料が蓄積されるまで待ちます。

このプロセスにより、Agent は完全な議論を見られ、モデルへの反復入力を減らせます。

### Stage A がエピソードインデックスを構築する

Stage A は各 channel の古いメッセージを処理します。1 つのチャットウィンドウを 1 つ以上のエピソードに分割します。ブランチは別のエピソードになり得ます。ノイズは無視できます。未完のトピックは次のバッチを待てます。

各エピソードには、トピック、要約、想定される将来の質問、結論、関連システム、結論を支える元のメッセージが含まれます。

エピソードはナビゲーションの補助にすぎません。Stage A はソースメッセージを置き換えたり削除したりしません。Agent がエピソードを引用または検証する必要があるとき、Brain は元のチャットを展開します。

Brain は、モデル出力が検証に合格した後にのみ、エピソードとカーソルを 1 つのトランザクションで保存します。失敗してもカーソルは進みません。セクションがスキップされた場合も、ソースメッセージはキーワード検索で利用可能なままです。

### Stage B が現在の知識を整理する

Stage B は 1 つの Agent の材料を処理します。最初にエピソード要約と軽量な材料インデックスをスキャンします。次に、関連するソースメッセージ、現在のエントリ、有効な Skill だけを開きます。

Stage B はエントリを作成でき、古いブロックを変更または削除でき、要約、エイリアス、プロパティ、関係を更新できます。また、固定メモを圧縮し、再利用可能な教訓を Skill Overlay に書き込みます。

チャットメッセージは、人、チーム、決定、外部世界についての主張を支えられます。タスクの成果は、Agent がタスクをどう実行したかのみを証明します。最終回答が正しかったことは証明しません。

通常の成功は自動的に経験になりません。人の修正、エラーリカバリ、非自明な複数ステップの成功は、再利用可能な作業教訓を正当化できます。

Stage B の変更はすぐに反映され、同じトランザクションで監査トレイルに入ります。人の監督は変更の後に行われます。人は、すべての整理アクションを事前に承認することなく、それを検査、修正、復元できます。

<details>
<summary>高度: デフォルトの Dreaming しきい値</summary>

Stage A は 30 分の静かな時間の後、または channel に 200 件のキューされたメッセージがあるときに実行されます。1 つのウィンドウは最大 200 行と約 8,000 token を含みます。最新の 20 行と最新の 360 分を保護します。

Stage B は 30 分の静かな時間の後、または 50 行の材料がキューされたときに実行されます。1 回の実行は最大 240 行の材料を読みます。両方のステージが `light` model profile を使います。

これらの値は、インスタンスまたは Agent の詳細な設定です。スキャンは頻繁に実行できますが、モデルを呼ぶのは資格条件が真のときだけです。

</details>

## 演繹 memory と帰納 memory

Brain は発言をコピーする以上のことをします。証拠の制約の下で新しい判断を形成できますが、演繹と帰納には異なる役割があります。

### 演繹: 既知の事実の意味を導出する

演繹は既知の事実と明示的な関係から始まります。「これらの事実は現在のタスクにとって何を意味するか」に答えます。Agent は関連するエントリとソースを再び開き、現在のコンテキストで推論します。

耐久性のある演繹は条件付きのままで、Dreaming の作者、日付、証拠を記録しなければなりません。推論された関係はグラフに入りません。ソースが述べる関係だけが構造化された関係になれます。

### 帰納: 観察をまたぐパターンを見つける

帰納は、異なるメッセージや時刻からの観察をトレンド、好み、規則、作業教訓に結合します。単一のイベントは耐久性のあるパターンになれません。現在の規則は少なくとも 2 つの異なる証拠アイテムを要求します。

その結果は、トピックを所有するエントリを更新します。Brain は観察ごとに新しい memory を作りません。後の証拠は、帰納を狭め、改訂し、拒否できます。

Dreaming の結果は、より完全だからといって権威が増すわけではありません。新しい生の材料が次の実行をトリガーし、すべての耐久性のある結論はソースへの経路を保持します。

## Memory がどう圧縮・進化するか

Stage B は 1 つの材料バッチに、この一般的な順序を使います:

1. ソースメッセージ、タスク成果、一時的な状態を分離します。
2. 各材料アイテムの安定したトピックを見つけ、現在のエントリを開きます。
3. 新しい証拠を現在の内容と比較し、可能なら既存のトピックを更新します。
4. 時代遅れの内容を書き直し、有用な発効日とソースを保持します。
5. 要約、エイリアス、明示的な関係、固定メモ、関連する Skill 経験を更新します。
6. 知識、Skill Overlay、監査、カーソルの変更を 1 つのトランザクションでコミットします。

前述の食事の例では、現在のエントリは説明なしに「バーベキューが好き」と「ベジタリアン」を並べてはなりません。古い好みが特定の日付より前に適用され、現在の好みがその後に適用される、と述べられます。

Brain は「最新のメッセージが常に勝つ」を使いません:

| 新しい状況 | Brain の処理 |
|---|---|
| 明示的な修正または新しい発効日 | 古い内容を書き直し、時間境界を述べる |
| 2 つの信頼できるソースが矛盾 | 両方を保持し、競合を**未解決**としてマーク |
| 検証されていない主張 | **未検証**としてマーク |
| 証拠からの Agent の判断 | 条件付きの言い回しを使い、Dreaming の作者と日付を保持 |
| 人の修正 | 人の改訂を保持する。古い復元は後の編集を上書きできない |

現在のリリースは、この決定に数値の信頼度スコアを 1 つ使いません。時刻、ソース、話者、明示的な修正、未解決の状態は、内容と監査記録の中で見えるままです。

## 会話だけでなく外部知識を学ぶ

**Knowledge → Materials → Ask an Agent to learn a source** を開きます。Agent と memory scope を選択してから、次のソースタイプのいずれかを提供します:

| ソースタイプ | Brain の処理 |
|---|---|
| **貼り付けたテキスト** | 編集可能な外部ドキュメントエントリを作成する |
| **Web URL** | ページ本文を取得し、編集可能な外部ドキュメントエントリを作成する |
| **PDF または他のファイル** | 不変のソースバイトを保存し、その後 Agent にファイルの読み取りと統合を依頼する |

Brain は学習タスクの開始前にファイルを保存します。Worker が利用できなくても、学習実行が失敗しても、ソースは失われません。同じ保存済みソースを再試行できます。

ソースは証拠であり、最終的な知識ではありません。Agent は別々のトピックを焦点を絞ったエントリに置き、ソースを引用すべきです。元の情報が変わったら、ソースを再学習するか、影響を受けるエントリを修正してください。

外部システムのイベントも、signal ソースを通じて Agent に入れられます。価格や在庫のように急変する値には、タスクの実行中に所有システムへクエリしてください。

Brain は安定した結論、原因、発効日、ソース経路を保持すべきです。

インスタンスにソース Connector がある場合、Brain はバージョン管理された外部ドキュメントも同期できます。ドキュメントは読み取り専用のミラーです。ソースが変わると Brain はそれを置き換え、ソースが削除されるかアクセスを失うと引き下げます。

<details>
<summary>高度: ソースのライフサイクルの違い</summary>

貼り付けたテキストと取得したウェブコンテンツは、人や Agent が編集できる通常のエントリになります。ファイルはソースバイトを保持し、学習された各ブロックはそのファイルを引用しなければなりません。

Connector ミラーは外部システムに属し、Ankole では編集できません。ソースは所有システムで変更してください。ローカルの判断は、ミラーを引用する別のエントリに入れてください。

ソースの削除は、派生した知識を盲目的に削除しません。Brain は、何を復元できるかを決めるときに、正確な引用と後の編集を使います。古い自動アクションは、人が後で変更した内容を上書きできません。

</details>

## Skill Overlay が作業方法を改善する

知識エントリは「今何が真実か」に答えます。Skill は「この種の仕事はどう行うべきか」に答えます。すべての作業教訓を knowledge ベースに入れると、事実と手順が混ざります。

そのため Ankole は、各 Agent と Skill に **Skill Overlay** を保存します。Console では **Skill experience** と呼びます。それは組み込み Skill に追加され、ベース Skill を変更せず、別の Agent にも影響しません。

Agent は作業中に経験を追加できます。Dreaming は、修正、エラーリカバリ、再利用可能な複雑な手順から経験を抽出することもできます。次回 Skill がロードされるとき、Agent はベースの指示と Overlay を受け取ります。

Dreaming は有効な Skill のみを更新できます。新しい Skill を作成できません。何も変わらない場合は更新を発行しません。ほぼ重複を追加するのではなく、既存の経験を改訂しなければなりません。

**Knowledge → Skill experience** を開いて内容を確認してください。変更や削除には **Agent Library** を使ってください。Skill が無効の場合、Overlay は保存されたままですが、Agent のコンテキストには入りません。

<details>
<summary>高度: Skill Overlay の書き込み規則</summary>

新しい経験はまず状況を述べ、次に注意事項を述べます。Dreaming は日付を追加します。1 つの状況はデフォルトで最大 50 token、Overlay 全体は最大 2,000 token です。

Dreaming は、高度に重複する経験を追加ではなく置き換えなければなりません。人が編集している間に Dreaming が Overlay を変更した場合、コンテンツの版チェックが古い保存を拒否します。

DM や機密 channel からの材料は、グローバルな Skill Overlay を更新できません。私的な内容が、別のコンテキストで Agent の働き方を変えてはなりません。

</details>

## Agent が memory をどう想起するか

各ターンは小さな固定メモを受け取ります。検索なしで適用しなければならない規則だけを含み、固定の token 予算を持ちます。Agent は他のすべての知識を、必要なときに検索します。

1 回の `memory_search` は、現在の会話スコープ内で次のルートを実行します:

1. 知識エントリのフィールドとボディブロックのキーワード検索。
2. 知識ブロックのベクトル検索。
3. ソースチャットメッセージのキーワード検索。
4. エピソード要約のベクトル検索。

Brain は 4 つのランキングを融合し、時間減衰を適用し、オプションの reranker を使えます。チャットは完全な経過時間減衰を受けます。知識は制限付きの減衰を受け、最近編集されていないからといって消えません。

Brain は勝者候補だけを展開します。エピソードはソースメッセージを展開します。スレッド内のメッセージはスレッドを展開します。スレッドのないメッセージは、近くの時系列コンテキストを受け取ります。

Brain は次に、最も関連性の高いアイテムを合計 token 予算に収めます。1 つの長い候補を制限し、他のすべての結果を除去しないようにします。Agent は `memory_browse` を使って完全なスレッドやソースを開けます。

Embedding はオプションです。ベクトルモデルがなくても、キーワード検索、エントリ、監査、Dreaming は機能します。欠ける機能は、同義語や関連する表現の意味的想起です。

## Memory scope が可視性を制御する

各知識アイテムは Agent オーナーとストアを持ちます:

| ストア | 使用目的 |
|---|---|
| **Shared** | 複数の会話が使う会社の知識、共通規則、チームの事実 |
| **Agent self** | Agent の固定メモ、耐久性のある役割知識、作業方法 |
| **Direct message** | 1 人のユーザーと Agent の間の耐久性のあるコンテキスト |
| **Channel only** | 1 つの機密 channel だけが読める材料 |

共有 channel は Shared と Agent-self の知識を読み、デフォルトで Shared に書き込みます。DM は私用ストアも読み、デフォルトでそのストアに書き込みます。

[signal routing rule](../signal-bindings/) の **Memory scope** は、chat channelの Shared または channel-only memory を選択します。便宜のため、顧客データや分離されたプロジェクト材料を Shared に置かないでください。

1 つの会話は 1 つの固定 memory scope を保ちます。変更された signal routing rule は次の会話に適用されます。Ankole は古い会話のコンテンツを新しい可視性の境界を越えて移動しません。

## Console の長期 memory 機能

**Knowledge** ページには 6 つのタブがあります。同じオーナー Principal セレクターを共有しますが、各タブは 1 つのタスクを所有します:

| タブ | できること |
|---|---|
| **Entries** | 現在の知識の検索、作成、編集、整理ガイドの維持 |
| **Materials** | 保持されたファイルと Connector ソースの検査（学習または同期状態を含む） |
| **Skill experience** | Dreaming や Agent が書いた Skill Overlay の検査 |
| **Status** | Dreaming、embedding、固定メモ、Job、知識品質の確認 |
| **Audit** | 知識変更のフィルタ、プレビュー、復元 |
| **Dreaming** | 1 つの Agent の Stage B を実行し、Dreaming fitness を検査する |

### Entries と整理ガイド

1. **Knowledge → Entries** を開きます。
2. **Owner** Principal を選択します。
3. 名前、エイリアス、要約、ボディで検索します。
4. タイプ、ストア、作者、更新時刻のフィルタが必要なときは、追加のフィルタを開きます。
5. エントリを開き、ブロック、ソース、関係を検査します。

エントリエディタには **Edit**、**Projection**、**Audit** タブがあります。Edit はメタデータ、ボディブロック、関係を変更します。Projection は、Agent が読む Markdown と引用されたソースへのリンクを表示します。

ボディブロックを修正するときは理由を入力してください。各ブロックは最新の作者とバージョンを保持します。編集は履歴を削除しません。

**Curation guide** はエントリリストの上にあります。各 Principal は自分の self ストアに 1 つのガイドを持て、編集できるのは人だけです。ドメインタイプ、ページしきい値、分類法、Dreaming の更新規則を定義します。

一時的な進捗、一度きりのエラー、検証されていない推測を、耐久性のある知識として保存しないでください。

### Materials と Skill experience

**Materials** タブは、保持されたバイナリファイルと Connector 管理のソースを一覧します。貼り付けたテキストとウェブコンテンツは知識エントリになるため、Console はこのリストに追加する代わりに新しいエントリを開きます。

保持されたファイルを開いて、学習状態の検査、不変のオリジナルのダウンロード、失敗した学習タスクの再試行、それを引用するエントリのオープンができます。

**Skill experience** タブは読み取り専用の要約です。Skill Overlay の変更・削除には **Edit in Agent Library** を使ってください。

### Dreaming と Dreaming fitness

**Knowledge → Dreaming** を開き、Agent を選択し、**Run curation now** を選択します。この操作は選択した Agent の Stage B だけを実行します。channel レベルの Stage A は実行しません。

結果は、材料数、知識操作数、Skill 経験更新数を報告します。

ページは **Dreaming fitness** も表示します。成熟した Dreaming ブロック書き込みのうち、人が変更または削除しなかった割合を測定します。レビュー用のシグナルであり、知識精度やモデル品質のスコアではありません。

### Audit と復元

**Knowledge → Audit** を開きます。ストア、アクション、アクター、Dreaming 実行、日付でフィルタできます。

復元の前に前後の値をプレビューしてください。1 つのレコードを復元するか、複数のレコードを選択して 1 回のアトミック復元を実行できます。バッチは新しいものから実行されます。いずれかの現在値が変更されていた場合、バッチ全体は何も書き込みません。

復元は新しい監査レコードを作成します。削除されたエントリは監査トレイルを保持し、削除レコードから完全なエントリを復元できます。

レビュー中は次を探してください:

- 一時的な状態が耐久性のある事実として書かれている
- 期限切れなのに決定に影響しうる規則
- 重複または矛盾するエントリ
- ソースのない強い主張
- 時代遅れまたは重複した Skill 経験

### Status

**Knowledge → Status** は長期 memory の単一のヘルスサーフェスです。アラート、エピソードとエントリブロックのベクトル、グローバルな embedding 設定、Stage A channel、Stage B、固定メモの予算、スタックした Job、知識 lint を表示します。

知識 lint は、日付付きの名前、ほぼ重複する名前、大きすぎるエントリ、本文のないエントリを数えます。ページはこれらの問題を報告します。知識を書き換えはしません。

## Memory の健全性を確認する

**Knowledge → Status** を開き、最初に **Active alerts** を確認し、次にページ順で名前付きパイプラインを確認してください。

- **新しいエントリが検索にない:** 正確なキーワードを試してください。意味検索だけが失敗する場合は、embedding 設定とバックログを確認します。
- **Agent が誤ったことを記憶している:** エントリを修正してください。その変更をすべて取り消す必要がある場合は、監査されたバッチを復元します。
- **ソースが学習中のまま:** ソースの状態を開き、次に Background Agent Jobs と Worker を確認します。
- **同じ事実が複数回現れる:** 重複するコンテンツを統合し、保持されたエントリに共通エイリアスを追加してください。
- **Dreaming が長時間新しい結果を出さない:** Agent の `light` model profile と、ステータスページの利用不可理由または失敗タスクを確認してください。
- **グループ材料が誤ったストアに現れる:** その Channel Provider の signal routing rule と memory scope を確認してください。
