Brain は Pod のページや会話から、検索可能な事実、判断、出来事、関係を抽出します。人と Agent は Pod で同じ知識を編集し、Brain は根拠の出所と主張の更新履歴を管理します。

## Pod で知識を編集する

**Meta Ankole → Brain** には組織の知識グラフとオントロジーの分類を表示します。知識項目は Markdown、業務属性、参照、版履歴を扱えます。人は Pod で編集し、Agent は Brain の `write_object` を使います。移動やタイトル変更でもページ ID は変わりません。分類はオントロジーが、内部の人物と Agent のプロフィールは Principal のライフサイクル処理が管理します。

ページの知識パネルには、閲覧者がアクセスできる事実、タイムライン、被リンク、予測評価を表示します。Console の **Objects** 一覧からも Pod のページを開けます。

| 入力経路 | 保存される内容 |
| --- | --- |
| Agent の `remember` 呼び出し | 根拠と出所ノードを持つ、独立した Fact または Take |
| Pod のページ編集 | 確定した版に対応する検索用テキストとページ参照 |
| 会話の学習 | 対象となる個人チャットやグループ会話の事実、判断、約束 |
| ファイルまたは URL の Source 登録 | Pod の知識ページと、設定に応じて抽出される主張 |

共有された Pod の業務内容は検索対象となり、`extract_facts` で事実抽出を有効にできます。これには、Ankole がテキストを抽出できるファイル（PDF、Office・OpenDocument 文書、スプレッドシート、CSV、プレーンテキスト）も含まれます。Brain はファイルの本文をページ、スライド、シート、見出しごとに検索します。ファイルが Brain ツリー内にあるか、ファイルのページ自体または上位のページで `extract_facts` が有効な場合は、そのファイルを出典とする事実とタイムラインの出来事も抽出します。スプレッドシートからは行ごとの事実ではなく、シートと列の要約を作成します。テキストレイヤーのないスキャン PDF のページは検索できません。Skill パッケージと Agent の指示規約は Meta Ankole で独立して保存・管理し、Brain の検索や事実抽出とは分離します。

## 事実と根拠を区別する

**Fact** は、確信度、日時、根拠、主張者を伴う観察です。**Take** は、後から評価できる重み付きの判断や予測です。**Timeline** は日付のある出来事を表します。型付きリンクでページ同士の関係を記録します。

主張と出来事には出所ノードが必須です。対象ページは省略できるため、会話中の約束を記録するためだけに別の人物や案件ページを作る必要はありません。主張者は「誰の見解か」、対象は「何についての見解か」を表します。

## 閲覧範囲と共有

知識の閲覧には Drive と Pod の現在の権限を使います。単一ページの共有と、配下を含むコンテナの共有を区別します。タイトル、プロパティ、本文、主張、出来事は同じ権限境界に従います。公開企業についての主張でも、非公開の会話から得た根拠はその会話の閲覧範囲にとどまります。

Agent の読み取り範囲は Agent と質問者の権限の共通部分です。グループの厳格な開示モードでは、その場にいる全参加者の権限も確認します。緩和モードでは Agent と質問者を確認します。共有や所属の変更は、その後の読み取りに即座に反映されます。

会話からの自動抽出では、会話の Drive ルートを出所にします。`remember` は通常、現在のリクエストの出所を使います。Agent は `AGENTS.md` の組織規則に従って、アクセスできる別の出所ノードを指定することもできます。

## タスクで記憶を使う

会話の開始時やコンテキスト圧縮後には、Brain が参加者、言及された対象、現在の事実、未完了の約束をまとめて渡します。続くテキストのやり取りでは、名前に一致するページの手掛かりを渡します。

| ツール | 用途 |
| --- | --- |
| `remember` | Fact または Take を 1 件記録する |
| `recall` | 主張、対象の概要、本文やタイムラインの抜粋を検索する |
| `entity` | 対象について閲覧可能な事実と関係を確認する |
| `whoknows` | 話題に関係する人、Agent、組織を探す |
| `delta` | 指定期間に追加・失効した主張や出来事を確認する |
| `synthesize` | 閲覧できる根拠にもとづいて分析ページを書く |
| `metric_query` | 公開済みの指標定義を実行し、モデルを介さずに正確な値を返す |

Pod の読み取りでは、プロパティ、概要、全文を選べます。概要には導入文と見出しを残し、長い表やコードを折り畳みます。詳細が必要な場合は全文を読み込みます。同じ名前が複数ある場合は候補を提示します。

`/drive/Brain` は現在の開示範囲を反映した読み取り専用ビューです。Agent は `write_object` に分類または項目 ID、Markdown、基準となる版を渡して作成・更新します。直接編集する権限がなければ Action Card を提案し、権限のある人が承認します。Skill と指示規約は人が [Meta Ankole](../agent-library/) で管理します。

## 更新と運用

定期実行の **Dreaming** は根拠の整理、分析、タイムライン抽出、期限を迎えた Take の評価、矛盾の検出を行います。矛盾は Console で人が処理します。事実の古さは検索順位に反映しますが、保存済みの確信度は書き換えません。

ページからの抽出結果は、入力した版が現在の版と一致するときだけ確定します。Drive で出所を削除すると、その抜粋と派生した主張は直ちに検索対象から外れます。ゴミ箱、復元、完全削除、版履歴は Pod が管理します。登録 Source のアーカイブは以降の学習を停止し、Pod の内容を保持します。

**self-healing** は古い検索用テキストや埋め込みを再生成し、インデックスを確認して、未処理の会話を学習に回します。Console の **Claims**、**Contradictions**、**Sources**、**Search preview**、**Principal audit**、**Health** で内容や状態を確認できます。

Brain はテナントのシステム主体 `ankole_brain` としてモデルを呼び出します。有効な `light` プロファイルは抽出、`heavy` は分析とモデルを使う保守、`web_fetch` は URL の取得を担います。これらと `rerank` は Console のモデル設定で管理し、埋め込みモデルはサイト設定で指定します。任意のモデルが未設定でも、既存の知識や全文検索は利用できます。`brain.enabled` はツール、自動コンテキスト、バックグラウンド学習を制御し、保存済みの知識を削除しません。
