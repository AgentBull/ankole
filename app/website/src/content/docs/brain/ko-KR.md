Brain은 Pod 페이지와 대화에서 검색할 수 있는 사실, 판단, 사건, 관계를 추출합니다. 사람과 Agent는 Pod에서 같은 지식을 관리하고, Brain은 근거의 출처와 주장이 바뀐 이력을 기록합니다.

## Pod에서 지식 관리하기

**Meta Ankole → Brain**은 조직 지식 그래프와 온톨로지 분류를 보여 줍니다. 지식 항목은 Markdown, 업무 속성, 참조와 버전 이력을 지원합니다. 사람은 Pod에서 편집하고 Agent는 Brain의 `write_object`를 사용합니다. 항목을 이동하거나 제목을 바꿔도 페이지 ID는 유지됩니다. 분류는 온톨로지가 관리하며 내부 사람과 Agent 프로필은 Principal 수명 주기 작업이 관리합니다.

페이지의 지식 패널에는 현재 사용자가 볼 수 있는 사실, 타임라인, 역방향 링크, 예측 평가가 표시됩니다. Console의 **Objects** 목록에서도 해당 Pod 페이지를 열 수 있습니다.

| 입력 경로 | 결과 |
| --- | --- |
| Agent의 `remember` 호출 | 근거와 출처 노드를 갖춘 독립적인 Fact 또는 Take 한 건 |
| Pod 페이지 편집 | 확정된 페이지 버전에 맞춘 검색 구절과 페이지 참조 |
| 대화 학습 | 대상 개인 채팅과 그룹 대화의 사실, 판단, 약속 |
| 파일 또는 URL Source 등록 | Pod 지식 페이지와 설정에 따라 추출한 주장 |

공유된 Pod 업무 콘텐츠는 검색 대상이며 `extract_facts`로 사실 추출을 켤 수 있습니다. 여기에는 Ankole가 텍스트를 추출할 수 있는 파일(PDF, Office·OpenDocument 문서, 스프레드시트, CSV, 일반 텍스트)도 포함됩니다. Brain은 파일 본문을 페이지, 슬라이드, 시트, 제목 단위로 검색합니다. 파일이 Brain 트리 안에 있거나 파일 페이지 자체 또는 상위 페이지에서 `extract_facts`를 켠 경우에는 해당 파일을 출처로 하는 사실과 타임라인 이벤트도 추출합니다. 스프레드시트는 행마다 사실을 만드는 대신 시트와 열의 요약을 제공합니다. 스캔한 PDF 페이지에는 텍스트 레이어가 없으므로, Pod 또는 사이트에 OCR 모델을 설정한 경우에만 Ankole가 그 글자를 읽습니다. 설정하지 않으면 이 페이지는 검색할 수 없습니다. OCR 제공업체는 페이지마다 요금을 부과합니다. 새로 업로드된 PDF의 스캔 페이지는 자동으로 읽고, 이전에 업로드된 PDF는 관리자가 Console에서 요금에 동의한 경우에만 읽습니다. 휴지통에 있는 PDF와 휴지통으로 옮긴 폴더 안의 PDF는 읽지 않은 수에 포함하지 않고 읽지도 않습니다. 복원하면 이전에 업로드된 다른 PDF와 똑같이 처리합니다. 내용이 같은 파일은 한 Pod 안에서 한 번만 읽습니다. 파일의 복사본이나 다른 위치에 업로드한 같은 파일은 이미 읽은 글자를 그대로 사용합니다. Skill 패키지와 Agent 지침 규약은 Meta Ankole에서 독립적으로 저장·관리하며 Brain 검색 및 사실 추출과 분리됩니다.

## 사실과 근거 구분하기

**Fact**는 신뢰도, 시점, 근거, 주장자를 포함한 관찰입니다. **Take**는 나중에 평가할 수 있는 가중치를 가진 판단이나 예측입니다. **Timeline**은 날짜가 있는 사건을 기록합니다. 유형이 지정된 링크는 페이지 사이의 관계를 표현합니다.

주장과 사건에는 출처 노드가 반드시 있어야 합니다. 대상 페이지는 생략할 수 있으므로, 대화에서 나온 약속을 기록하기 위해 별도의 인물이나 프로젝트 페이지를 만들 필요는 없습니다. 주장자는 ‘누구의 견해인가’를, 대상은 ‘무엇에 관한 견해인가’를 나타냅니다.

## 읽기 권한과 공유

지식은 Drive와 Pod의 현재 권한을 사용합니다. 한 페이지만 공유하는 경우와 하위 항목까지 포함하는 컨테이너 공유를 구분합니다. 제목, 속성, 본문, 주장, 사건은 같은 접근 범위를 따릅니다. 공개 기업을 다루는 주장이라도 비공개 대화에서 얻은 근거는 해당 대화의 권한을 따릅니다.

Agent가 읽을 수 있는 범위는 Agent와 요청자 권한의 교집합입니다. 엄격한 그룹 공개 모드에서는 현재 참여 중인 모든 사람의 권한도 확인합니다. 완화 모드는 Agent와 요청자를 확인합니다. 공유 설정이나 소속이 바뀌면 이후 읽기에 즉시 반영됩니다.

대화에서 자동 추출한 지식은 해당 대화의 Drive 루트를 출처로 사용합니다. `remember`는 기본적으로 현재 요청의 출처를 사용하며, Agent는 `AGENTS.md`의 조직 규칙에 따라 접근 가능한 다른 출처 노드를 선택할 수도 있습니다.

## 작업에서 기억 사용하기

대화를 시작하거나 컨텍스트 압축 후 재개할 때 Brain은 참여자, 언급한 대상, 현재 사실, 미완료 약속을 정해진 분량 안에서 제공합니다. 이어지는 텍스트 대화에서는 이름이 일치하는 페이지의 단서도 제공합니다.

| 도구 | 용도 |
| --- | --- |
| `remember` | Fact 또는 Take 한 건 기록 |
| `recall` | 주장, 대상 카드, 본문 및 타임라인 구절 검색 |
| `entity` | 대상의 접근 가능한 사실과 관계 확인 |
| `whoknows` | 주제와 관련된 사람, Agent, 조직 찾기 |
| `delta` | 기간 내 추가되거나 만료된 주장과 사건 확인 |
| `synthesize` | 접근 가능한 근거를 바탕으로 분석 페이지 작성 |
| `metric_query` | 게시된 지표 정의를 실행하고 모델 없이 정확한 값을 반환 |

Pod 읽기는 속성, 개요, 전문을 제공합니다. 개요에는 도입부와 제목을 남기고 긴 표와 코드를 접습니다. 자세한 내용이 필요하면 전문을 읽습니다. 이름이 여러 대상과 일치하면 후보를 반환합니다.

`/drive/Brain`은 현재 공개 범위를 반영하는 읽기 전용 뷰입니다. Agent는 `write_object`에 분류 또는 항목 ID, Markdown, 기준 버전을 전달하여 생성하거나 수정합니다. 직접 편집 권한이 없으면 Action Card를 제안하고 권한 있는 사람이 승인합니다. Skill과 지침 규약은 사람이 [Meta Ankole](../agent-library/)에서 관리합니다.

## 지식 갱신과 운영

정기 **Dreaming**은 근거 정리, 분석 생성, 타임라인 추출, 기한이 된 Take 평가, 모순 탐지를 수행합니다. 모순은 운영자가 Console에서 처리합니다. 사실이 오래되면 검색 순위에 반영하지만 저장한 신뢰도는 바꾸지 않습니다.

페이지 추출 결과는 입력 버전이 현재 버전과 일치할 때만 확정됩니다. Drive에서 출처를 삭제하면 해당 검색 구절과 파생 주장은 즉시 검색 대상에서 제외됩니다. 휴지통, 복원, 영구 삭제, 버전 기록은 Pod가 관리합니다. 등록한 Source를 보관 처리하면 이후 학습을 멈추고 Pod 내용은 유지합니다.

**self-healing**은 오래된 검색 구절과 임베딩을 다시 만들고 인덱스를 확인하며 미처리 대화를 학습에 배정합니다. Console의 **Claims**, **Contradictions**, **Sources**, **Search preview**, **Principal audit**, **Health**에서 내용과 상태를 확인할 수 있습니다.

Brain은 테넌트의 `ankole_brain` 시스템 주체로 모델을 호출합니다. 유효한 `light` 프로필은 추출, `heavy`는 분석과 모델 기반 유지관리, `web_fetch`는 URL 가져오기에 사용됩니다. 이 프로필과 `rerank`는 Console의 모델 설정에서 관리하고 임베딩 모델은 사이트 설정에서 지정합니다. 선택 모델이 없어도 기존 지식과 전문 검색은 이용할 수 있습니다. `brain.enabled`는 도구, 자동 컨텍스트, 백그라운드 학습을 제어하며 저장한 지식을 삭제하지 않습니다.
