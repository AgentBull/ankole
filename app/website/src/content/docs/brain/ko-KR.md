Brain은 GBrain에서 영감을 얻고 Palantir 스타일의 온톨로지 위에 구축한 장기 기억 시스템으로, 조직의 최신 세계 모델을 유지합니다. 대화, 파일, 웹페이지에서 장기적 가치가 있는 정보를 추려 출처 추적이 가능한 조직 지식으로 구조화하며, Agent는 명확한 공개 범위 경계 안에서 이 지식을 회상하고 갱신하거나 망각할 수 있습니다.

Brain은 끝없이 쌓이는 채팅 로그를 그대로 기억으로 삼지 않고 사람, 조직, 사건, 판단과 그 사이의 관계에 대한 최신 상태를 유지합니다. 새로운 근거가 들어오면 기존 Claim이 보강되거나 수정·대체되며, 서로 충돌하는 근거가 발견되더라도 이전 상태와 근거 이력을 지우지 않고 사람이 검토할 수 있도록 남겨 둡니다.

동일한 Ankole 테넌트에 속한 모든 Agent는 Agent마다 별도 DB를 복제하지 않고 하나의 지식 공간을 공유합니다. 다만 개별 기억마다 명시적인 공개 범위가 지정되므로, 저장소를 공유한다고 해서 모든 지식이 무제한 공개되지는 않습니다.

## Brain이 학습할 수 있는 정보

지식이 축적되는 경로는 다음 네 가지입니다.

| 경로 | 결과 | 조건 |
| --- | --- | --- |
| Agent가 `remember`를 호출 | 단일 사실이나 판단이 즉시 영구 기억으로 저장됨 | Agent가 원자적인 단일 Claim, 출처, 유효한 공개 범위를 함께 지정해야 함 |
| Agent가 `put_page` 또는 `edit_page`를 호출 | 구조화된 대상 페이지를 새로 만들거나, 버전 이력과 `[[slug]]` Link 정합성을 유지한 채 기존 페이지 본문을 갱신함 | 기존 페이지 갱신에는 `expected_revision` 기반 낙관적 동시성 검증이 필요함. 다중 공개 범위가 섞인 페이지 편집은 호출자가 쓸 수 있는 Markdoc 구간 안에서만 적용되며 숨겨진 구역은 그대로 보존됨 |
| Signals 학습이 대화를 처리 | 별도의 `remember` 호출 없이도 장기적 가치가 있는 사실, 판단, 미완료 약속을 자동 추출해 학습함 | 대상 채널이 1:1 메시지(DM) 또는 IM 그룹이어야 하며 Brain 유지보수 Agent에 사용 가능한 `light` 프로필이 구성되어 있어야 함. 그룹 대화 학습에는 동기화된 구성원 권한 그룹도 필요함 |
| 운영자가 Source를 등록 | 파일이나 웹페이지가 검색 대상이 되고 본문에서 구조화된 Claim을 추출함 | Claim 추출에는 유지보수 Agent의 `light` 프로필이 필요함. 파일은 배포 환경에서 읽을 수 있어야 하며 파일 및 수집 본문은 10 MiB 이하의 유효한 UTF-8 텍스트여야 함. URL 수집에는 유지보수 Agent의 `web_fetch` 프로필이 필요함 |

Signals 기반 자동 학습은 대상 채널이 일정 시간 유휴 상태가 되거나 대화가 마무리된 뒤에 메시지 묶음을 일괄 처리합니다. 이때 Agent의 내부 모델 추론 기록이 아니라 채널에 저장된 실제 대화 발언만 읽습니다. 1:1 대화에서 학습한 지식의 기본 공개 범위는 대화 상대방 개인으로 지정되고, 그룹 대화에서 학습한 지식의 기본 공개 범위는 해당 채널에 매핑된 구성원 권한 그룹으로 지정됩니다.

`remember` 호출이 한 번 성공하면 그 즉시 쓰기가 영구 확정됩니다. 이후 현재 실행 턴이 중간에 실패하거나 취소·재시도되더라도 이미 커밋된 기억은 롤백되지 않습니다. 즉, 확정된 기억은 최종 답변 전달 여부와 무관하게 보존되는 독립된 결과입니다.

운영자가 등록하는 각 Source에도 기본 공개 범위가 설정됩니다. 해당 지식을 실제로 참조해야 하는 대상에게 필요한 최소한의 범위만 부여하세요. 나중에 Source를 보관(archive) 처리하면 추가 학습은 멈추지만 이미 추출해 둔 지식은 삭제되지 않습니다.

## Brain이 지식을 표현하는 방식

Brain은 질문의 성격에 맞춰 적절한 단위로 답할 수 있도록 지식을 다섯 가지 구조로 나누어 보관합니다.

- **페이지(Page)**는 인물, 기업, 사건, 프로젝트, 문서, 개념처럼 고유한 실체 하나에 대한 현재 종합 설명입니다.
- **Fact**는 검증하고 갱신할 수 있는 단일 관찰 사실로서 신뢰도, 시점, 출처, 보유 주체(`holder`), 공개 범위를 갖습니다.
- **Take**는 사람이나 Agent 또는 Brain이 내린 판단, 예측, 전망, 가설입니다. 가중치를 가지며 추후 실제 결과에 비추어 채점하거나 확정할 수 있습니다.
- **Timeline**은 특정 대상에게 언제 어떤 사건이 일어났는지를 시간순으로 기록합니다.
- **Link**는 두 페이지 사이의 의미 관계를 연결합니다.

여기서 `holder`는 문장 속 화제가 아니라 해당 Claim을 주장하거나 보유한 사람 또는 Agent를 가리킵니다. 예컨대 Alex가 특정 공급업체를 신뢰하기 어렵다고 평가했다면, 그 Take의 `holder`는 공급업체가 아니라 의견을 제시한 Alex가 됩니다.

각 Claim에는 독립적으로 참·거짓이나 유효성이 바뀔 수 있는 단일 주장만 담습니다. Brain은 모든 Claim의 근거 출처를 보존할 뿐 아니라 이전 페이지 버전과 대체된 과거 Claim까지 이력으로 남깁니다. 따라서 내용을 수정하면 현재 요약 상태는 최신으로 바뀌지만 그 결론에 이르기까지의 형성 과정은 지워지지 않습니다.

## Agent가 기억을 사용하는 방식

Brain은 두 가지 경로로 관련 기억을 대화에 자동 주입합니다. 대화가 처음 시작될 때와 컨텍스트 압축 직후에는 대화 참여자, 최근 언급된 주요 대상, 핵심 유효 Fact, 미완료 약속을 추려 크기 제한이 적용된 컨텍스트 팩을 조립합니다. 또한 매 텍스트 턴마다 새 메시지에 등장한 고유명사와 일치하는 페이지가 있으면 이를 Agent에게 함께 알려 줍니다.

이 자동 주입 단계에서는 별도의 추론 모델을 호출하지 않으며, 만약 조회가 시간 초과되거나 실패하더라도 빈 결과를 반환해 현재 턴을 막힘없이 이어 갑니다. 회상된 기억은 참고용 배경 정보일 뿐 강제 명령이 아니며 시점에 따라 다소 오래되었거나 불완전할 수도 있습니다.

업무 수행 중 능동적으로 기억을 조회하거나 관리해야 할 때 Agent는 다음 도구를 호출합니다.

| 도구 | 결과 |
| --- | --- |
| `remember` | 출처와 공개 범위를 지정해 원자적인 Fact 또는 Take 하나를 기록함 |
| `put_page` | 구조화된 페이지를 새로 만들거나 `expected_revision` 검증 아래 단일 공개 범위 페이지의 전체 본문을 교체함 |
| `edit_page` | `expected_revision` 검증 아래 호출자가 쓸 수 있는 Markdoc 구간 안에서 부분 치환을 적용하고 간결한 diff를 반환함 |
| `learn_source` | 단일 웹 URL을 Source로 등록하고 백그라운드 학습을 시작함 |
| `recall` | 가지치기되거나 삭제된 페이지를 제외하고, 지정된 토큰 한도 안에서 유효 Fact와 Take를 우선 반환한 뒤 별칭이 일치하는 대상 카드와 관련 페이지 본문 발췌를 반환함 |
| `get_page` | slug나 자연어 이름으로 공개 범위에 맞춰 필터링된 전체 페이지(`revision` 및 선택적 Markdoc `content` 포함)를 읽음(이름이 모호하면 임의 추측 대신 후보 목록을 반환) |
| `entity` | 핵심 Fact, 주요 관계, 백링크 수를 요약한 대상 카드를 반환함 |
| `whoknows` | 현재 열람 가능한 지식을 바탕으로 특정 주제를 잘 아는 사람, Agent, 조직의 순위를 산출함 |
| `delta` | 지정한 기간 동안 새로 추가되거나 만료된 Claim 및 Timeline 이벤트를 집계해 보고함 |
| `synthesize` | 회상한 근거, 상충하는 주장, 미해결 공백을 종합해 특정 질문에 답하는 영구 분석 페이지를 새로 작성함 |
| `forget` | 사유를 기록한 뒤 Fact 만료, Take 비활성화, 또는 페이지 소프트 삭제를 수행함 |

### Brain에서만 검색되는 Skill 발견하기

기본 배포되는 Skill 가운데에는 특정 업무를 만났을 때만 참고하면 되는 표준운영절차(SOP)나 전문 방법론이 있습니다. 이러한 Skill에 `brain-recall-only: true`를 선언해 두면 매 프롬프트에 실리는 상시 Skill 카탈로그에서는 빠지고 필요할 때 Brain 검색을 통해 찾아 쓸 수 있습니다.

Brain은 해당 Skill의 `name`, `description`, `tags`만 추려 `lazyload-agent-skills/<skill-name>` 경로의 `world` 범위 발견 레코드로 인덱싱하며, 실제 Skill 본문과 부속 파일 및 Agent별 교훈은 원래 저장소에 그대로 두고 `skill_view`로 읽어들입니다. `recall` 결과에 이 발견 레코드가 나타나면 Agent가 `skill_view`를 호출하며, 로더는 `ankole-runtime` 제약을 적용해 현재 실행 표면과 호환되면 지침을 로드하고, 메인 Agent가 백그라운드 전용 Skill을 조회하면 Job 위임 안내를 돌려주며, 그 외 호환되지 않는 접근은 거부합니다. 이 레코드에 대해 `get_page`를 호출하더라도 내부적으로 `skill_view`로 위임되어 동일한 결과를 반환합니다.

검색 후보를 추릴 때 Brain은 호출한 Agent의 현재 Agent Plugin 및 Skill 유효 활성화 상태를 먼저 확인하므로, 비활성화된 Skill은 검색 결과에 노출되지도 않고 로드할 수도 없습니다. 다만 테넌트 공유 발견 레코드 자체는 삭제하지 않으므로 나중에 다시 활성화하면 재인덱싱 없이 즉시 복원됩니다.

사이트에 임베딩 모델이 구성되어 있으면 전문(BM25) 검색 후보와 벡터 유사도 후보를 하이브리드로 결합하며, 테넌트에 리랭크 모델까지 구성되어 있으면 결합된 후보들의 순위를 한 번 더 정밀하게 재정렬합니다. 임베딩 모델이 없어도 전문 검색만으로 정상 동작하며, 리랭크 모델이 없으면 하이브리드 결합 순서를 그대로 사용합니다.

## 지식 경계와 공개 경계

보호 대상인 각 페이지 본문 구역과 Fact, Take, Timeline 이벤트에는 다음 세 가지 공개 범위 중 하나가 지정됩니다.

| 범위 | 접근할 수 있는 Principal |
| --- | --- |
| `world` | 같은 테넌트 내의 활성 정식 구성원(`membership = member`), 활성 Agent, 시스템 Principal(외부 게스트 `membership = guest`와 비활성 Principal은 제외) |
| `group:<name>` | 해당 권한 그룹에 현재 소속된 구성원 |
| `principal:<uid>` | 지정된 단일 Principal 본인만 |

Brain은 지식을 읽고 쓸 때마다 실시간으로 현재 권한 그룹 소속 여부를 조회합니다. 따라서 직원의 부서 이동이나 그룹 변경이 일어나면 과거 기억 행을 일일이 다시 쓰지 않아도 다음 회상부터 변경된 권한이 즉시 반영됩니다.

자신이 직접 작성한 Claim과 Timeline 이벤트는 작성자 본인이 언제나 열람할 수 있습니다. 또한 Agent의 소유자는 해당 Agent의 전용 비공개 범위 기억과 그 Agent가 작성하거나 보유(`holder`)한 지식을 감사 목적으로 열람할 수 있습니다. 다만 소유자 본인이 특정 그룹의 구성원이 아니라면, 단순히 Agent를 소유하고 있다는 이유만으로 그 그룹 범위(`group:<name>`)의 공유 지식까지 읽을 수는 없습니다.

여러 사람이 참여하는 그룹 대화방에서는 노출 사고를 막기 위해 추가 공개 범위 검사를 거칩니다.

- 기본값인 **엄격 모드(Strict)**에서는 현재 검사 대상인 대화 참여자 전원이 원래 열람 권한을 가진 경우에만 그룹 범위 기억을 인용합니다.
- **완화 모드(Relaxed)**에서는 질문한 발화자의 권한만 확인하며 대화방의 다른 참여자 때문에 조회 결과를 좁히지 않습니다.

1:1 대화(다이렉트 메시지)에서는 두 모드가 동일하게 동작합니다.

원본 Source나 대화 Channel 정보는 근거의 출처(provenance)를 남길 뿐, 그로부터 추출된 지식의 열람 권한을 결정하지는 않습니다. 열람 가능 여부는 오직 지식 항목 자체에 부여된 공개 범위를 따릅니다. 페이지의 slug, 제목, 유형, 존재 여부는 같은 테넌트 안에서 공통으로 보이지만 보호된 본문 구역과 구조화된 Claim은 호출자의 권한 범위에 맞게 필터링되어 반환됩니다.

Agent가 `remember` 도구를 능동적으로 호출할 때는 자신의 기밀 유지 정책(`ConfidentialityPolicy.md`)을 바탕으로 공개 범위를 판단합니다. 이는 모델의 최선형(best-effort) 분류이므로 간혹 판단이 틀릴 가능성도 있습니다. 플랫폼은 선택된 공개 범위를 결정론적으로 강제하지만 모델이 처음 고른 범위 자체가 완벽했다고 보장하지는 않으므로, 엄격한 규제 준수 격리가 필요한 업무에서는 기억 분류에만 의존하지 말고 [Principal과 권한 그룹](../principal-and-groups/)에서 애초에 Agent에 접근할 수 있는 주체를 분리하세요.

## 지식을 현재 상태로 유지하는 방식

Dreaming은 맥락 판단이 필요한 장기 지식을 주기적으로 정돈하고 통합하는 백그라운드 유지 관리 과정입니다. 실행 시 다음과 같은 작업을 수행합니다.

- 서로 연관된 여러 Fact를 묶어 Brain이 보유하는 신중한 종합 Take를 도출합니다.
- 여러 페이지에 걸친 공통 패턴을 찾아 근거 Link가 연결된 분석 노트를 작성합니다.
- 개체 간 관계와 주요 Timeline 이벤트를 추출합니다.
- 평가 기한이 도래한 예측성 Take를 실제 결과와 대조해 채점하고 보정(calibration) 요약을 갱신합니다.
- 상충 가능성이 있는 Claim 쌍을 감지해 표시합니다.

중요한 원칙으로, Dreaming은 감지된 모순을 임의로 덮어써서 무마하지 않습니다. 상충 내역을 그대로 기록해 두어 운영자나 담당자가 Console에서 직접 확인하고 해결하거나 기각할 수 있게 합니다.

개별 Fact는 지식 유형과 경과 시간에 따라 검색 노출 가중치가 완만하게 감쇠하지만, 저장된 신뢰도 수치나 원본 기록 자체가 변하지는 않습니다. 현재 유효 상태를 바꾸는 것은 명시적인 망각(`forget`) 작업뿐입니다. 망각을 실행하면 Fact는 만료 처리되고 Take는 비활성화되며 페이지는 소프트 삭제됩니다. 소프트 삭제된 페이지는 설정된 영구 정리 유예 기간 안에는 언제든 복원할 수 있으며, 만료되거나 대체된 Claim 역시 감사 및 예측 보정 이력으로 보존됩니다.

한편 Self-healing 작업은 추론 모델을 호출하지 않고 검색용 파생 인덱스만 점검·복구합니다. 오래된 청크와 임베딩을 재생성하고 검색 인덱스 정합성을 맞추며 아직 학습 배치가 돌지 않은 대상 채널을 찾아 큐에 넣습니다.

## Console에서 Brain 관리하기

Console의 **Brain** 메뉴에서는 축적된 지식 공간을 관점별로 나누어 조회하고 관리할 수 있습니다.

- **Objects**: 페이지 목록과 본문, 연결된 Fact·Timeline·Link, 버전 이력을 확인하고 롤백·삭제·복원을 수행합니다.
- **Claims**: 개별 Fact와 Take의 출처 및 현재 상태를 조회하고 내용 수정, 망각, 판정 확정 작업을 수행합니다.
- **Contradictions**: 사람이 검토해 정리해야 할 상충 Claim 후보 목록을 보여 줍니다.
- **Sources**: 파일과 웹 URL을 등록해 학습을 시작하거나 더는 갱신하지 않을 Source를 보관 처리합니다.
- **Search preview**: 특정 Principal과 공개 모드를 지정해 실제 회상(recall) 결과를 시뮬레이션해 봅니다.
- **Principal audit**: 특정 Principal이 보유자(`holder`), 작성자, 또는 공개 대상으로 지정된 모든 지식을 모아 감사할 수 있습니다.
- **Health**: 필요한 모델 프로필 준비 여부, 학습 대기열 적체, 임베딩 오류, 채널 학습 전제 조건, 검색 인덱스 상태를 한눈에 점검합니다.

테넌트 단위 Brain 설정에서는 유지보수 전담 Agent와 Rerank 모델을 지정하고, 사이트 단위 설정에서는 임베딩 모델과 벡터 차원 수를 지정합니다. 모든 Brain 내부 모델 호출은 지정된 유지보수 Agent 명의로 실행되며 토큰 사용량도 해당 Agent에 집계되므로 이 Agent는 항상 활성 상태를 유지해야 합니다. 만약 유지보수 Agent가 비활성화되면 Brain이 비정상(unhealthy) 상태를 알리고, 해당 Agent를 다시 켜거나 다른 활성 Agent로 교체할 때까지 모델 기반 학습과 URL Source 수집을 일시 중지합니다(이미 저장된 지식 조회와 키워드 검색은 계속 작동합니다).

| 소유자 및 설정 | 활성화되는 결과 |
| --- | --- |
| 유지보수 Agent의 `light` 프로필 | 대화 Signals 자동 학습 및 등록 Source에서의 Claim 추출 |
| 유지보수 Agent의 `heavy` 프로필 | 추론 모델이 필요한 Dreaming 통합 작업 및 `synthesize` 실행 |
| 유지보수 Agent의 `web_fetch` 프로필 | URL Source에서 본문 텍스트 수집(미설정 시 URL Source 학습 불가) |
| Brain 임베딩 모델 | 의미 기반 벡터 검색 및 Fact 의미 중복 판정 |
| Brain 리랭크 모델 | 하이브리드 검색 후보 결합 후 정밀 재정렬 |

선택적 모델 프로필 중 일부를 비워 두면 해당 보조 기능만 비활성화되며, 어떤 기능이 꺼져 있는지는 숨김없이 **Health** 화면에 명확히 표시됩니다. Brain 전체를 비활성화하더라도 기존에 저장된 지식은 손상되지 않고 기억 도구 노출과 컨텍스트 주입 및 백그라운드 유지 관리만 멈춥니다.

모든 테넌트에는 범용 엔티티·관계 어휘를 담은 `general` Schema Pack이 기본 설치되며, 초기 구성 시 사모펀드·벤처캐피털, 상장 주식 시장, 소비재, 법무, 소프트웨어 엔지니어링, 컨설팅 도메인 Pack을 추가로 선택할 수 있습니다. 설치된 온톨로지 어휘는 테넌트 내 모든 Agent가 함께 공유합니다.

## 현재 지원 범위

현재 자동 대화 학습은 1:1 메시지와 IM 그룹 채널의 메시지 묶음을 대상으로 동작하며, 직접 등록 가능한 외부 Source 유형은 파일과 웹 URL입니다. 별도의 SaaS 커넥터나 웹훅, 알림 스트림에서 곧바로 자동 학습하지는 않습니다.

마지막으로 Brain은 수집된 근거를 체계적으로 보관하는 시스템일 뿐 저장된 모든 진술이 절대적으로 참이거나 완전하다고 보증하지는 않습니다. 중요한 의사결정에 활용할 때는 반드시 기록된 출처, 시점, 신뢰도, 보유 주체(`holder`), 상충 여부를 함께 대조해 판단하세요.

전체 시스템 아키텍처 안에서의 위치는 [아키텍처](../architecture/)를, 세부 런타임 설정 키는 [AppConfigure](../app-configuration/)를, 실무 실행 이력에서 절차적 가드레일을 학습하는 구조는 [Skill Lessons](../skill-lessons/)를 참조하세요.
