Brain 是受 GBrain 启发、基于类 Palantir 本体论构建的企业长期记忆系统，负责维护持续更新的企业世界模型。它将日常对话、文档文件与网页中具有长期价值的信息整理为可溯源的组织知识，供 Agent 在明确的披露边界内按需召回、修正与遗忘。

Brain 不会把不断膨胀的原始聊天记录直接当作记忆，而是维护人物、组织、事件、判断及其相互关系的当前视图。随着新证据流入，系统可以印证、修正或取代既有断言（Claim），也可以揭示前后矛盾；原始依据与历史状态均完整保留，随时可供人工复核。

同一 Ankole 租户内的所有 Agent 共用同一个知识空间，系统不会为每个 Agent 单独复制一套私有数据库。虽然底层共用同一套存储，但每条记忆都受各自的披露范围严格限制，绝不会无限制公开。

## Brain 可以学习什么

Brain 支持四条知识写入与摄取路径：

| 路径 | 产出结果 | 前置条件 |
| --- | --- | --- |
| Agent 调用 `remember` | 一条客观事实或主观判断立即写入持久记忆 | Agent 必须提交单条原子 Claim，注明原始出处，并指定合法的披露范围 |
| Agent 调用 `put_page` 或 `edit_page` | 创建结构化对象页面，或在保留版本历史与自动对齐 `[[slug]]` 关联关系的前提下就地修订页面正文 | 更新既有页面需传入 `expected_revision` 进行乐观并发校验；多受众页面的片段修订严格限制在调用方允许写入的 Markdoc 范围内，自动保留其他受众的隐藏段落 |
| Signals 自动学习对话 | 无需显式调用 `remember`，自动从日常交流中提炼有长期价值的事实、判断与未决承诺 | 所在 Channel 必须是私聊或 IM 群聊，且负责维护 Brain 的 Agent 已配置可用的 `light` 模型档案；群聊还必须关联已同步的成员权限组 |
| 管理员注册 Source | 文档文件或网页进入检索索引，并自动抽取结构化 Claim | 抽取 Claim 需依赖维护 Agent 的 `light` 档案；文件须可由部署实例读取，文件与抓取后的网页正文均须为合法的 UTF-8 文本且不超过 10 MiB；抓取网页 URL 还需配置该 Agent 的 `web_fetch` 档案 |

当符合条件的聊天 Channel 进入空闲窗口或相关对话结束时，Signals 学习流程会自动切分并处理近期消息。该流程仅读取 Channel 的原始消息镜像，不读取 Agent 私有的内部推理记录；从私聊提炼出的知识默认仅对私聊对端人员可见，从群聊提炼出的知识默认面向该 Channel 关联的成员权限组开放。

一旦 `remember` 工具调用成功，对应记忆便已立即持久化落盘；即便当前对话回合后续报错、被取消或触发重试，这条已落盘的记忆也不会撤回。换言之，已确认写入的记忆是独立的持久化成果，不依赖于当轮最终回复是否成功发出。

每个注册的 Source 都须指定默认披露范围，建议遵循最小够用原则，选择既能覆盖目标读者又最收敛的范围。归档某个 Source 只会停止后续学习，不会删除此前已经提炼形成的知识。

## Brain 怎样表示知识

Brain 用五种结构化形态分别承载不同维度的认知：

- **页面（Page）**：保存某个稳定对象的当前综述，例如人物、公司、事件、项目、文档或业务概念。
- **Fact（事实）**：保存一条可核验、可更新的客观观察，同时记录置信度、时间、出处、持有者与披露范围。
- **Take（观点）**：保存某个人类成员、Agent 或 Brain 自身所持的判断、预测、押注或推论，并记录权重以便日后判分或结算。
- **Timeline（时间线）**：记录某个对象在什么时间发生了什么事件。
- **Link（关联）**：保存两个页面之间的语义关系。

字段 `holder`（持有者）表示“谁持有这条 Claim”，而不是“这句话在评价谁”。例如，张三认为某家供应商不可靠，系统会将其记为一条由张三持有的 Take，而非记在该供应商名下的 Fact。

每条 Claim 只包含一个可独立演变的原子断言。Brain 会完整保存每条 Claim 的出处，同时保留页面的历史版本与已被新结论取代的旧 Claim——修正认知只会更新当前结论，不会抹去认知的形成过程。

## Agent 怎样使用记忆

在对话执行期间，Brain 会通过两种轻量机制自动提供背景记忆：一是在会话启动及上下文压缩之后，自动组装一份受预算上限约束的上下文包，涵盖当前对话参与者、近期提及的对象、关键的当前 Fact 与未决承诺；二是在每个文本回合开始前，根据新消息中出现的名称提示相匹配的页面。

这两项自动注入过程本身不发起任何大模型调用；一旦组装超时或读取异常，系统会直接返回空结果让当前回合照常推进。需要注意，自动召回的内容仅作为参考背景提供，并非执行指令，且可能存在滞后或遗漏。

当任务需要显式检索或写入记忆时，Agent 可主动调用以下工具：

| 工具 | 作用 |
| --- | --- |
| `remember` | 记录单条原子 Fact 或 Take，并附上出处与披露范围 |
| `put_page` | 创建结构化页面，或在 `expected_revision` 校验下替换单一受众页面的完整正文 |
| `edit_page` | 在 `expected_revision` 校验下对调用方允许写入的 Markdoc 区间执行精确片段替换，并返回精简 diff |
| `learn_source` | 将一个公开网页 URL 注册为 Source，并在后台启动知识抽取 |
| `recall` | 在给定的 Token 预算内优先返回匹配的当前 Fact 与 Take，随后补充精确别名命中的实体卡片与相关页面片段 |
| `get_page` | 按页面 slug 或自然语言名称读取经权限裁剪后的完整页面（附带当前 `revision`，并可按需读取裁剪后的 Markdoc `content`）；若名称存在歧义则返回候选列表，绝不盲目猜测 |
| `entity` | 返回指定对象的摘要卡片，包含精选 Fact、关联关系与反向链接计数 |
| `whoknows` | 基于当前可见知识，对熟悉某个主题的人员、Agent 与外部机构进行排序 |
| `delta` | 汇总指定时间段内新增或已失效的 Claim 与 Timeline 事件 |
| `synthesize` | 综合召回的事实证据、争议断言与认知空白，针对特定问题撰写一篇出处可查的持久化综合分析页 |
| `forget` | 记录原因后，将指定 Fact 标记为失效、将 Take 归入历史（不再作为当前结论），或软删除某个页面 |

### 发现只通过 Brain 召回的 Skill

部分随产品发布的内置 Skill 属于特定领域的标准作业程序（SOP）或研究方法论，只有在当前任务确有需要时才应载入上下文。这类 Skill 可在清单中声明 `brain-recall-only: true`：平时从每轮提示词的默认 Skill 目录中省去，改由 Agent 在需要时通过 Brain 检索发现。

为此，Brain 仅将这类 Skill 的 `name`、`description` 与 `tags` 索引为一条 `world` 可见范围的轻量发现记录，路径命名为 `lazyload-agent-skills/<skill-name>`；而 Skill 的完整正文、附属文件以及 Agent 专属技能教训仍保存在各自原有的存储位置，通过 `skill_view` 按需读取。当 `recall` 命中这类记录时，Agent 会接着调用 `skill_view`：加载器会根据 `ankole-runtime` 校验当前运行位置是否兼容（若主 Agent 遇到仅限后台任务使用的 Skill，会收到引导其创建后台 Job 的提示；其余不兼容的读取请求则直接拒绝）。若对这类发现记录调用 `get_page`，系统同样会将其转交给 `skill_view` 并返回相同结果。

在筛选召回候选之前，Brain 会先结合当前 Agent 对各 Agent Plugin 和 Skill 的有效启用状态进行过滤：已关闭的 Skill 既不会被检索命中，也无法被加载。底层的共享发现投影不会因单个 Agent 关闭某项 Skill 而删除，因此日后重新启用时即可直接恢复访问，无需重建投影。

检索配置上，接入 Embedding 模型后，`recall` 会融合全文检索候选与向量语义候选；再接入 Rerank 模型后，系统还会对融合后的候选结果重新排序。未配置 Embedding 模型时，全文检索仍可独立工作；未配置 Rerank 模型时，则直接保留多路融合后的默认排序。

## 知识边界与披露边界

每个受保护的页面正文段落、每条 Fact、每条 Take 以及每个 Timeline 事件都绑定以下三种披露范围之一：

| 范围 | 允许访问的主体 |
| --- | --- |
| `world` | 当前租户内处于启用状态的正式成员（`membership = member`）、启用状态的 Agent 与系统级 Principal；外部访客（`membership = guest`）及已停用的 Principal 均不包含在内 |
| `group:<name>` | 对应权限组的当前在组成员 |
| `principal:<uid>` | 仅限指定的单个 Principal |

Brain 在每次读写时都会实时核验当前的权限组成员关系。因此，员工转岗或移出某个权限组后会立即影响其后续可召回的知识范围，无需逐条改写历史记忆记录。

知识作者本人始终有权读取自己写入的 Claim 与 Timeline 事件。Agent 负责人（Owner）有权审计该 Agent 的私有记忆范围，以及由该 Agent 编写或持有的知识；但负责人身份并不会自动穿透权限组边界——若某条共享知识限定了特定权限组可见，负责人本人仍须属于该权限组才能查阅。

在多人参与的群聊中，系统还会额外执行第二层披露核验：

- **严格模式（默认）**：只有当纳入检查的全体在场群成员原本都有权访问某条记忆时，Agent 才能在群内引用该记忆。
- **宽松模式**：仅核验当次提问者的访问权限，群内其他在场成员不会收窄可引用的记忆范围。

在单人私聊中，两种模式表现一致。

请注意，Source 或 Channel 仅用于记录“证据出自何处”，本身并不向读者授予学习产物的访问权——能否读取某条知识，完全取决于该知识自身的披露范围。在同一租户内，页面的 slug、标题、对象类型及存在性默认可见，而受保护的正文段落与结构化 Claim 则会严格按访问者的权限实时裁剪。

当 Agent 主动调用 `remember` 写入记忆时，会依据保密政策指引尽力判定合适的披露范围。由于这一步依赖大模型语义判断，仍可能出现分类偏差：应用层能够确定性地强制执行已选定的披露范围，但无法从数学上保证模型最初的范围分类绝对无误。对于有严格合规隔离要求的敏感场景，应通过[主体与权限组](../principal-and-groups/)直接管控谁有权与该 Agent 对话，而不应单纯依赖模型的记忆分类。

## 知识如何持续更新

Dreaming 是需要模型参与判断的后台知识维护窗口，负责定期完成以下整编工作：

- 将多条相关的 Fact 审慎归纳为一条由 Brain 持有的 Take；
- 挖掘跨页面的潜在模式，并撰写附带证据链接的综合分析；
- 抽取对象之间的关联关系与 Timeline 事件；
- 对已到期的历史 Take 判分结算，并更新预测校准摘要；
- 排查并标记潜在的前后矛盾。

遇到证据冲突时，Dreaming 绝不会私下静默覆盖或直接改写原有 Claim，而是将冲突登记在案，交由人工在 Console 中裁决或忽略。

随着时间推移，Fact 在召回排序中的权重会按类别与时间自然衰减，但权重衰减不会修改已存储的置信度数值或历史记录。只有显式执行遗忘操作，当前状态才会改变：对应 Fact 标记为失效、Take 不再作为当前结论（归入历史），或页面进入软删除状态。软删除的页面可在彻底清理期限内恢复；已失效和被取代的 Claim 仍会继续保留，供合规审计与预测校准使用。

后台自愈任务（Self-healing）则专门维护可搜索投影：自动修复过期的文档分块与向量嵌入、巡检搜索索引，并找出待补学的 Channel 消息切片。这项维护纯属确定性索引修复，不调用推理模型。

## 在 Console 中管理 Brain

Console 的 **Brain** 面板按业务视图组织整个知识空间：

- **Objects**：浏览知识页面、渲染后的正文、Fact、Timeline、关联关系、标签与历史版本，支持版本回滚、软删除与恢复。
- **Claims**：查看每条 Fact 与 Take 的原始出处和当前状态，提供人工纠正、显式遗忘与预测结算操作。
- **Contradictions**：集中展示待人工复核的证据冲突列表。
- **Sources**：注册本地文件或网页 URL、手动触发学习以及归档旧数据源。
- **Search preview**：模拟指定 Principal 身份与群聊披露模式预览实际召回结果。
- **Principal audit**：按指定 Principal 审计其作为持有者、作者或可见受众的全部关联知识。
- **Health**：监控各依赖模型就绪状态、待学习队列积压、向量化报错、聊天频道学习前置条件及索引投影健康度。

在模型配置上，租户级 Brain 设置负责指定“维护 Agent”与 Rerank 模型，站点级设置负责指定 Embedding 模型及其向量维度。Brain 内部发起的所有推理与抓取请求均以所选维护 Agent 的身份执行，并将 Token 用量计入该 Agent 名下。该维护 Agent 必须保持启用状态：一旦停用，Brain 会立即标记为不健康，并暂停全部模型调用与 URL Source 抓取，直至重新启用或改绑其他活跃 Agent；不过，已入库的存量知识与纯全文检索不受影响。

| 配置项 | 启用后支撑的能力 |
| --- | --- |
| 维护 Agent 的 `light` 档案 | Signals 对话自动学习与 Source 文档的 Claim 抽取 |
| 维护 Agent 的 `heavy` 档案 | 依赖深度推理的 Dreaming 归纳阶段与 `synthesize` 综合分析 |
| 维护 Agent 的 `web_fetch` 档案 | 提取 URL Source 的可读网页正文（未配置时跳过 URL Source 学习） |
| Brain 的 Embedding 模型 | 向量语义召回与 Fact 语义去重 |
| Brain 的 Rerank 模型 | 用交叉编码器对多路召回融合结果重新排序 |

缺少某项可选模型时，系统只会优雅关闭对应增强能力，并在 **Health** 页面如实标明哪些功能暂不可用，绝不隐瞒降级状态。若整体关闭 Brain 开关，系统会移除相关记忆工具与自动上下文注入并停掉后台维护任务，但已保存的知识数据仍完整保留。

每个租户初始化时都会默认安装 `general` 通用本体包（Schema Pack）以提供基础分类词表；首次初始化期间，管理员还可按需勾选私募股权与风险投资、公开市场投资、消费零售、法律服务、软件工程与管理咨询等行业本体包。同一租户内的所有 Agent 共享已安装的词表。

## 当前支持范围

目前，Brain 的对话自动学习仅覆盖单人私聊与外部 IM 群聊 Channel 的消息切片；手动注册 Source 仅支持文档文件与公开网页 URL，暂不支持直接从第三方连接器（Connector）、Webhook 或告警流中自动摄取知识。

最后需要强调：Brain 负责忠实归档各方证据与出处，但并不担保入库的每一条说法都绝对客观完备。在依托记忆作出关键业务决策时，请务必一并核查证据出处、记录时间、置信度、观点持有者及是否存在未决矛盾。
