Brain 从 Pod 页面和会话中提取可检索的事实、判断、事件与关联。人和 Agent 在 Pod 中共同维护知识；Brain 记录证据来源，并区分当前有效的主张与已被替代的主张。

## 在 Pod 中维护知识

**Meta Ankole → Brain** 展示组织知识图谱与本体分类。知识条目支持 Markdown、业务属性、引用和版本历史。人通过 Pod 编辑，Agent 通过 Brain 的 `write_object` 操作维护条目。条目移动或改名时，页面 ID 保持不变。本体引擎管理分类，Principal 生命周期操作维护内部成员与 Agent 档案。

页面的知识面板展示当前读者有权访问的事实、时间线、反向链接和预测校准结果。Console 的 **Objects** 列表会在 Pod 中打开对应页面。

知识通过以下路径进入 Brain：

| 路径 | 结果 |
| --- | --- |
| Agent 调用 `remember` | 记录一条带有证据说明和来源节点的原子 Fact 或 Take |
| 人或 Agent 更新 Pod 内容 | 检索片段和页面引用随页面版本一起更新 |
| 会话学习 | 从符合条件的私聊和群聊中提取事实、判断及承诺 |
| 注册文件或 URL Source | 将来源内容写入 Pod 知识页面，并按配置提取主张 |

公共 Pod 业务内容参与检索，可通过 `extract_facts` 属性开启事实提取。其中也包括 Ankole 能提取文字的文件：PDF、Office 与 OpenDocument 文档、电子表格、CSV 和纯文本。Brain 按页、幻灯片、工作表或章节检索文件内容；文件位于 Brain 目录下，或者文件页自身或其上级页面开启了 `extract_facts` 时，Brain 还会从中提取事实和时间线事件，并以该文件作为出处。电子表格贡献的是各工作表和列的摘要，而不是逐行事实；没有文字层的扫描版 PDF 页面无法检索。技能包和 Agent 指令契约在 Meta Ankole 中独立存储和管理，与 Brain 检索和事实提取分离。

## 区分事实、判断和证据

**Fact** 记录可核验的观察，包括置信度、时间、证据说明和持有者。**Take** 记录判断或预测，并带有供后续评估使用的权重。**Timeline** 记录发生在某个日期的事件。带类型的链接表达页面之间的关系。

每条主张和事件都必须有来源节点，主体页面则可以为空。因此，会话中的承诺可以先成为知识，无需先创建实体页面。持有者表示「谁提出这个主张」，主体表示「这个主张讨论什么」。

## 读取和共享知识

知识直接使用 Drive 和 Pod 的当前权限。仅分享一个页面时，读者只能访问该页面；分享容器时，可以包含容器的后代。页面标题、属性、正文、事实和事件都遵循这套可见性规则。即使主张讨论的是公开公司，来自受限会话的证据仍然受限。

Agent 读取范围取 Agent 与提问者权限的交集。群聊采用严格披露模式时，还需取全部在场参与者权限的交集；宽松模式检查 Agent 和提问者。成员关系或分享设置变化会立即影响后续读取。

会话学习使用会话的 Drive 根节点作为来源。Agent 显式调用 `remember` 时，默认沿用本次请求的来源，也可以依据 `AGENTS.md` 中的组织规则选择其他可访问的来源节点。Ankole 在检索时确定性地核验来源节点的当前权限。

## 在任务中使用记忆

会话开始或上下文压缩后恢复时，Brain 提供有长度限制的上下文，涵盖参与者、提及的实体、当前事实和未完成的承诺。后续文本轮次也可携带匹配名称的页面线索。Agent 可以调用以下工具：

| 工具 | 用途 |
| --- | --- |
| `remember` | 记录一条原子 Fact 或 Take |
| `recall` | 检索当前主张、实体卡片、页面片段和时间线片段 |
| `entity` | 查看主体的可见事实和关系 |
| `whoknows` | 查找与主题相关的人、Agent 和组织 |
| `delta` | 查看一段时间内新增、失效的主张和事件 |
| `synthesize` | 基于可见证据撰写分析页面 |
| `metric_query` | 执行已发布的指标口径，不经模型直接返回精确数值 |

Pod 页面读取分为属性、概览和全文。概览保留导语与章节标题，并折叠较长的表格和代码块；任务需要细节时，Agent 再读取全文。名称有歧义时，系统返回候选项供消歧。

`/drive/Brain` 是当前披露范围内的只读视图。Agent 新建或修订条目时，使用 `write_object` 提交分类或条目 ID、Markdown 和基础版本。缺少直接编辑权限时，Agent 发起 Action Card 提案，由有权限的人类确认。技能与指令契约由人在 [Meta Ankole](../agent-library/) 中管理。

## 持续更新知识

定时运行的 **Dreaming** 负责归纳证据、生成分析、提取时间线事件、评估到期 Take，并发现矛盾。操作人员在 Console 中处理矛盾。Brain 根据 Fact 类型和时间调整检索排序，但不改写原始置信度。

页面提取结果只有在输入版本仍匹配时才能提交。来源在 Drive 中被删除后，其检索片段和衍生主张立即退出检索。Pod 统一管理回收站、恢复、永久删除和页面历史。归档注册 Source 会停止后续学习，同时保留其 Pod 内容。

定时运行的 **self-healing** 重建过期片段和向量、检查索引，并为符合条件的会话安排学习。系统可以从 PostgreSQL 中的内容和结构化记录重建这些检索投影。

## 运维和检查

Console 提供 **Claims**、**Contradictions**、**Sources**、**Search preview**、**Principal audit** 和 **Health**。操作人员可以纠正或使主张失效、结算 Take、查看来源、触发 Source 学习，以及诊断模型配置问题。

Brain 使用租户的 `ankole_brain` 系统主体调用模型。其有效 `light` 配置用于提取，`heavy` 用于综合分析及需要模型的维护任务，`web_fetch` 用于获取 URL Source。操作人员在 Console 的模型配置编辑器中维护这些配置及 `rerank`，嵌入模型则属于站点设置。缺少可选模型只影响对应能力，已有知识和全文检索仍可使用。`brain.enabled` 控制 Brain 工具、自动上下文和后台学习，不删除已存储的知识。
