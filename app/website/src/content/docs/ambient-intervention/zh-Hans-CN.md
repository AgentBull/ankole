开启**可主动介入（May intervene）**后——无论是将外部群聊渠道的[信号路由规则](../signal-bindings/)群聊消息模式设为“可主动介入”，还是在原生 **Pod Chat** 群组话题中开启某个参与 Agent 的 `may_intervene` 策略——Agent 都会旁路读取群内未 `@` 它的消息，并针对每一批新到达的人类消息评估处理路径。默认策略是保持沉默；只有在确有介入价值时，才会发起简短回复、识别并承接新任务，或将补充信息转交给正在运行的后台任务。

该模式下的群聊表现受两项配置共同控制：会话常驻指令（`standing_orders`）与群组介入开关（外部渠道通过信号路由规则配置；Pod Chat 群组话题无需信号路由规则，按每个参与的 Agent 独立设置 `may_intervene`，并共用话题级的 `standing_orders`）。

## 每条消息只判一次

同一对话（Conversation）中的每个 Agent 各自独立维护判断进度：它们共享群内消息与常驻指令，但互不共用评估游标。只有**人类**发出的消息才会触发主动介入检查，Agent 发出的消息绝不会唤醒其他 Agent。每次评估仅针对上次判断之后新产生的消息，已经看过的历史消息只作为背景上下文提供，不会被反复评估。因此，一条当初决定略过的消息，不会在几轮对话后突然又被翻出来回复。

每次判断都会记录所选动作、授权来源与判断理由；若触发后台任务转交，还会记录唯一匹配的目标任务。当某个 Agent 在群里显得过于沉默或过于活跃时，运维人员可以直接核查这些路径记录来定位原因。

## 四种处理路径

- **不处理（`NOOP`）**：Agent 保持沉默。日常寒暄、收到确认、重复提问或已有他人接手的工作通常走这条路径。
- **前台回复（`FOREGROUND_REPLY`）**：启动一个简短的可见回合，用于解答疑问、澄清细节、协调进度、汇报状态或完成小范围查询。这条路径不能创建或重启后台任务。
- **新工作（`NEW_WORK`）**：识别一项独立且工作量较大的任务。人类成员直接提出请求，或频道常驻指令明确授权时，系统进入常规工作回合。资源访问只使用执行 Agent 的权限；`turn_authority` 与 `WorkAccess` 检查指令是否仍然有效。两种授权来源均不存在时，Agent 只能先询问是否需要接手；该确认回合不挂载工具，也不能创建后台任务。
- **转交（`HANDOFF`）**：将这批新消息静默转交给一个明确匹配的运行中后台任务。目标任务必须归属于同一 Agent、同一所属 Session 与同一 Conversation（来自外部渠道时还须匹配同一条信号路由绑定）；若候选任务信息不全或存在多个歧义目标，则不予转交。

介入意图识别器本身不会创建后台任务，它只负责选定处理路径与授权依据；后续进入常规工作回合后，仍遵循既有的用户确认与后台任务管理规则。

## 回复挂在提问的人身上

当 Agent 决定开口发言时，系统会区分以下两种场景：

- **回应具体提问**：群里某条新消息实际上是在向 Agent 提问或呼唤它（哪怕没有显式 `@`）。此时 Agent 的回复会直接锚定到那条提问消息上——在支持引用或消息线程的渠道中会自动呈现为引用回复或跟帖回复，让群成员一眼看清它在回答谁。
- **主动补充信息**：群里无人直接发问，但 Agent 判断此时补充信息很有价值，或恰好命中了频道常驻指令。此时回复会作为一条普通群消息发出。

提问归因经过严格校验：被认定的提问消息必须真实存在于当前评估批次中、确系人类发出，且提问者仍是群内最近的发言人。对于话题已经翻篇的早期旧提问，系统不会强行挂靠，而是自动降级为普通的主动发言。如果外部聊天平台事后删除了已被采纳的提问原消息，持久化归因状态会降级为 `degraded` 并清空消息锚点，但当次判断记录与评估游标仍会保留。

## 频道常驻指令

常驻指令是一段保存在 Conversation 上、由群内参与的 Agent 共同遵循的持久策略文本，用来明确约定 Agent 在这个群里什么情况下应该主动开口。例如：

- “只在 CI 变红或部署失败时发言。”
- “每天 18:00 之后如果有人发日报，帮忙汇总一下；其他时间保持安静。”
- “这里是客户群，除非有人直接问技术问题，否则不要插话。”

**设置方式非常简单，直接在群里告诉 Agent 即可。**任何群成员都可以直接发送“以后在这个群里只在 CI 红了才说话”，Agent 便会调用内置工具将其保存为该频道的常驻指令，并记录设置人。修改指令采用全量替换：要求调整规则时，Agent 会把整理后的完整新指令保存进去；发送“清空这个群的常驻指令”即可移除。

常驻指令会在两处同时生效：在介入评估阶段，系统将其作为该频道的运营策略，一旦消息语义明确匹配即可直接授权进入 `NEW_WORK`；而在可见的常规对话回合中，Agent 也能在上下文里读取这条指令。

使用时请注意两条边界：

- **仅在“可主动介入”模式下生效。**如果当前未开启可主动介入（例如外部渠道采用了其他路由模式，或 Pod Chat 群组话题中未勾选该 Agent 的 `may_intervene`），常驻指令仍会保存在 Conversation 的 `standing_orders` 字段中，但暂不激活；Agent 保存完毕后会明确提示当前尚未生效，待开启可主动介入后即刻生效。
- 单条常驻指令文本最长不超过 4000 个字符。

管理员也可以通过 Console 读写常驻指令，详见 [Console API 参考](../console-api/) 中的 `/api/v2/conversations/:conversation_id/standing-orders` 端点。

## 它还是插话太多或太少

- **插话太多**：先收紧或清空该群的常驻指令，再检查并收敛 Agent 自身的长期角色设定；如果该群只需要被动一问一答，直接将外部渠道的信号路由规则改回**仅处理明确提及**，或在 Pod Chat 群组话题中关闭该 Agent 的 `may_intervene` 即可。
- **插话太少**：先确认已开启“可主动介入”模式（检查外部渠道的信号路由规则，或 Pod Chat 群组话题中该 Agent 的 `may_intervene` 开关），再为该会话补充一条明确的常驻指令——介入评估默认偏向克制，未配置指令时，Agent 只有在确信有人需要它回应时才会开口。
- **设了常驻指令却没反应**：查看 Agent 保存指令时的回复提示——它会明确告知指令当前是否处于激活状态。若提示未激活，说明外部渠道的信号路由规则尚未设为“可主动介入”，或 Pod Chat 群组话题中尚未启用该 Agent 的 `may_intervene`。
