把一条 [信号路由规则](../signal-bindings/) 的群聊消息模式设为**可主动介入**后，Agent 会看到群里未 @ 它的消息，并在每一批新消息上先做一次廉价判断：现在开口有没有帮助。默认是沉默——大多数群聊不需要它插话。判断认为值得说话时，才会启动一次真正的回复回合。

本页说明这个判断的行为方式，以及你可以控制它的两个手段：频道常驻指令和路由规则本身。

## 每条消息只判一次

Agent 按频道维护一个判断进度。每次判断只针对上次判断之后的新消息；已经看过的旧消息只作为背景展示，不会被反复评估。所以一条它决定不接的消息，不会在几轮之后突然被翻出来回复。

每次判断连同判断理由都会留下记录。Agent 显得过于沉默或过于活跃时，运维侧可以回看它每一次“说/不说”的理由，而不是猜。

## 回复挂在提问的人身上

Agent 决定发言时会区分两种情况：

- **有人在问它**——群里某条新消息实际是在向它提问或叫它（即使没有 @）。这时它的回复会锚定到那条消息上：在支持的渠道里表现为引用回复或线程回复，群里的人一眼能看出它在回答谁。
- **主动补位**——没有人点名，它认为此刻补充信息有价值（或常驻指令命中）。这时回复作为普通群消息发出。

归因有校验：被认定的提问必须真实存在于这批消息里、出自人类，而且提问的人仍是最近的发言者。话题已经翻篇的旧提问不会被强行接起，这种情况会降级为普通的主动发言。

## 频道常驻指令

常驻指令是一段挂在频道上的持久策略文本，告诉 Agent 在这个群里什么时候该主动说话。例如：

- "只在 CI 变红或部署失败时说话。"
- "每天 18:00 之后有人贴日报，帮忙汇总；其他时间保持安静。"
- "这里是客户群，除非有人直接问技术问题，否则不要插话。"

**设置方式就是在群里直接告诉 Agent。**任何频道成员都可以说"以后这个群只在 CI 红了才说话"，Agent 会调用工具把它存为该频道的常驻指令，并记录是谁要求的。修改是整体替换：让它改指令时，它会把完整的新文本存进去。说"清掉这个群的常驻指令"即可清除。

常驻指令会同时进入两处：发言判断把它当作这间屋子的运营策略（命中即是发言理由，按含义匹配而不是关键词），正式回复回合也能在上下文里看到它。

两条边界：

- **只在"可主动介入"模式下生效。**其他模式的路由规则下，指令会被保存但完全不起作用，Agent 存完会告诉你它当前未激活。把规则切到可主动介入后自动生效。
- 单条指令文本上限 4000 字符。

Console 也可以读写常驻指令，见 [Console API 参考](../console-api/) 中的 `/signal-channels/:channel_id/standing-orders` 端点。

## 它还是插话太多或太少

- **太多**：先收紧或清空常驻指令，再收紧 Agent 的角色说明；只需要被动问答的群，直接把路由规则改回**仅处理明确提及**。
- **太少**：确认路由规则是可主动介入模式；给频道写一条明确的常驻指令——判断默认保守，没有指令时它只在有人实际需要它时开口。
- **指令设了没反应**：看 Agent 存完指令时的回复——它会说明指令当前是否激活。未激活几乎总是因为该频道的路由规则不是可主动介入模式。
