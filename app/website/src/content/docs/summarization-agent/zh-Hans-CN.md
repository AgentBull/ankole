一个摘要 agent 拿一份长文档——PDF、会议转写、频道 thread、论文——产出结构化摘要：要点、决定、未解决问题、适用的行动项。这是 LLM agent 最直接的使用之一，本指南是它在 Ankole 中的实际形态。

先把决定性的性质说清楚：agent **忠实摘要，不编辑**。它捕获文档说了什么、组织成有用结构，不加观点、不遗漏实质事实、不虚构不存在的内容。摘要是来源的投影，不是来源的替代。

## 需要什么

- **绑定 `primary` profile**——摘要是综合任务，强模型更佳。
- **一种交付源文档的方式**——在频道粘贴文本、上传文件（通过 [worker 文件](../worker-files/)）、或提供 URL（通过 `web_fetch` 抓取）。
- **一个 signal binding** 到摘要发帖的频道。

## 三种输入形态

| 来源 | 如何到达 | agent 做什么 |
|---|---|---|
| **粘贴文本** | 频道里的一条长消息 | 读文本、摘要 |
| **上传文件** | PDF、Markdown 文件、转写 | 从 Agent Home 读文件（通过 shell 或 `pdf` skill 做 PDF 文本提取）、摘要 |
| **URL** | 网页或文档的链接 | `web_fetch` 读内容、摘要 |

## 摘要结构

agent 产出的一个好摘要：

```text
**摘要 — <来源标题>**
**要点**：
- <要点 1>
- <要点 2>
- <要点 3>
**决定**（若适用）：
- <决定了什么>
**未解决问题**（若适用）：
- <留下了什么未解决>
**长度**：<原始字数> → <摘要字数>
```

结构一致，团队知道期待什么。人设可调整各节（项目文档加"风险"、转写加"引用"）。

## 人设控制什么

- **长度**——"200 字摘要"vs"5 个要点"vs"一段"。
- **结构**——各节、格式（要点 vs 散文）、详细程度。
- **忠实度**——"关键段落逐字引用；不要改写关键声明。"
- **范围**——"摘要整个文档"vs"只摘要关于 X 的部分"。

## 一个完整示例

设置一个摘要频道里丢进来的 PDF 报告的 agent：

1. 创建 agent，绑 `primary`/`light`/`heavy`。
2. 撰写 `MISSION.md`："当频道里出现 PDF，通过 pdf skill 的文本提取读它。产出结构化摘要：要点（最多 5 个）、决定、未解决问题。关键段落逐字引用。不加观点。把摘要发到频道。"
3. 通过 worker-file 路由上传一个 PDF（或粘贴一份转写）。
4. agent 读、提取、结构化、发摘要。

## 委派长文档

很长的文档（100+ 页），摘要本身可能慢。委派给后台任务（见[委派模式](../delegate-patterns/)）——任务读和摘要；任务完成时 agent 发摘要。这保持会话响应。

## 本指南不是什么

它不是搜索引擎——agent 摘要特定文档，不跨 web 摘要话题。它不是事实核查器——它报告文档说了什么；验证文档的声明是另一份工作。它也不是读源的替代——摘要是投影；源仍然权威。
