一个测试覆盖报告 agent 带覆盖率跑测试套件、读覆盖输出、识别未覆盖的代码路径（分支、函数、行）、提议能填补缺口的具体测试用例。本指南是那个 agent 的实际形态。

先把决定性的性质说清楚：agent **识别缺口和提议测试，不写它们**。它读覆盖报告、找未覆盖的分支、建议什么测试用例能覆盖每个。人写测试；agent 做分析。价值在于快速找缺口和提议有针对性的用例，不在于生成测试代码。

## 需要什么

- **WorkerEnv 里的 git 凭证**（`GIT_TOKEN`）。见 [Git 集成](../git-integration/)。
- **绑定 `primary` 和 `coding` profile**——读覆盖报告和提议测试用例需要代码理解能力。
- **一个 signal binding** 到覆盖报告发帖的频道。
- **项目的覆盖率工具**——`bun test --coverage`、`npx c8`、`pytest --cov`、或 repo 声明的任何工具。

## 工作流

1. **覆盖任务到达**——定时或大变更后。
2. **agent 带覆盖率跑测试**——`bun test --coverage`、`pytest --cov=src` 等。
3. **agent 读覆盖报告**——识别低于阈值的文件和函数、及其中具体的未覆盖分支。
4. **agent 映射到源码**——每个未覆盖分支，读代码理解什么条件未被测试。
5. **agent 提议测试用例**——每个缺口：什么输入会触发未覆盖分支、预期行为是什么、应放在哪个测试文件里。

## 覆盖报告

```text
**覆盖报告 — <日期>**
**整体**：78% 行、65% 分支、82% 函数
**低于阈值**（目标：80% 行、70% 分支）：

**`src/payments/refund.ts`** — 62% 行、50% 分支
- 未覆盖分支（第 45 行）：`if (amount === 0) return early`——无测试发零金额退款。
  提议测试：`amount=0 的退款应立即返回，不调 provider。`
- 未覆盖函数（第 82 行）：`calculatePartialRefund()`——任何测试都未调用。
  提议测试：`部分退款正确计算按比例金额。`

**`src/auth/token.ts`** — 71% 行、55% 分支
- 未覆盖分支（第 30 行）：过期 token 路径——无测试用过期 token。
  提议测试：`带过期 token 的请求返回 401 和 token_expired code。`
```

报告是可行动的——每个缺口有提议的测试用例，带触发输入和预期行为，不只是"第 45 行未覆盖"。

## 人设控制什么

- **阈值**——"目标 80% 行覆盖和 70% 分支覆盖。报告低于目标的文件。"
- **范围**——"所有源文件"vs"仅自上次发布以来修改的文件""
- **提议深度**——"每个未覆盖分支一个提议测试"vs"把小缺口组合成一个提议测试"。
- **不做什么**——"不写测试代码。提议用例。不改源码。"

## 一个完整示例

设置一个每周覆盖报告 agent：

1. 在 WorkerEnv 存 `GIT_TOKEN`。
2. 创建 agent，绑 `primary`/`coding`。
3. 撰写 `MISSION.md`："跑 `bun test --coverage`。读覆盖报告。识别低于 80% 行 / 70% 分支覆盖的文件。每个未覆盖分支读源码并提议测试用例：触发输入、预期行为、目标测试文件。发报告。不写测试。"
4. 加一条每周调度：`cron: "0 7 * * 1"`。
5. agent 跑、读、映射、提议、发报告。

## 本指南不是什么

它不是测试编写器——agent 提议用例；人写代码。它不是覆盖门控——它报告；CI 决定是否挡。它也不是代码质量裁判——覆盖测量代码是否被执行过，不测量测试是否断言了正确的东西。100% 覆盖加弱断言比 70% 覆盖加强断言更糟。
