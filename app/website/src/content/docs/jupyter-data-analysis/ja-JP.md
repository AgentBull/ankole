データ分析は試行錯誤の連続です。DataFrame の中身を確認し、クエリを調整し、結果を可視化してはまた確認する——こうした反復作業を単発の Python プロセスで行うと、呼び出しのたびにメモリ上の状態が失われてしまいます。`jupyter-live-kernel` Skill は、ライブの Jupyter カーネルを起動して状態を保持し、Agent が複数のセルをまたいで対話的に分析を進められるようにします。このガイドでは、データ分析を担う Agent の実践的な構築手順を説明します。

最大の特徴は、Jupyter カーネルが**セルをまたいで状態（ステート）を保持する**点にあります。定義した変数や読み込んだ DataFrame、インポート済みのライブラリ、プロットの状態は、Agent のツール呼び出しをまたいでそのまま維持されます。そのため、ステップごとにデータを読み込み直したり、ライブラリを再インポートしたりせずに反復分析を進められます。

## 必要なもの

- **`jupyter-live-kernel` Skill が有効であること。** デフォルトで有効（`default_enabled: true`）になっています。詳しくは [Skills](../skills/) を参照してください。
- **Worker イメージ。** Agent Computer Worker イメージには Python、Jupyter、`hamelnb` カーネルがあらかじめ組み込まれているため、追加インストールなしで利用できます。
- **`primary` モデルプロファイルがバインドされていること。** Agent が生成した Python コードを、カーネル側で実行します。

## kernel を使う場合と 1 回限りの script を使う場合

次のような場面では Jupyter カーネルが適しています。

- **反復的に分析を進める場合：** データの確認、条件の調整、再確認を繰り返す作業
- **状態を保持したい場合：** 読み込み済みの DataFrame、学習済みのモデル、インポート済みのライブラリを維持したいとき
- **データの構造を探索したい場合：** 最終的なクエリを組み立てる前に、データの傾向や欠損状況を調べたいとき

一方、次のような場面では単発の Python プロセス（`command` ツール経由）を使います。

- **スクリプトがステートレスな場合：** 1 回実行して出力を得れば完了する処理
- **バッチ変換を行う場合：** 対話的な確認を必要としないファイル変換などの定型処理

この Skill の `SKILL.md` でも、「ステートレスなスクリプトには単発の Python プロセスを優先してください」と案内されています。

## kernel の仕組み

`jupyter-live-kernel` Skill はバックグラウンド Job（`ankole-runtime: background_job`）として動作します。Worker 内で Jupyter カーネルを起動し、Agent は Skill のツールを通じてカーネルへセルを送信します。各セルはカーネルの永続状態の上で実行されるため、セル 1 で定義した変数をセル 5 からそのまま参照できます。

カーネルはバックグラウンド Job の実行中のみ稼働し、Job が終了すると停止してメモリ上の状態も消去されます。あくまで実行中の一時的な状態であり、永続ストレージに保存されるものではありません。

## 実践例

チームメンバーがチャネルに投稿した CSV ファイルを分析する Agent をセットアップしてみましょう。

1. `jupyter-live-kernel` Skill が有効になっていることを確認します（デフォルトで有効です）。
2. Agent を作成し、`MISSION.md` に次のように記述します。「チャネルに CSV が投稿されたら DataFrame に読み込み、スキーマと要約統計量を確認したうえで、異常値を特定し、グラフを添えて調査結果を報告してください。」
3. チャネルに CSV ファイルを添付するか、Console から Agent のドライブへアップロードしてファイルパスを伝えます。
4. 依頼を受けた Agent はバックグラウンド Job に処理を委任し、カーネルを起動して CSV を読み込み、反復的にデータを確認・可視化したうえで結果を報告します。

## このガイドではないもの

このページは Python や pandas 自体の入門ガイドではありません。コードを書くのは Agent であり、Skill はその実行環境を提供する役割を担います。また、配布用ノートブックの作成手順を解説するものでもありません。カーネルはあくまで Agent が分析を進めるための実行基盤であり、保存用ノートブックの生成を主目的とはしていません（もちろん、タスクとして指示すればノートブックを保存させることは可能です）。なお、仕様の正確な詳細については、正式なリファレンスである Skill 本体の `SKILL.md` をあわせて参照してください。
