一个社媒监控 agent 盯着你品牌、产品或关键词在公开来源上的提及，分类找到的东西，并按人设定义的阈值报告——或保持安静。本指南是那个 agent 的实际形态。它是[市场研究 agent](../market-research-agent/) 的变体，聚焦社交信号而非竞品策略。

先把决定性的性质说清楚：社媒监控是**阈值驱动，不是穷尽的**。它按节奏扫描、分类找到的东西、只在提及越过阈值时报告——量飙升、负面情感趋势、KOL 提及、或团队该回答的直接提问。其余是安静。

## 需要什么

- **绑定 `web_search` 和 `web_fetch` profile。** agent 搜提及并读找到的帖子。
- **绑定 `primary` profile**——用于情感分类和阈值判断。
- **绑定 `embedding` profile**——Brain 召回把这次扫描的发现和上次的对比，所以 agent 报告变化，不是每次报告完整景观。
- **一个调度**——快变品牌每小时，多数每天。见 [Cron 调度](../cron-schedules-ops/)。

## 工作流

1. **调度触发**——agent 跑搜索查询。
2. **agent 搜索**——`web_search` 搜品牌名、产品名、关键话题标签或竞品对比。
3. **agent 抓取**——对最相关的结果 `web_fetch` 读实际帖子。
4. **agent 分类**——情感（正面/中性/负面）、量（这是飙升吗？）、影响力（这是来自重要的账号吗？）、可操作性（这需要回应吗？）。
5. **agent 决定**——有没有提及越过报告阈值？
6. **agent 报告或保持安静**——结构化报告到频道，或什么都不发。

## 阈值

人设定义什么越过阈值：

- **量飙升**——"若品牌提及相比上次扫描增加超过 50%，报告。"
- **负面情感**——"若负面提及来自超过 1 万粉丝的账号，报告。"
- **直接提问**——"若有人在问团队该回答的产品问题，报告。"
- **KOL 提及**——"若已知 KOL 或记者提到品牌，总是报告。"

阈值以下 agent 保持安静。这与[市场研究 agent](../market-research-agent/) 的安静模式是同一纪律。

## Brain 增加什么

- **上次扫描记忆**——agent 把这次扫描的量和情感与上次的对比，所以"飙升"是相对的，不是绝对的。
- **KOL 清单**——一份总是值得报告的账号的策展知识条目。
- **已知问题**——若负面提及匹配 Brain 里的已知问题，agent 指向回应而非盲目升级。

## 一个完整示例

为 SaaS 品牌设置每日社媒监控：

1. 绑 `web_search`、`web_fetch`、`primary`、`embedding`。
2. 撰写 `MISSION.md`："每天搜各社交平台上的'YourBrand'。分类情感、量、影响力。以下情况报告：量比上次扫描飙升 >50%、负面提及来自 >1 万账号、直接产品提问、或 KOL 提及。否则保持安静。始终附链接。"
3. 加一条每日调度：`cron: "0 10 * * *"`。
4. 策展 Brain 知识：KOL 清单、已知问题清单、首次扫描的基线量。

## 本指南不是什么

它不是社媒管理工具——agent 监控和报告；它不发帖、回复或安排内容。它不是情感 API——agent 通过其模型分类，不通过专用情感分析服务。它也不是危机检测系统——它浮现信号；团队决定某事是否是危机。
