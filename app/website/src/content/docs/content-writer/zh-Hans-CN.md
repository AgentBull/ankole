一个内容写作 agent 拿一份简报——"写一篇关于我们新功能的博客"、"起草定价变更公告"——产出匹配品牌语气、使用产品术语、遵循团队内容约定的草稿。本指南是那个 agent 的实际形态。

先把决定性的性质说清楚：agent **起草，不发布**。草稿是人类编辑的起点，不是完成的发布物。价值是初稿的速度；是否发出的判断是人的。

## 需要什么

- **绑定 `primary` profile**——内容质量取决于强模型。
- **Brain 知识已策展**——品牌语气指南、产品术语、风格指南、过往内容作为参考材料。
- **一个 signal binding** 到草稿发帖的频道。
- **`pdf` skill（可选）**——若交付物必须是 PDF。

## 工作流

1. **简报到达**——频道消息、调度任务或 webhook。
2. **agent 读简报**——写什么、给谁、什么格式、多长。
3. **agent 召回 Brain 知识**——品牌语气、产品术语、相关过往内容、风格指南。
4. **agent 起草**——按请求格式的内容，匹配语气和约定。
5. **agent 发草稿**——带一句请求复核。

## 人设控制什么

- **语气**——"用自信、技术但易懂的语气。短句。主动语态。无炒作词。"
- **术语**——"用 Brain 术语表里的产品官方名。不缩写产品名。"
- **结构**——"博客：引言+3 节+结论。公告：变了什么、为什么、做什么。"
- **长度**——"博客：800-1200 字。公告：最多 200 字。"
- **请求**——"发草稿并请求复核。不发布。"

## 一个完整示例

为开发者工具公司设置内容写手：

1. 创建 agent，绑 `primary`/`heavy` + `embedding`。
2. 撰写 `MISSION.md`："从简报起草内容。匹配品牌语气：技术、直接、无营销废话。用 Brain 里的产品术语。博客：800-1200 字、引言+3 节+结论。发草稿请求复核。"
3. 策展 Brain 知识：品牌语气指南、产品术语表、风格指南、3 篇参考文章链接。
4. 在频道里："写一篇关于我们新 webhook 功能的博客。受众：后端开发者。要点：做什么、怎么设置、一个例子。"
5. agent 召回语气指南、起草、发出来供复核。

## 本指南不是什么

它不是发布管线——agent 起草；人编辑和发布。它不是内容策略工具——agent 从简报写；它不决定写什么。它也不是人工编辑的替代——草稿是起点；编辑塑造最终语气、捕捉模型遗漏的东西。
