Ankole 内置了 `web_search` 与 `web_fetch` 用于常规网页检索和读取，也提供了 `browser` Skill 用于操控真实浏览器。但在实际业务中，还有一类网页数据需求是这三者难以高效覆盖的：反爬拦截严密的站点、需要将整站文档批量清洗为干净 Markdown、需要按给定 JSON 结构直接提取字段，或是需要连续数月跟踪竞品页面变动。内置的 `context-dev` Skill 通过对接 [Context.dev](https://context.dev) API 补齐了这块能力。

由于每次调用都会消耗 Context.dev 账户中的额度点数（Credits），这项 Skill 默认处于关闭状态，需要由管理员配好 API Key 并显式开启后才会生效。

## Agent 能用它做什么

启用后无需记忆底层接口参数，直接在聊天里向 Agent 描述目标产物，Agent 会自行挑选合适的子工具完成任务：

```text
把 example.com/docs 下的所有页面读一遍，把 API 限制整理成一张表。

这个定价页挡住了我们的抓取，帮我拿到套餐名和月价。

这个邮件签名里的域名，给我它的 logo、品牌色和 LinkedIn 主页。

每天两次盯着 example.com/pricing，套餐价格变了就告诉我。

stripe.com 对应哪个 NAICS 行业代码？
```

它提供的能力主要涵盖以下五类场景：

- **实时网页读取**：支持全网搜索、单页转换为干净的 Markdown 或 HTML、提取页面全部图片链接，以及拉取指定域名的完整 URL 清单。底层自动处理反爬绕过与代理升级，常规抓取被拦截的网页通常都能顺利读出。
- **大规模整站采集**：支持同步抓取最多 500 个页面，或提交最多包含 100,000 个 URL 的异步批量采集任务，适合无法在前台干等的大体量文档归档。
- **按 Schema 结构化抽取**：传入自定义的 JSON Schema，直接拿回严格对齐该结构的数据对象，省去再让大模型通读全文二次提取的步骤。
- **企业品牌与视觉情报**：输入域名、公司名称、企业邮箱、股票代码、银行卡账单摘要或任意单页 URL，即可查询企业的 Logo、标准品牌色、官方社媒账号、所属行业、注册地址及上市信息；还可进一步提取目标网站的设计系统、字体清单、整页长截图，以及对应的 NAICS 或 SIC 行业分类代码。
- **持续变更监控**：按设定周期定时复查指定网页、站点地图（Sitemap）或某次结构化抽取结果，自动记录前后差异，并支持选配 Webhook 主动推送。

## 怎么开启

### 1. 获取 API Key

前往 [context.dev](https://context.dev) 注册账号并创建一把以 `ctxt_secret_` 开头的 API Key。免费套餐每月提供 1,000 点额度，具体账号的有效额度以其控制台显示为准。

### 2. 配置环境变量

打开 **Console → 环境变量**，新增一条变量配置：

- **名称**：`CONTEXT_DEV_API_KEY`
- **值**：粘贴你的 `ctxt_secret_...` 密钥
- **加密存储**：开启

变量名称必须精确填写为 `CONTEXT_DEV_API_KEY`——该 Skill 清单固定声明读取这一键名。你可以将其配在站点级或租户级供多 Agent 共用，也可以前往 **Console → 智能体 → 选择目标 Agent → 环境变量**，只挂载给某一个特定 Agent 使用，从而把额度消耗严格限制在该 Agent 身上。详细继承规则见 [环境变量](../worker-env/)。

### 3. 启用 Skill

打开 **Console → Agent 能力库**，找到 `context-dev` 并开启：既可设为租户默认开启，也可仅对确实需要采集外部网页的个别 Agent 单独放行。“租户默认 + 单 Agent 覆盖”的配置方式详见 [Agent 能力库](../skills/)。

启用或停用 `context-dev` 后，设置从后续 Agent 回合和后台 Agent 任务开始生效。

### 4. 验证可用性

找一个已启用该能力的 Agent 发起一次轻量测试（例如查询某个常见企业域名的品牌色与 Logo）。如果返回结果提示 `401` 未授权，说明密钥缺失或填写有误：请核对变量名是否为准确的 `CONTEXT_DEV_API_KEY`、状态是否并非“未设置”，并确认当前 Agent 或租户下没有残留错误的空覆盖值遮蔽了上级 `WorkerEnv` 配置。

## Ankole 怎么连接

Context.dev 的 MCP 服务地址为 `https://mcp.context.dev/mcp`，由 Skill 声明为远程 MCP 依赖。Worker 使用短期回合令牌调用控制面的 Skill 代理。代理读取已配置的 `CONTEXT_DEV_API_KEY` 并用于上游认证，该引用密钥不会进入 Worker 环境快照。临时 MCPorter 配置指向内部网关。

顺带一提，Context.dev 面向个人桌面客户端默认推荐走浏览器 OAuth 交互授权，这在无人值守的服务端 Worker 中显然无法使用；因此 Ankole 对接的是同一服务端原生支持的 API Key 鉴权模式，直接通过 `Authorization` 请求头完成认证，全程无需人工点选登录。

该 MCP 服务不会膨胀进每轮模型默认可见的原生工具表：Agent 先按需读取 Skill 说明、选定具体子工具，再通过 `mcporter` 发起调用。详细调用链路见 [使用 MCP-backed Skill](../using-mcp/)。

## Credits 与成本

Context.dev 按点数（Credits）计费；当前费率与附加选项费用以[官方价目表](https://www.context.dev/pricing)为准：

| 操作类型 | 消耗点数（Credits） |
| --- | --- |
| 单页转 Markdown/HTML、拉取一次 Sitemap、提取图片清单、解析单个文件 | `1` |
| 网页搜索 | 每 `10` 条结果 `1` 点；结果数默认 `10`，可指定 `1`–`100`；正文等附加选项另行计费 |
| 整站批量抓取 | 每抓取一页 `1` 点 |
| 整页截图、提取字体清单 | `5` |
| 查询企业品牌资料、提取设计系统、按 Schema 结构化抽取、查询 NAICS / SIC 代码 | `10` |

想要管住账单，只需养成两个习惯：第一，整站抓取和网页搜索均按结果条数计费，面对大型站点若不设页数上限最容易瞬间烧光额度——内置 Skill 指令已要求 Agent 将抓取页数上限收敛到它实际读得完的范围，布置任务时也可顺手写明页数上限。第二，变更监控器一旦创建，只要没删就会按周期持续扣费（每小时查一次的开销是每天查一次的 24 倍，且不会自动停止）；让 Agent 创建监控器时请嘱咐它把返回的 `monitor ID` 报给你备查，若只允许特定 Agent 消耗外部额度，只需将 `CONTEXT_DEV_API_KEY` 收窄挂载给该 Agent 即可。

## 限制

- **每次调用都会消耗真实外部额度**：一旦为某个 Agent 开启该 Skill，它在做任何公开网络调研时都可能自主选用这些接口。如需严格控费，请按单个 Agent 精准挂载密钥并按需开关 Skill。
- **监控器与异步批量任务独立于会话之外**：这类长生命周期对象直接保存在你的 Context.dev 云端账户中，Ankole 控制台不设专门的管理列表，需通过对话让 Agent 调用该 Skill 查询或删除。
- **抓取回来的网页一律属于不可信外部数据**：外部页面正文只是待分析的原始素材，绝非系统指令。Agent 应把这些内容作为待分析的数据；审阅或转发结果时也应保持这一边界。
- **解析本地工作区文件无需动用本 Skill**：对于已经存放在 Agent 工作区内的 PDF 文档或图片，直接调用 [`pdf` 与 `ocr` Skill](../ocr/) 即可解析，无需消耗 Context.dev 点数。
