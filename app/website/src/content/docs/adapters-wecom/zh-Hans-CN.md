Ankole 支持把企业微信（WeCom）智能机器人接成聊天渠道，把自建应用接成登录与通讯录提供方。**如果你可以选择渠道，我们不建议优先使用企业微信**：在 Ankole 支持的聊天平台里，企业微信的机器人开放能力最少，下面的限制全部来自平台本身，Ankole 无法绕过。飞书 / Lark、钉钉、Slack 和 Microsoft Teams 都能提供更完整的体验。

只有当组织已经全员使用企业微信、且接受本页全部限制时，再选择它。

## 平台限制（Ankole 无法绕过）

**消息接收**

- 群聊里 Agent 只能收到明确 @ 机器人的消息。不 @ 就完全收不到，因此「记录未提及消息」「可主动介入」两种群聊模式都不可用，Console 只会提供「仅处理明确提及」。
- 图片、语音、文件、视频只有单聊能收到；群聊 @ 消息只能带文本和图文混排。
- 语音消息只有平台转写的文字，Agent 拿不到原始音频。
- 用户撤回、编辑消息不会通知机器人，Agent 看到的历史可能过时。

**消息发送**

- 发出的消息**无法撤回**（平台没有撤回接口），也无法编辑。
- 不能加表情回应，没有针对某条消息的定向回复。
- Agent 主动开口（例如定时任务的结果推送）有前置条件：**用户必须先在该会话给机器人发过消息**。全新会话无法由 Agent 先发起。
- 收到消息后的回复窗口是 24 小时；超过后只能走上一条的主动推送路径。
- 流式回复（打字机效果）只在回复用户消息时可用；主动推送只能一次性发完整 Markdown。单条流式消息还有 10 分钟内必须写完的平台时限，长回答会拆成多条。
- 发消息限频约每会话每分钟 30 条、每小时 1000 条。

**交互与身份**

- 交互按钮卡片在用户点击后只有 5 秒的更新窗口，之后卡片内容永远无法再改。
- **机器人必须由企业超级管理员创建**。否则消息里的用户 id 是加密形态，聊天身份永远无法和通讯录、扫码登录对上。
- 通讯录同步必须使用「管理工具 → 通讯录同步」的专用 Secret：2022 年 6 月之后，普通应用凭证拿不到成员姓名等字段。
- 通讯录变更没有实时同步，靠周期性全量同步收敛。

**部署要求**

- 登录与通讯录接口要求**固定出口 IP**，并配置到企业微信管理后台的「企业可信 IP」（自建应用与通讯录同步各配各的），否则报错 60020。
- 登录回跳域名必须配置为自建应用的可信域名。
- 平台强制每个机器人只允许一条长连接：如果有别的程序用同一个 Bot ID 连接，双方会互相顶掉。Ankole 检测到被顶掉后会停下等待，不会反复抢线。

## 与其他渠道的对比

| 能力 | 飞书 / Lark | 钉钉 | Slack / Teams | 企业微信 |
|---|---|---|---|---|
| 群聊读取非 @ 消息 | ✅ | ❌ | ✅ | ❌ |
| 撤回自己发出的消息 | ✅ | ✅ | ✅ | ❌ |
| 群聊接收图片 / 文件 | ✅ | 部分 | ✅ | ❌ |
| Agent 主动发起会话 | ✅ | ✅ | ✅ | ❌（需用户先发言） |
| 流式回复 | ✅ | ✅ | ✅ | 仅回复时可用 |
| 通讯录实时同步 | ✅ | ✅ | ✅ | ❌（周期全量） |

## 如果仍要使用

1. 用**企业超级管理员**账号在管理后台创建 API 模式的智能机器人，记录 Bot ID 和 Secret。
2. 创建自建应用（登录用），配置可信域名与企业可信 IP；如需通讯录同步，在「管理工具 → 通讯录同步」开启 API 同步并记录专用 Secret 与其可信 IP。
3. 确保 Ankole 部署有固定出口 IP。
4. 在 Console 的[信号路由](../signal-bindings/)创建企业微信规则，在身份提供方里配置登录与通讯录。
5. 让使用者先给机器人发一条消息，解锁该会话的主动推送。
