Agent にイラストやコンセプトアート、ビジュアルのたたき台を作成させたいときは、画像生成を有効にします。普段使っているチャット画面のまま依頼でき、生成された各画像は添付ファイルとして返されます。また、参照画像の入力に対応したモデルを選択していれば、既存の画像を編集することも可能です。

## 実行パスを選択する

公開されている `image_generation` ツールには、次の 2 つの実行パスがあります。

- **Hosted:** Agent の `image_generate` プロファイルを設定する方法です。AIGateway がそのプロファイルで指定された別の Provider・モデルでツールを実行し、生成結果をメインモデルへ返します。
- **Native:** `image_generate` を空欄のままにし、ネイティブ画像生成に対応したメイン Provider を使う方法です。OpenAI と ChatGPT Subscription がこのパスに対応しており、AIGateway は公開ツールをそのままメイン Provider へ引き渡します。

つまり、`image_generate` プロファイルは機能のオン・オフを切り替えるスイッチではなく、実行先を切り替えるルーティングスイッチとして機能します。`image_generate` が空欄で、かつメイン Provider もネイティブ画像生成を宣言していない場合、AIGateway は設定不足を示す明確なエラーを返してツール呼び出しを拒否します。

Hosted パスを使う手順は次のとおりです。

1. Console の **LLM Providers** で、使用したい画像生成モデルに対応する Provider を追加します。
2. **Agents** を開き、対象の Agent を選択します。
3. モデルプロファイル一覧から `image_generate` を探します。
4. 画像生成に使う Provider とモデルを選択し、プロファイルを保存します。
5. チャット画面に戻り、具体的な画像生成リクエストを送信します。

なお、通常のモデルトークン（model-token）の使用量はメイン Provider の認証情報に記録され、画像トークン（image-token）の使用量は実際に画像を生成した認証情報に記録されます。これは認証情報プールのローテーションが発生した後も同様です。

## 短いビジュアルブリーフを書く

リクエストを長文にする必要はありません。「どこで使う画像か」「何を描き込む必要があるか」「勝手に補完してほしくない点はどこか」を Agent に簡潔に伝えます。まずは用途と主題から書き始め、仕上がりに影響する構図やビジュアルスタイル、制約条件だけを添えるのが効果的です。

必要に応じて、次の 5 つの観点を整理して伝えてください。

- **用途とキャンバス:** Web サイト、プレゼン資料、SNS 投稿などの掲載先と、横長・縦長・正方形または正確なアスペクト比を指定します。
- **主題とシーン:** メインとなる被写体、周囲の状況、動きを指定します。
- **構図とビジュアル言語:** 特に重要な視点、配置、余白（ネガティブスペース）、素材感、光、表現媒体だけを指定します。
- **画像内のテキスト:** 画像に入れたい正確な文字列を引用符で囲み、配置場所を記述します。長文のコピーは、可能なかぎり画像の外に配置してください。
- **制約:** 含めてはならない文字、透かし（ウォーターマーク）、ロゴ、オブジェクトを指定します。参照画像を渡す場合は、変更してはならない要素も明記します。

たとえば次のように記述します。

```text
Use: A 16:9 hero image for a product announcement. The page title will be on the left.
Subject: A white device on a dark blue table, placed on the right.
Composition: Simple geometry, soft side light, and a large open area on the left.
Text: Include only "ANKOLE 2.0" in the bottom-right corner.
Constraints: No people, watermarks, other brand marks, or extra text.
```

画像内テキストの描画、サイズ指定、参照画像のサポート範囲はモデルごとに異なります。選択したモデルと Provider のドキュメントをあわせて確認してください。

## 同じチャットで画像を仕上げる

1 回の生成で狙いどおりの画像が完成することは稀です。まずは 1 つの方向性で画像を出力し、同じチャットの中で少しずつ調整を重ねていきましょう。1 回の Turn につき修正点を 1 つ（または互いに関連する項目群 1 つ）に絞ると、結果を制御しやすくなり、全面的な描き直しを防げます。

編集を依頼する際は、「変更する部分」と「そのまま維持する部分」の両方を指定します。たとえば次のように伝えます。

```text
Change only the background to light gray. Keep the subject, composition,
lighting, text position, and colors unchanged.
```

参照画像を複数添付する場合は、「画像 1」「画像 2」のようにラベルを付け、それぞれの役割を指定します（例：「画像 1 の主題と、画像 2 の配色を使ってください」）。ただし、この指定は選択したモデルが参照画像の入力や画像編集に対応している場合にのみ機能します。

## 画像が表示されない場合

- **Agent がテキストしか返さない:** クライアントまたは Agent 側で `image_generation` ツールが公開されているか確認してください。あわせて、`image_generate` が設定されているか、あるいはメイン Provider がネイティブ画像生成に対応しているかを確認します。
- **利用可能なモデルがない:** 現在登録されている LLM Provider が画像生成モデルを提供していません。画像生成に対応した Provider を追加してください。
- **リクエストがサポートされていない:** 条件に対応したモデルを選択し直すか、未対応のサイズ、フォーマット、透過背景、参照画像、編集指定をリクエストから外してください。
- **画像は表示されるが内容が意図と違う:** 多くの場合、設定の問題ではありません。同じチャットでやり取りを続け、何を変更し、何を維持するかを具体的に指定してください。
- **生成は成功しているがチャットに添付されない:** 利用中の Channel Provider がファイルのアップロードに対応しているか確認し、その会話のエラー内容を確認してください。

指定できるサイズ、フォーマット、透過背景、参照画像、編集機能の範囲は、使用するモデルと Provider に依存します。
