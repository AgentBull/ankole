外部イベントは Connector サブスクリプション、または任意の送信元が POST できるコールバック URL で受け取ります。Ankole は配信を永続化してから受理を応答し、関連付けに従って Agent または Applet Job に渡します。

## ソースを選ぶ

GitHub のリポジトリ・組織イベントや Lark の承認・カレンダー変更は Pod の接続ページで設定します。管理者がアプリケーションを登録し、必要に応じて本人が個人アカウントを認可します。リソースを選んでサブスクリプションを作ると、制御プレーンが上流の登録と削除を管理します。失敗状態には再試行操作があります。

汎用のコールバックは Applet の自動化パネルから Job 用に作成します。`standing` または `one_shot` と有効期限を指定し、一度だけ表示される URL を送信元へコピーしてテストしてください。Agent の会話を再開するコールバックは `create-webhook-cli --help` の手順で作成できます。

## 配信と管理

`one_shot` は最初の一致する配信だけを処理し、`standing` は停止・失効・期限切れまで受信します。上流イベントの重複に対応し、重要な操作の前には情報源の現在の状態を確認してください。

Job 所有のエンドポイントは Agent セッションなしで Applet Action を起動します。Action は `ctx.signal` を読み、自動化パネルで配信記録、Run の状態、入力、結果、ログを確認できます。個人用は所有者、チーム用はページの権限に従います。Job を削除すると所有エンドポイントも削除しますが、他の処理先が使う共有 Connector サブスクリプションは残ります。

一時停止は設定を残して受信を止めます。完全に終了する場合は取り消しまたは削除を使います。汎用エンドポイントを取り消しても、送信元に別途作った Webhook は削除されません。

HTTPS で `/webhooks/v1/event-callbacks/*` と必要な `/webhooks/connectors/*` を転送してください。コールバック URL は秘密として管理し、プロキシのログでも隠します。URL の所持はイベント送信を許可するだけで、内容の正しさを保証しません。失敗時は送信元のログ、期限、認可、配信記録、Run の順に確認します。

[Automation Jobs](../automation-jobs/)と[Signals](../signals/)を参照してください。
