在钉钉上，Agent 的回复可以是普通 Markdown 消息，也可以是流式 **AI 卡片**。卡片会边写边显示答案，保留一个折叠的思考区，并承载 Agent 反问时用到的按钮。钉钉卡片是模板托管的：版式保存在钉钉卡片平台上，Ankole 只往一组固定变量里写值。

因此你只需为一个钉钉组织搭建一份模板，把模板 id 填进信号路由规则，绑定该规则的 Agent 就会用卡片回复。id 留空则回复保持普通 Markdown，其他行为不变。

第一次搭建模板大约需要二十分钟。[验证卡片](#验证卡片)一节告诉你是否成功，[排查](#排查)表把每种异常外观对应到原因。

## 前置条件

你需要：

1. 一个已发布、开启机器人能力、并且已经作为聊天渠道正常工作的钉钉企业内部应用。请先按[信号路由规则](../signal-bindings/)接通，并确认 Agent 能用纯文本回复。
2. 在钉钉开发者后台打开卡片平台、并为该应用发布模板的权限。
3. 应用侧的这些权限：互动卡片实例写入、AI 卡片流式更新。

如果 Agent 目前完全不回复，请先解决那个问题。卡片模板修不了一条本来就投递不到的渠道。

## 搭建模板

打开钉钉开发者后台 → 卡片平台 → 新建模板，选择 **AI 卡片** 类别。只有这个类别带 AI 卡片容器，由它绘制输入指示、完成态和出错态。

### 1. 添加变量

按下表逐个添加模板变量，名称必须与第一列完全一致。名称不一致时，对应区域在每次回复里都是空的。

| 变量 | 类型 | Ankole 写入的内容 |
|---|---|---|
| `flowStatus` | 文本 | 卡片状态：书写中 `2`、完成 `3`、失败 `5` |
| `state` | 文本 | 一行状态，例如正在运行的工具名、`已完成` 或 `出错` |
| `answer` | Markdown，流式 | 回复正文，每一帧全量重写 |
| `thought` | Markdown | 临时思考草稿，回复结束时清空 |
| `plan` | 文本 | `执行计划 · 1/3` 加每条任务一行 |
| `activity` | 文本 | 每个正在执行的工具调用一行，回复结束时清空 |
| `results` | 文本 | 每条结构化结果一行 |
| `receipts` | 文本 | 每条已记录的副作用一行 |
| `actions` | 文本 | 按钮的 JSON 列表；Agent 不反问时为空 |
| `meta` | 文本 | 精简元信息：触发原因、卡片序号、计数、耗时 |

### 2. 排布卡片

在 AI 卡片容器内按这个顺序放组件：

1. `meta` 与 `state` 放在顶部，用小号文本。
2. `plan` 用文本组件。
3. `thought` 放进一个折叠区，`activity` 放进第二个折叠区。两者都是临时内容，回复结束后不应保持展开。
4. `answer` 作为主 Markdown 组件。把它的内容变量类型设为 markdown，并在该组件上开启流式。这是唯一一个 Ankole 会按流式频率更新的组件。
5. `results` 与 `receipts` 用文本组件。
6. `actions` 绑定到操作区。

### 3. 绑定卡片状态

选中 AI 卡片容器，把它的流程状态变量（`flowStatusVar`）绑定到 `flowStatus`，并保持书写态与失败态启用。

这条绑定决定了卡片是否显示得出内容。容器靠读取 `flowStatus` 来选择绘制哪个状态，所以状态变量未绑定的容器会永远停在初始状态，而且经常渲染出空白正文。关闭回复流不会改变它，值由 Ankole 写入。

### 4. 发布并接入

把模板关联到持有机器人的企业内部应用，发布，复制模板 id。在 Console 打开钉钉信号路由规则，把 id 填进 **AI 卡片模板 id**（`cardTemplateId`），保存规则。

改动在下一次回复生效，无需重启任何组件。

## 一次回复如何使用卡片

一次回复是一条卡片链，每张卡片是一条钉钉消息：

1. Ankole 创建并投放一张卡片，然后随 Agent 书写把 `answer` 流式写进去。
2. 源文超过约 2.5 KB 时封口当前卡片，它的状态行变为 `回答继续于下一张卡片`，答案在新卡片上继续。已封口的卡片不再被写入。
3. 回复结束时最后一张卡片同样封口：清空思考区和活动区，写入最终结构，`flowStatus` 置为 `3`；本轮失败时置为 `5`。
4. Agent 反问时，最后一张卡片保持书写态，按钮因此保持可用。按钮回传走承载消息的同一条长连接。

每次按钮点击 Ankole 都会重新校验操作者权限。已经不对应待答问题的按钮会被受理并忽略。

## 验证卡片

给 Agent 发一条能产出好几句话的消息，完整看一次回复：

1. **出现的是卡片**而不是文本消息。如果来的是普通 Markdown 消息，说明模板 id 为空或者 Ankole 拒绝了卡片，见下方排查表。
2. Agent 书写时**答案在增长**，卡片显示输入指示。
3. 回复结束时**指示停止**，答案完整可读。
4. 完成后的卡片上**思考区与活动区为空或消失**。

然后问一个需要你做决定的问题，让 Agent 反问。此时必须出现按钮，点击后本轮继续。

如果某次回复长到跨两张卡片，检查第一张卡片以 `回答继续于下一张卡片` 结束，并且不再显示输入指示。

## 排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 卡片空白，或回复结束后仍显示输入指示 | AI 卡片容器的状态变量没有绑定到 `flowStatus` | 按第 3 步绑定并重新发布模板 |
| 卡片能渲染，但某个区域始终为空 | 该变量名不匹配，或组件没有绑定到它 | 与第 1 步的表逐字核对名称 |
| 答案只在最后出现，或完全不出现 | `answer` 组件不是 markdown 流式组件 | 把内容变量类型设为 markdown 并开启流式 |
| 回复是普通 Markdown 消息 | 模板 id 为空、模板未发布到本应用，或钉钉拒绝了卡片内容 | 先查路由规则里的 id，再查控制面日志中的 `param.contentUnsafe` 或 `param.cardNotExist` |
| 按钮出现但点击无反应 | 操作区没有原样透传每个按钮的 `value` | 修正模板中操作区的绑定 |
| 同一次回复先是卡片，随后又来一条纯文本 | 永久性拒绝让本轮降级 | 这是预期行为。回复仍然送达，日志里能查到拒绝原因 |

卡片路径永久失败时，Ankole 为这次回复一次性降级为普通 Markdown，不会来回震荡。回复始终会送达。

## 钉钉做不到的事

钉钉的卡片模型比飞书 / Lark 更窄，Ankole 不假装没有这个差距：

- 版式是固定变量集，不是自由拼装的卡片 JSON。表格这类富结构结果以文本呈现，不是原生表格组件。
- 单张卡片约 3 KB，长答案会变成一条卡片链，而不是一张不断变长的卡片。
- 卡片始终是会话中的一条新消息。钉钉没有锚定回复，卡片无法挂在触发它的那条消息上。
- 本轮运行期间只有答案和思考草稿在动。计划、活动和元信息区在卡片创建时写入，封口时再写一次。

钉钉同样只投递单聊消息和群里 @ 机器人的消息。这个限制属于渠道，不属于卡片。
