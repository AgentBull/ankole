一个定时报告 agent 按节奏运行、收集报告所需数据、格式化、交付到频道。这是[每日简报机器人](../daily-briefing-bot/)的变体，聚焦结构化数据输出而非研究——指标仪表盘、用量摘要、合规检查。本指南是那个 agent 的实际形态。

先把决定性的性质说清楚：报告是**数据驱动且结构化的，不是叙事**。agent 获取数字、格式化成表格或摘要、发出来。价值是一致性——同样的报告、同样的格式、同样的计划、每次一样。格式漂移了，报告就坏了。

## 需要什么

- **绑定 `primary` profile**——用于格式化和异常检测。
- **一个 signal binding** 到报告发帖的频道。
- **一个调度**——每天、每周或每月。见 [Cron 调度](../cron-schedules-ops/)。
- **一个数据源**——数据库查询（通过 `command` 用 `psql` 等）、API 端点（通过 `web_fetch`）、或 Agent Home 上的文件。

## 工作流

1. **调度触发。**
2. **agent 获取数据**——跑查询、调 API、或读文件。
3. **agent 格式化**——把数据结构化成报告：Markdown 表格、要点摘要、或结构化文档。
4. **agent 检查异常**——把这次运行的数字与预期范围或上次运行比较。数字越界就标记。
5. **agent 交付**——把报告发到频道。

## 报告模板

一个好的定时报告是一致的。在人设里定义模板：

```text
**周指标 — <日期范围>**
| 指标 | 本周 | 上周 | 变化 |
|---|---|---|---|
| 活跃用户 | 1,234 | 1,100 | +12.2% |
| API 调用 | 45.6k | 42.1k | +8.3% |
| 错误率 | 0.3% | 0.2% | +50% ⚠️ |

**异常**：错误率升了 50%——需调查。
```

异常标记是让这是 agent 而非 cron 脚本的东西。cron 脚本发表格；agent 注意到错误率飙升并指出来。

## 人设控制什么

- **数据查询**——确切的 SQL、API 端点或文件路径。
- **格式**——表格、要点或散文。跨运行一致。
- **异常规则**——"错误率 > 0.5% 时标记，或任何指标周环比变化超过 20% 时标记。"
- **交付**——"周一早上 9 点发到 #metrics。"
- **异常时做什么**——"在报告里标记并 @on-call。不自主调查。"

## 一个完整示例

设置一个每周用量报告 agent：

1. 绑 `primary`/`light` + 把数据库连接串存在 WorkerEnv（`DB_READONLY_URL`）。
2. 撰写 `MISSION.md`："每周一早上 9 点，查只读数据库上周的指标。格式化为 Markdown 表格。标记任何周环比变化超过 20% 的指标。发到 #metrics。有异常时 @on-call。"
3. 加一条每周调度：`cron: "0 9 * * 1"`。
4. agent 通过 `command`（`psql $DB_READONLY_URL -c "..."`）跑查询、格式化表格、检查异常、发帖。

## 委派数据获取

慢查询或多来源报告，把数据收集委派给后台任务（见[委派模式](../delegate-patterns/)）。任务获取；任务完成时 agent 格式化和交付。

## 本指南不是什么

它不是 BI 仪表盘——agent 把文本报告发到频道；它不画图或不服务交互式 UI。它不是监控系统——报告是周期性的不是实时的；要实时告警用[告警分诊 agent](../alert-triage-agent/)。它也不是数据管线——报告读数据；它不转换或存储数据。
